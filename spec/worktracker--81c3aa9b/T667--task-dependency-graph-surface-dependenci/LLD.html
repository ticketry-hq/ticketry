Scope modes — one canvas, three lenses

A single DependencyView with a scope selector. "Strictly in-scope" is defined per mode — for module/sprint the scope is a membership set (cross-boundary edges are hidden); for task-ego the scope is the N-hop neighborhood. Click a mode for its node set and boundary rule.

Graph build & layout — views/Dependencies/graph.ts

Pure, store-free functions: take the loaded items + a ScopeSpec, return { nodes, edges } with x/y coordinates. No fetch — the view derives entirely from backlogStore.items already in memory. Two stages: (1) select the in-scope node set, then (2) layer + place.

Stage 1 — in-scope node selection

moduleNodes = the module issue + its descendant tasks via the parent_id tree (Epic→Story→Sub-task). A BFS down children already computed by backlogStore.
task (ego)BFS out from the target following blocked_by_ids (upstream) and blocks_ids (downstream), bounded by maxHops (default 2). The reached set is the scope.
sprintNodes = items whose sprint_id equals the selected sprint.
boundaryBuild inScope: Set<id>. Edges kept only when BOTH endpoints ∈ inScope — cross-boundary edges are dropped (no external stub nodes in v1). Archived items (is_archived) excluded.

Stage 2 — layered DAG placement

guaranteeThe graph is acyclic by construction — the server's _blocker_would_cycle BFS rejects any edge that would close a loop. So a longest-path layering always terminates; no cycle-breaking needed.
layer(n)0 if n has no in-scope blocker; else 1 + max(layer(b)) over in-scope blockers. Memoized DFS. Prerequisites sit left, dependents right.
x / yx = layer · COL_W; within a layer, stack by (state.group rank, key) for stable order. SVG height grows with the tallest layer.
scaleSingle-user graphs are small (tens of nodes). No virtualization; full SVG render. A soft cap (e.g. 150 nodes) shows a "scope too broad — narrow it" notice instead of rendering.
// views/Dependencies/graph.ts — shape (pure, unit-tested)
export type ScopeSpec =
  | { kind: "module"; rootId: string }
  | { kind: "task"; rootId: string; maxHops: number }
  | { kind: "sprint"; sprintId: string };

export interface GraphNode {
  id: string; key: string; name: string;
  state: State | null; unresolved: boolean;   // reuse RESOLVED_GROUPS
  ownedElsewhere: boolean;                     // assignees.length > 0
  isFocus: boolean; layer: number; x: number; y: number;
}
export interface GraphEdge { from: string; to: string; } // blocker → blocked

export function buildGraph(items: WorkItem[], spec: ScopeSpec): { nodes: GraphNode[]; edges: GraphEdge[] };

Reused logic, not reinvented: the unresolved flag reuses issueStore.RESOLVED_GROUPS ({completed, cancelled}); the ego BFS mirrors the traversal already in BlockerPicker.blocksReach (we generalize it to walk both directions and lift it into graph.ts so picker + graph share one walker). Node fill uses display.stateColor as-is.

Agent scope-context payload — backend

Deliverable B. A read-only endpoint a subagent calls when it picks up a task, so it knows its fixed slice: what must land first, what waits on it, and what is already owned elsewhere. Derived entirely from existing edges + the assignees M2M — no new field, no migration.

Route — worktracker/api.py

GET /work-items/{id}/scope-contextNew, read-only. Resolve the issue (404 if missing). Walk blocked_by (depends-on, direct) and blocks (depended-by, direct). Mark any neighbor with a non-empty assignees set as owned_elsewhere. Reuse prefetch_related("blocked_by","blocks","assignees") to keep it a couple of queries. No writes, no state change.
directionEdges are direct in v1 — exactly mirroring blocked_by_ids/blocks_ids so there is one source of truth. The same _blocker_would_cycle BFS makes transitive (full upstream chain) a trivial later toggle; flagged as an open item, not built now.
deliveryREST is the contract. An MCP tool that wraps this endpoint (so the coding agent reaches it via the existing tool surface) is a thin follow-on in the host layer — noted, out of this subtask.

Schema — worktracker/schemas.py

ScopeRefid, key, name, state_group (str | null), resolved (bool — group ∈ completed/cancelled), assignees (List[str] names). Compact, agent-readable.
ScopeContextOuttask: ScopeRef · depends_on: List[ScopeRef] · depended_by: List[ScopeRef] · owned_elsewhere: List[ScopeRef] (subset of the union with non-empty assignees) · advisory: str (e.g. "2 of 3 blockers unresolved — stay within this task; T-19 is owned by another assignee").

Relationship ↔ state — advisory only

Locked at refinement: this feature never writes state. It reuses the existing amber "unresolved blocker" signal as a visual cue and stops there. The #629 "Blocked" state stays a manual board column. No auto-derivation, no nudge that mutates data.

ConcernDecision
Auto-set Blocked from edgesNo. Out of scope (#629 owns Blocked as a manual column). The graph reads state; it does not write it.
Unresolved indicatorA node whose state.group ∉ {completed, cancelled} and that blocks an in-scope node renders with the amber border + ⚠, identical semantics to BlockerChipView. Visual only.
Editing edges from the graphNot in v1. The canvas is read-only; edges are still created/removed in IssueSidebar via BlockerPicker. Clicking a node navigates to that issue, where editing already lives.
Suggest "mark Blocked" nudgeConsidered and declined for v1 (advisory-only path chosen). Could be a later additive hint; no data model impact either way.

Build order

Five steps; each green before the next. The pure graph core comes first so the view renders against tested logic; the agent payload is an independent track.
1Graph coregraph.ts: ScopeSpec, in-scope selection (all 3 modes), layered layout; lift the shared blocked-reach walker. Unit tests.
2RenderDependencyGraphSvg (nodes via stateColor + amber, directed edges, node click) + DependencyView scope selector + dependencyStore selection state.
3Wire-inAdd "dependencies" to the View union; ContentHost dispatch; NavDrawer PLAN entry + icon. Deep-link works.
4Agent payloadBE ScopeRef/ScopeContextOut + GET …/scope-context; SDK parity; backend tests. Independent of FE.
5Live e2eReal module/task/sprint walk, node navigation, payload read. Your validation gates Done.

Acceptance

Every refinement decision is mapped: a read-only dependency-graph view scoped by module (the driving ask), task-ego, and sprint on one canvas; strictly in-scope rendering defined per mode (membership sets hide cross-boundary edges; ego scope is the N-hop neighborhood); built on the existing #624 edges with no edge writes and no migration; advisory-only reuse of the amber unresolved signal with the #629 Blocked state left manual; a separate read-only scope-context payload (depends_on / depended_by / owned_elsewhere + advisory) derived from edges + assignees for a subagent to stay in scope; cross-project explicitly out; and a hand-rolled layered SVG that adds no new dependency.
