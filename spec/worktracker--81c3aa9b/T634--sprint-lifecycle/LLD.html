The four behaviors

Each is a thin delta on an existing surface — never a rewrite. Nothing here adds story points, velocity, or a new view.

1 · Auto-incrementing names

whereNew Project.sprint_seq counter; mint in create_sprint.
ruleBlank/omitted name → sprint_seq += 1, name = Sprint N. A supplied name is honored and never touches the counter.
parityCounter is never decremented on delete — Jira board-counter behavior. Distinct from the existing issue seq_counter.

2 · Sprint goal

whereNew Sprint.goal TextField; round-trips model → SprintOut → SDK → Studio.
gotchaSDK OutputModel is extra="forbid" — shipping goal on the response without the SDK field rejects every sprint (same as #629). Co-ship is mandatory.
uiOptional input on Create / Start; one muted line on SprintCard.

3 · Explicit Start

whereNew POST /sprints/{id}/start; StartSprintDialog.
rulestatus → active; start = start or today; end = end or start + duration_days (default 14). Reuses the single-active guard → 409.
uiDuration presets 1/2/3/4 wk (default 2 wk) or explicit dates; goal field.

4 · Complete-with-carryover

whereNew POST /sprints/{id}/complete; CompleteSprintDialog.
ruleIn one transaction: status → completed; re-point only unfinished members (group not completed/cancelled) to a target sprint or Backlog. Done/cancelled stay as history.
returns{ sprint, moved_count }. Absorbs #604's close-as-advance.

Frontend flow & store contract

Rides the existing stores and components — no new view. Optimistic apply, server-as-source-of-truth on reconcile, total rollback on any non-2xx.

backlogSprintActions.ts

startSprintOptimistic flip status → active + apply goal/dates locally; client single-active pre-check (mirror existing). Call api.startSprint, reconcile from response; non-2xx ⇒ roll sprints back to snapshot + toast.
completeSprintSnapshot both sprints + items; flip status → completed and move unfinished cards locally (same predicate as sprintProgress). Call api.completeSprint, reconcile sprint, keep moves. non-2xx ⇒ roll back both snapshots + toast.

Views

NewSprintPrefill name with nextSprintName(sprints) (optional ⇒ server mints); add optional goal field.
StartSprintDialogNew. Prefilled name, goal, duration presets 1/2/3/4 wk (default 2 wk) or explicit dates; blocked with a clear message when another sprint is active (server 409 backstop).
CompleteSprintDialogNew. Done/unfinished split from sprintProgress; carryover = Backlog or a planned sprint (dropdown excludes the completing sprint + all completed; "+ new sprint" inline). 0 unfinished ⇒ skip picker.
Lens / CardSprintsLens verbs open the dialogs (keep start-{id}/complete-{id} testids); SprintCard renders goal.
nextSprintName is client prefill only — the server is authoritative on the real number at create time, so raced concurrent creates can't collide.

Acceptance

Auto-named sprint in → goal round-trips → explicit Start stamps dates → Complete moves exactly the unfinished work, atomically — counter never reused, 409 on re-complete / second-active, 422 + full rollback on a bad target, and a failed Studio op rolls the board back cleanly, with all three suites green.
