Strategy Pack Store + Loader — High-Level Design

Decomposition strategy becomes a first-class, swappable run parameter — the thing #700's hardcoded recipes.py never had. A strategy is a named, git-versioned directory of per-phase prompt templates; a loader validates the pack once at run start and renders per-phase prompts with issue context interpolated. This slice ships the format, the loader, and the default pack — prompts only.

Why this slice exists

#700 proved phase-based prompting but hardcoded it. The orchestrator's bet — "better or cheaper" by swapping how agents are asked to decompose — needs strategy to be a run parameter, which requires a store and a loader first.
#700 · FROZEN REFERENCE
recipes.py: per-phase prompts are hardcoded Python f-strings (initial_prompt_for(phase, issue)). One prompt set, no variants, no store. Strategy is not a parameter — you edit code to change how a task is split.
⟶
THE GAP
To A/B "split by feature" vs "split by interface", or run cheaper models on a leaner prompt, strategy must be selectable per run and recorded on the run header. No format, no lookup, no default pack exists to make that possible.
⟶
THIS SLICE (#783)
Git-versioned strategies/<name>/ packs (manifest + <phase>.md templates) + a loader (load_pack / prompt_for) that hard-errors at run start on any bad pack + a default pack rewritten for the autonomous decompose → implement model.

The pack ⇄ loader contract

Three parts, all on disk under the orchestrator app. The loader imports only issue context from worktracker — never from apps/execution (the frozen reference) or apps/terminals.
FORMAT · what a pack is

A directory per strategy

strategies/<name>/ holds a pack.toml manifest (name, version, declared phases, and a reserved-but-empty [policy] table) plus one <phase>.md template per declared phase. Git is the store; a new pack is a new directory.

Manifest ships now; [policy] reserved for #786
LOADER · how it is read

load_pack then prompt_for

load_pack(strategy) validates the whole pack once at run start and returns a StrategyPack; pack.prompt_for(phase, issue) renders a preloaded template. Interpolation is a minimal {{var}} whitelist substitution — literal { and $ in a description pass through untouched.

Unknown strategy/phase/token → hard error at run START
DEFAULT PACK · what ships

default/, rewritten for autonomy

decompose.md + implement.md, adapted from #700's split/register/implement prose but stripped of every human-gate assumption: one agent proposes and creates children in a pass, no HLD-approval pause, no lifecycle-state flips.

Decompose prompt MUST require deterministic child slugs

PILLAR 1 · FORMAT · decision D1

Pack format as repo files

A manifest-plus-templates directory under apps/orchestrator/strategies/, git-versioned, one dir per strategy.

  • pack.toml: name, version, phases = ["decompose","implement"], and a reserved empty [policy] table
  • One <phase>.md template per declared phase; parsed with stdlib tomllib (no new dependency)
  • Fixed phase sequence in v1 — phases is declared but sequence-shaping is deferred
  • [policy] present but empty; #786 populates model-per-(phase,depth,attempt) without a format migration
PILLAR 2 · LOADER · decisions D2 · the heart of the slice

Loader + eager validation

The pure, framework-light module the coordinator (#784) calls: validate at run start, render per launch.

  • load_pack(strategy) → StrategyPack — validates dir exists, manifest parses, declared phases equal the required set, each <phase>.md present, every {{token}} in every template is in the whitelist
  • pack.prompt_for(phase, issue) → str — renders a preloaded template; can't miss a file because load_pack already proved they exist
  • {{var}} whitelist engine: replaces only known tokens; {/$ stay literal; any unknown token fails the load
  • One error type (StrategyError) raised eagerly — the mechanism behind "hard error at run start, not mid-run"
PILLAR 3 · DEFAULT PACK · decisions D3 · D4

Default pack, rewritten for autonomy

decompose.md + implement.md authored to the BRIEF's locked contract, not a placeholder.

  • decompose.md: one agent proposes AND creates child tickets + blocked_by edges in a pass; deterministic child slugs; nonempty descriptions; 2..budget children parented under the root
  • Blocker-note convention: if the task is impossible, write a blocker note and stop — never exit silently (feeds the coordinator's no-retry path)
  • implement.md: commit on the node's branch, run the check, flip the ticket; blocker-note on impossibility
  • No HLD-approval pause, no lifecycle-state flips, no doc phase — every #700 human-gate assumption removed

Decisions & open questions

Green = decided (grill session + BRIEF). Red = genuinely open — neither gates this slice.
DECIDED · D1 pack format

Manifest now, or bare .md dir?

Manifest now. pack.toml with name/version/phases populated and a reserved empty [policy] table beside the <phase>.md files. #786 fills policy with no format migration.

DECIDED · D2 interpolation

Which template engine?

Minimal {{var}} whitelist substitution. Not str.format/string.Template — implement.md contains shell $ and { that both mis-parse. Only known tokens are replaced; unknown token → hard error at load.

DECIDED · D2 variable set

What is interpolated?

key, name, description, children, project_id, project_slug. Project context added beyond the ticket's illustrative list because decompose creates child tickets. children is live: empty on first decompose, populated on reconcile-retry.

DECIDED · D3 reconcile seam

Where does retry's "already-created children" come from?

Split. Child key+name fall out of the live children var; richer edge-level + per-attempt-diff diagnostics are coordinator-appended (#784), layered after the base prompt exactly as #700 layered initial_prompt.

DECIDED · D4 prose fidelity

How faithful to #700's prose?

Rewrite for autonomy. #700's prose is raw material only — every human-gate assumption (HLD approval, lifecycle flips, separate register/lld phases) is removed for the autonomous decompose → implement model.

DECIDED · "run start" for a slice with no run

What validates, and when?

load_pack is that function. It does the eager validation the coordinator invokes at run start; prompt_for then renders a preloaded pack and cannot fail on a missing file.

OPEN · deferred to #786

What is the [policy] schema?

Open by construction. Only the reserved empty table lands here. The (phase, depth, attempt) → (agent, model) shape is decided in the model/cost-policy slice; this slice must not lock it.

OPEN · deferred to #784

Exact reconcile diagnostic text?

Open, no blocker. How edges and per-attempt diffs are formatted into the corrective prompt is the coordinator's concern; the pack's base template is stable regardless.

Acceptance signal

The slice is done when the default pack loads and validates, and the loader is provably strict:
  • Renders: prompt_for("default","decompose",issue) and ("default","implement",issue) return fully interpolated strings — tested with children both populated and empty.
  • Errors at load: load_pack raises StrategyError for an unknown strategy dir, a manifest whose phases don't match the required set, a missing <phase>.md, a malformed manifest, and any template containing an out-of-whitelist {{token}}.
  • Collision-safe: an issue description containing literal { and $ renders verbatim, not mangled.
  • Format goal: a second pack could be added later as pure files with zero loader changes (the property #787 will actually exercise).
All within the orchestrator app boundary, importing only from worktracker.
