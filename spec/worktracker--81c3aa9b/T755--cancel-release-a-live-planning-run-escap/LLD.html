The contract

Legality lives in the pure reducer; mutation lives at the driver boundary; the API/MCP/Studio surfaces are thin.
SurfaceBehavior
reducer.decide(..., release_requested)New event kind. running → idle (drops agent_run_id/error). Any other status, or a mismatched task_id, is a no-op. Pure — emits no actions.
driver.release(task_id) → EngineStateRaises planning_run_not_found unless a registered run is running. Validates via the reducer, then deletes the registry entry and returns the previous (running) state. Never spawns, never terminates.
DELETE /work-items/{id}/planning-run200 {task_id, status:"idle", released:{…previous run…}}; 404 planning_run_not_found on miss (no state/lifecycle mutation).
release_planning_run(task_id)MCP tool → DELETE. Returns the release result, or {task_id, error} on 4xx — same convention as execute_dependency_graph.
Studio “Release lock” buttonBeside Refine/Split. On success clears any launch error and shows “Lock released”; on 404 surfaces planning_run_not_found. Copy avoids “kill”.

Relaunch fix: re-launching the same phase after release found the lifecycle still parked at that phase (e.g. refining), and set_lifecycle rejects a self-transition. _advance_launch_lifecycle now skips the advance when already at target, so relaunch is a genuine fresh spawn — satisfying the “spawns once” criterion.

Durability handoff — the single seam CODIN-757 retargets

Per the refinement acceptance, the LLD names exactly one boundary the durable-run-state ticket must move.
driver.release(task_id) is the one boundary. It is the sole place the guard is mutated for release, reached identically by the HTTP route, the MCP tool, and the Studio client.
  • Today it reads and deletes the process-local _registry[task_id] entry after a reducer-validated release_requested.
  • CODIN-757/776 swaps that read/delete for a durable EngineRun row update (released/idle) inside a row-locked transaction — no change to the reducer, API shape, MCP tool, or Studio.
  • Serializing through this single function is what keeps release and launch from double-spawning on stale reads; the durable row makes that serialization survive an ASGI restart.

Acceptance

Green signal. A wedged planning_run_already_running lock is releasable without a server restart, and the next tracked launch is a genuinely fresh run.
  • ✓ Launch → second launch 409 → release → third launch 201, spawning once (twice total).
  • ✓ Release with no running run → 404 planning_run_not_found, no state/lifecycle mutation.
  • ✓ No terminal/AgentRun termination on the release path; UI/MCP/docs label it lock release, not kill.
  • ✓ MCP release_planning_run clears the same lock and returns the released/current state.
  • ✓ Drawer exposes the affordance near Refine/Split without breaking normal terminal launch.
