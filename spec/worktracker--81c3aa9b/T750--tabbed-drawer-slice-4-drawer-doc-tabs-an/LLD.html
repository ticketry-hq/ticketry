What already exists (do not rebuild)

The doc state machine is complete. CODIN-750 must read and drive it, not re-implement it. Verified in the current tree.

State & actions — coding/stores/workspaceStore.ts

  • docs: DocTabState[] with an open flag, deduped by relPath, disambiguated labels.
  • activeDocId and active: TabKind ("details" | "doc" | "terminal").
  • setActiveDoc, closeDoc (active → falls back to details), reopenDoc (opens + selects).
  • hydrateDocs opens discovered docs as open:true without stealing focus.

Hydration — CODIN-748 seam

  • Opening /issues/:key resolves taskId and calls hydrateDocs(taskId, docs).
  • Discovered docs are already open tabs; Details stays selected on first open.
  • effectiveActiveTab restores a valid in-memory prior active doc, else details.
  • Docs load failure is a scoped docs.status = "error"; the drawer still renders.

Interaction steps

Decision-complete behaviors. Each maps directly onto an existing workspaceStore action, so this slice wires events, it does not compute state.
1
Open drawerCODIN-748 hydrate has run: docs are open tabs, Details selected. Tab strip renders Details + a Doc tab per open doc.
2
Select doc tabClick → setActiveDoc(taskId, docId). Host renders ReadOnlyDocFrame for that doc.
3
Close doc tabClick × → closeDoc. If it was active, store falls back to details; other docs and Details untouched.
4
Dormant chipClosed doc appears as a reopen chip. Click → reopenDoc opens + selects it.
5
Doc load failsiframe fails or docs.status = "error" → the tab still exists, Details still renders; scoped status is shown, drawer never breaks.
6
Zero docsNo open docs and no closed docs → tab strip shows Details only, no docs row, no chip, no status.

Status model

Docs report independently; Details is always the stable fallback and always renders.

Loading

  • Details renders immediately.
  • Doc tabs appear as they hydrate.

Ready + docs

  • Details + closable doc tabs.
  • Closed docs show as dormant chips.

Ready, empty

  • Details only.
  • No docs row, chip, or status.

Error

  • Scoped docs status shown.
  • Details still renders; drawer never fails whole.
