Slice boundary

CODIN-758 owns only the durable field, its guard, and its HTTP surface. Everything that drives the machine (agents, engine, drawer) is a downstream slice that depends only on this one.

Build in this slice

  • The 19-value enum + its choices constant on WorkTracker core.
  • Issue.lifecycle_state nullable field + migration 0009, no backfill.
  • A single guarded service set_lifecycle(issue, target) — the sole writer — validating transition and pairing.
  • allowed_transitions(issue) returning the legal-next set.
  • Read-only lifecycle_state + lifecycle_transitions on WorkItemOut.
  • POST /work-items/{id}/lifecycle → 422 on illegal target/pairing.
  • Service tests, API tests, sole-writer gate test, OpenAPI contract refresh.

Explicitly out of this slice

  • No auto-move of Issue.state — pairing is defined + validated, never performed (per parent HLD).
  • No engine retrofit, no deletion of the phantom to_state=="LLD" gate — that is CODIN-761.
  • No MCP set_lifecycle tool — CODIN-760.
  • No drawer chicklet / picker UI — CODIN-759.
  • No blocked lifecycle value; no sixth visible group; no new State row.
  • No role plumbing: the guard permits both entry points; which one a caller uses is decided upstream.

The guarded write path — set_lifecycle(issue, target)

One function, five ordered checks, one persist. Click a step for its mechanics, the exception it raises, and edge cases. It is the sole code path that assigns the field.

  1. Receive the resolved issue + target string. No fetch inside the guard.
  2. Reject an unknown target value. → InvalidTransition (422).
  3. Reject a target not in allowed_transitions(issue). → InvalidTransition (422).
  4. Reject an illegal (target, state.group) pairing. → InvalidTransition (422).
  5. — a narrow write that touches nothing else and bumps the audit timestamp (auto_now only fires when the field is in update_fields). Wrapped in transaction.atomic() to match the house pattern even though it is a single row. Returns the mutated Issue so the route can re-serialize it.">Persist via save(update_fields=…) and return the issue.

Sole-writer enforcement. Django cannot truly seal an attribute, so sole-ownership is enforced two ways: (1) convention — no other module assigns lifecycle_state; and (2) a grep-style gate test (in the flavor of this repo's forbidden-symbol gates) asserting the literal assignment lifecycle_state = / update_fields=["lifecycle_state" appears only in lifecycle.py and the migration. The field is not exposed as writable on any input schema (WorkItemIn/WorkItemPatch unchanged), so the PATCH route cannot set it either.

Visible-state pairing map

The second half of the guard. CODIN-758 defines and validates these pairings; it never performs the visible move. The pairing is keyed on the visible state group (via state_group(issue.state_id)), not the state name — so custom states inherit their group's rule and the five frozen groups stay the axis.

Why 422 is possible: setting implementing while the issue is visibly Backlog is rejected — a human or a phase ticket must first move the visible state to the started group; then the lifecycle write succeeds. A constrained target against a null state group (issue has no state) also fails. This keeps 758 contract-only.

Read / write surface

Read — WorkItemOut (schemas.py)

  • lifecycle_state: Optional[str] = None — plain field, read straight off the ORM object (no resolver).
  • lifecycle_transitions: List[str] = [] — added via a resolve_lifecycle_transitions(obj) staticmethod delegating to lifecycle.allowed_transitions(obj).
  • Cheap: allowed_transitions reads only obj.lifecycle_state in memory — no per-row query, safe on the list endpoints.
  • Board / StatePicker / filters read only State rows, so neither field can ever surface as a column — invisible by construction.

Write — POST /work-items/{issue_id}/lifecycle

  • New Ninja LifecycleIn schema: { target: str }.
  • Route mirrors archive_work_item: resolve via resolve_issue(issue_id, task_only=False) (accepts UUID or KEY-N; 404 if missing; task_only=False so module/epic roots qualify).
  • Call set_lifecycle(issue, payload.target) inside with _http_errors(): — InvalidTransition (a ValidationError) surfaces as 422 with no new mapping code.
  • Return resolve_issue(str(issue.id), task_only=False) → hydrated WorkItemOut carrying the new state + fresh transitions.
  • operation_id="setWorkItemLifecycle", tags=["WorkItems"]. Server-mounted at /work-tracker/work-items/{id}/lifecycle.

Demoable end-to-end via curl once merged: POST a target, watch lifecycle_state advance and lifecycle_transitions re-compute on the response; POST an illegal target or an illegal pairing and get a 422 with the guard's message.

Test plan

tests/test_lifecycle.py — the machine

  • Every listed transition is accepted (parametrized over the table).
  • A representative set of unlisted transitions raises InvalidTransition.
  • → failed / → cancelled accepted from each active state; rejected from all three terminals.
  • Back-edges prd_review→refining, hld_review→generating_hld, lld_review→lld_generating accepted.
  • Entry: from NULL, only backlog / split_created accepted.
  • Illegal pairing (implementing while visible Backlog; constrained target with no state) rejected; the legal pairing (same target after moving to the right group) accepted.
  • allowed_transitions(issue) returns exactly the row's next set (incl. failed/cancelled for actives) for each state and the entry set for NULL.
  • An unknown target string raises InvalidTransition.

tests/test_lifecycle_api.py — the surface

  • WorkItemOut exposes lifecycle_state (null on a fresh issue) and lifecycle_transitions (the entry set on a fresh issue).
  • POST …/lifecycle advances a legal target and the response shows the new state + recomputed transitions.
  • Illegal target → 422; illegal pairing → 422; unknown/missing issue → 404.
  • Accepts both a UUID and a KEY-N path param.
  • Sole-writer gate: assert the field assignment appears only in lifecycle.py + the migration.
  • OpenAPI contract: refresh the exported schema; the new route + fields appear with an explicit operationId, WorkItems tag, and the 401 security block (satisfies the existing contract test).

Fixtures reuse tests/conftest.py (client, project, auth, post_json/patch_json, BASE) exactly as test_work_items_api.py does. Default project states (Backlog/Todo/Blocked/In Progress/Done/Cancelled) give every group needed for the pairing cases.
