Search & Quick-Filter Parity — High-Level Design

Three Jira-muscle-memory affordances over the already-loaded item set: an inline search box that narrows Backlog and Board by key or name, a composable + Add filter chip bar that replaces the fixed State/Sprint dropdowns, and a ⌘K / “/” palette to jump straight to an issue. Pure frontend, client-side, zero new endpoint. Closes gaps G10 / G11 / G18.

What changed in refinement

G11 asked for a priority quick-filter. In refinement the user reframed it: not one more dropdown, but a composable filter model. That reshapes the store, so it is recorded here up front.
TICKET AS FILED
A single-select Priority dropdown sitting beside the existing State and Sprint dropdowns on the Backlog filter bar. Minimal, but three fixed controls that don't compose.
⟶
THIS DESIGN
A Linear-style + Add filter bar: pick a field, pick value(s), each active filter becomes a removable chip. Multi-value per field. The fixed State/Sprint dropdowns are replaced, not extended — so filters moves from single ids to id arrays.

The slice, in three pillars

All three read the item set the store already loaded — none refetches. Click a pillar to expand its boundary.
PILLAR 1 · G10 · Backlog + Board

Inline search box

An always-visible field in the toolbar of both surfaces. Type to narrow what's on screen.

  • Matches key OR name — case-insensitive substring (auth, 609, studio)
  • New query: string on the shared backlogStore.filters — set on one surface, carries to the other
  • Backlog keeps matching rows and their ancestors via the existing matches() scaffolding rule
  • Board narrows each column via boardColumns()
PILLAR 2 · G11 (reframed) · Backlog + Board

Composable filter chips

A + Add filter control: pick a field → pick value(s); each active filter is a removable chip.

  • Backlog fields: Priority · State · Sprint
  • Board fields: Priority · Sprint — State excluded, it is the column axis
  • Multi-value: within a field = OR, across fields = AND
  • Priority values are the frozen enum from lib/display.ts (urgent…none)
  • Replaces the two fixed dropdowns → stateId/sprintId become stateIds/sprintIds
PILLAR 3 · G18 · global

Quick-jump palette

⌘K / Ctrl+K anywhere, or “/” when not typing. A modal to jump to an issue without the mouse.

  • Lists the current project's loaded issues; substring match on key + name
  • ↑↓ move · Enter opens the issue · Esc closes
  • “Open” navigates to /issues/KEY-N — the existing route → drawer path
  • “/” suppression reuses the useCodingAppShortcut typing-target guard
  • It navigates; it does not touch filters
✓ new — built in this slice ↻ reuse — existing seam, unchanged ◌ breaking — store-shape change with blast radius

The filter model

One shared backlogStore.filters object backs every surface (D1). Search, chips, and the surface-render predicates all read it. The model is the contract; the widgets are interchangeable.
STATE · the shared shape

BacklogFilters (breaking)

query: string  ·  priorities: string[]  ·  stateIds: string[]  ·  sprintIds: string[]  ·  epicIds: string[] (unchanged, #627)  ·  showSubtasks?: boolean.

Singular stateId/sprintId → plural arrays. Touches matches(), boardColumns(), EMPTY_FILTERS, both filter bars, and their tests.
SEMANTICS · how a row passes

OR within, AND across

An item passes when, for every active field, its value is in that field's set. query is a case-insensitive substring on key + name. An empty set = field inactive = matches all.

Example: priorities=[high,urgent] AND query="auth" → high-or-urgent issues whose key/name contains “auth”.
SCOPE · per surface

Same state, different fields exposed

Backlog exposes Priority/State/Sprint chips + search. Board exposes Priority/Sprint chips + search (State is the column axis, so it is never a chip there). Epic/module stays where #627 put it — the epic rail on Backlog, the Module dropdown on Board — not folded into chips.

A field a surface doesn't expose simply isn't offered there; it is not cleared from the shared object.
LIFECYCLE · reset & persistence

Cleared on project switch

All fields reset to EMPTY_FILTERS on project change (today's behavior, extended to the new fields), so stale ids never leak across projects. Filters are not persisted to localStorage.

No refetch anywhere — every narrowing is a pure recompute over the loaded items.

Decisions & open LLD points

Green = settled with the user in refinement. Amber = deliberately deferred to LLD; none gates the shape of this slice.
ANSWERED · search vs palette

One affordance or two?

Two, distinct. The inline search box narrows the list in place (G10); the ⌘K/“/” palette is a separate modal that jumps/navigates (G18). Different mental models, matching Jira.

ANSWERED · the G11 reframe

Fixed priority dropdown or composable?

Composable chips. A “+ Add filter” bar replacing the fixed State/Sprint dropdowns, multi-value per field — the user's explicit ask over a single dropdown.

ANSWERED · match scope

What does search match?

Key + name, case-insensitive substring, for both the inline box and the palette. Type a title word or the number.

ANSWERED · board chip set

Does Priority filter the Board too?

Yes, via its own chips. Board exposes Priority + Sprint chips (State is the axis). Module stays in its existing control, not in the chips (#627 owns epic filtering).

LLD · palette state home

Where does palette open/close live?

To decide in LLD: a uiStore flag (symmetric with drawerKey, easy to test) vs. local state in a root-mounted component. Leaning uiStore.

LLD · chip widget mechanics

Add-filter menu & value picker UX

To detail in LLD: the exact dropdown/menu interaction, reuse of existing pickers, and empty/“no matches” copy. The model (this doc) is fixed; the widget is not.

Acceptance signal

The slice is done when, on both Backlog and Board, typing in the toolbar search box narrows the visible items by key or name with no refetch; a + Add filter control lets you stack Priority / State / Sprint (Board: Priority / Sprint) as removable chips that combine OR within a field, AND across fields; pressing ⌘K or “/” (when not typing) opens a palette that finds a loaded issue by key or name and Enter jumps straight into it; switching projects clears all filters; and the whole thing ships with zero backend change and a green tsc + vitest + build.
