The filter-shape change

The one breaking edit. The shared backlog filter goes from a single nullable epic id to a list of ids. Empty list = all epics (no filter). The NO_EPIC sentinel becomes an ordinary list member, so "Auth + No-epic" is now expressible.

BacklogFilters shape

beforeepicId: string | null — one epic, or null for all. Single-select only.
afterepicIds: string[] — the selected epics. Empty array = all (the cleared state).
No-epicNO_EPIC ("none") is a valid member; it selects the trailing parent-less group alongside any real epics.
resetEMPTY_FILTERS.epicIds = []; loadBacklog still resets filters on project change so ids never leak across projects.
toggleA pure toggleEpic(ids, id) helper (add/remove) keeps the rail's click logic unit-testable; the rail calls setFilter({ epicIds }).

Write sites — who sets the filter

  • EpicRail (NEW) — multi-toggle: click adds/removes the epic id; an "All" affordance clears to []. The Backlog's primary selector.
  • FilterBar (Backlog) — the standalone epic <select> is removed; the rail supersedes it. State + Sprint selects stay.
  • BoardFilterBar — keeps its single Module <select> but reads filters.epicIds[0] ?? "" and writes epicIds: value ? [value] : []. The Board stays single-select via the dropdown; rail multi-select is Backlog-only. Both write the one shared array.
  • IssueDetail.goEpic — the "Epic" chip's jump-to-backlog sets { epicIds: [epic.id] } (was { epicId: epic.id }) then routes to Backlog.
  • EpicsList.openEpic — deleted with the component; its behavior is absorbed by the rail.
