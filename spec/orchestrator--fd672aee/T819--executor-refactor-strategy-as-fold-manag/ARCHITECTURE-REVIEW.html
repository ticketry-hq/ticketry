Problem:
packs swap prompts, but the strategy — phase grammar (loader.py:34), lifecycle policy (reducer.py:68), postconditions & corrective relaunch (driver.py:600, 687), model selection (policy.py) — is engine implementation; the seam admits no second control flow.
Solution:

2 · Durable inbox, stateless fold — the redux answer

Strong local-substitutable

driver.py · headless.py · startup.py · signals.py · models.py · dao/runs.py

Before — three state layers; restart kills the middle

DB rows — CoordinatorRun · RunNode · HeadlessRun durable
asyncio supervisors — _supervise_process, timeout tasks dies on reload
on_commit → schedule_coroutine → live loop required dies on reload
startup.py adoption — repairs the damage after the fact patch

#814: supervisor dies on ASGI reload → runs stuck "running".

After — DB is the only state; reconcile is the only loop

DB — run rows + durable event inbox (exits, transitions, verdicts) durable
reconcile(): adopt pids → drain inbox → fold reducer → launch ready set. Idempotent — run it at startup, on signal, on poll. stateless

Restart = run reconcile. No adoption "repair" path — recovery is the normal path.

Problem:
the fold is already rebuilt from DB rows each pass (driver.py:293), but launching and supervising hang off a live event loop (headless.py:36–62) and on_commit callbacks (driver.py:331) — the process, not the database, is what keeps a run moving.
Solution:
keep the reducer, drop the residency: every external fact lands as a durable event row; reconcile() adopts recorded pids and drains the inbox through the fold; delete the fallback-loop machinery and startup "repair" special case. Redux stays — as a replayable fold over the DB, which it already half is.
  • Locality: one recovery path, exercised constantly
  • Server restart is a non-event; kills #814's orphan class
  • Tests: seed inbox rows, call reconcile, assert rows
  • Deletes loop-registration + fallback-loop implementation
This is the honest answer to "why not Temporal": same durability idea (event history + deterministic replay) without a second runtime — single box, recursive runs, and tmux-bound interactive sessions make an external executor a poor fit.

  • Locality: process mechanics change in one module
  • Fake adapter → driver tests drop subprocess guards
  • Aligns with ticket #811's headless port direction

Problem:
service.py is shallow — start/abort commands, entry validation, serialization, console shaping, and terminal teardown share one interface, and it reaches through the engine's seam (imports driver._live_topology).
Solution:
split by audience: a command module (mutations, guards) and a console read module (queries dao directly); deletion test — removing today's service.py scatters both audiences into api.py, so each half earns its keep as a module.
  • Interface per audience shrinks to a handful of calls
  • Console reads stop coupling to engine internals
  • Pure readability win; no behavior change
