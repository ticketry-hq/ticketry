Implementation Shape

Selected node

LifecyclePicker

  • Does: renders the current internal lifecycle beside the visible state chip.
  • Does: offers only server legal next transitions plus failed and cancelled.
  • Does not: read or mutate visible workflow State rows.

Decision Table

These choices are fixed for implementation so the slice can be coded without reopening scope.

QuestionDecisionReason
Where does it render?In IssueDetail.tsx, beside StatePicker.That is the existing visible-state chip row named by the acceptance criteria.
Where do options come from?lifecycle_transitions plus failed and cancelled, de-duplicated.The server owns legal transitions; terminals are an explicit ticket-level exception.
Optimistic update?No optimistic lifecycle jump before the POST returns.A rejected transition must leave the visible state unchanged; non-optimistic save is clearer.
Who enforces legality?The UI hides illegal targets; the guarded route remains authoritative.Prevents normal bad clicks while still protecting stale clients and pairings.
Visible state surfaces?No behavior changes except leak-regression tests.Lifecycle must never become a workflow state, board column, filter option, or config row.

Regression Harness

The main risk is cross-contamination between internal lifecycle and visible workflow state. Tests pin both behavior and isolation.

drawer

Render and options

Open issue with lifecycle fields. Assert current lifecycle is shown beside visible state and options equal legal next plus terminals.

mutation

Success and rejection

Mock guarded route success to reconcile returned state. Mock 422 to show toast and keep old lifecycle.

leak guards

Visible-only state surfaces

Seed lifecycle values on items, not in states. Assert board columns, swimlanes, state picker, board filter, and workflow config expose only visible states.
