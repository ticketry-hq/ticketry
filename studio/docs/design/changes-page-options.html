Changes page — redesign options

Five layouts for the same data, ordered from smallest change to largest. Each keeps every capability that exists today. Mockups use the live Studio palette and square-corner rule.

Diagnosis Fixes common to all A · Status bar B · Ship pipeline C · Branch inspector D · Worktree switcher E · Review + Ship modes Compare

What is wrong with the current page

Measured against Norman's fundamentals and Tognazzini's principles, the screenshot has seven concrete defects. All five options fix the first four; they differ in how they treat the rest.

1 · The content is below the fold VisibilityThe file list, which is what the page is for, starts at 64% of the viewport. Eight controls, two status boxes, a definition list, a branch picker and an error sit above it. The user came to read a diff and gets a settings form.
2 · No action hierarchy Affordance · DefaultsCommit & push, Commit, Push, Open PR, Prepare merge, Refresh merge eligibility all render as identical bordered boxes. The one filled button is disabled. Nothing says "this is what you should do next."
3 · Four navigation layers say the same thing Consistency · SimplicityModule tabs, Details/Changes tabs, the row of "instant" chips, and the "Current worktrees" list all pick a context. The left column is a second copy of the tab strip and costs 22% of the width.
4 · State is scattered Visibility · Mapping"Merge conflicts / Merge preparation available", "The mapped pull request has not merged", "Dirty · 3 unpushed", "Finish or abort the Git operation" appear in four places with four visual treatments. One branch has one state; show it once.
5 · Errors without an exit Error recovery"Finish or abort the Git operation in the destination checkout, then retry" is red text with no button. The recovery actions exist in the code (Finish merge / Abort merge) but render in a different section.
6 · The diff pane wastes its width EfficiencyRight column is 58% of the screen and shows 12 lines. The file header is a single truncated line of mono text with no status, no counts, no navigation between files.
7 · File rows lose the signal ReadabilityPaths truncate in the middle of the directory, so eight rows read "studio/scripts/performanc…". The status is a full word in the same colour weight as the counts.
8 · Everything is the same box AestheticsButtons, status notices, confirm dialogs, the worktree list and the file list all use the same 1px border on the same background. Nothing groups, nothing recedes.

Fixes that apply to every option

File rows

  • Single-letter status badge M A D R C U ! in the lifecycle colour, left-aligned, so the eye scans a column.
  • Path split: directory in muted, truncated from the left; filename in primary, never truncated.
  • Optional grouping by top-level directory with a count, collapsed when a group exceeds ~8 files.
  • +n −n right-aligned in green/red, fixed width so counts line up.
  • Keyboard: j / k or arrows move selection, Enter focuses the diff, [ ] previous/next file from inside the diff.

Diff pane header

  • Status badge + full path + counts + "3 of 34" + prev/next buttons.
  • Empty state says what to do: "Select a file, or press j."

Actions

  • Exactly one primary button, derived from state: dirty → "Commit & push"; clean + unpushed → "Push"; pushed, no PR → "Create PR"; PR open → "Open PR"; PR merged → "Merge locally" / "Clean up".
  • Everything else moves into a ⋯ menu with its enabling condition shown as a disabled reason ("Push · nothing to push").
  • Confirmations become an inline popover anchored to the button, not a box that reflows the column.
  • Every red message carries the action that resolves it on the same row.

Status

  • One status line per branch: coloured dot + short phrase + PR badge. The long explanation goes in a tooltip or a disclosure.
  • Local merge preview and worktree cleanup are secondary; they should be one click away, not always expanded.

Option B · The ship pipeline state as a horizontal stepper

Shipping a worktree is linear: commit → push → pull request → merge → clean up. Render that as a five-step strip across the top of the workspace. Each step shows its current state and, when it is the active step, exactly one action. Errors attach to the step they belong to. The files and diff take the whole area below.

Open, it holds the full detail in sections: Status, Pull request, Local merge, Worktree. Users who only review never see the plumbing.

Option E · Two modes: Review and Ship segmented control decides what the column shows

Keep a two-column layout and accept that the page has two jobs. A segmented control at the top of the left column switches it between Review (the file list) and Ship (status, actions, PR, local merge, cleanup as a readable vertical form). The right column is always the diff. Mode defaults to Review; it flips to Ship automatically when an action needs attention, with a badge on the segment.
