Programmatic launch primitive spawn_run()

Give the backend a reusable callable that starts a coding-agent run for a task with no human at a WebSocket and returns its agent_run_id — a run indistinguishable from a human-started one (detached tmux session, real terminal the ticket view attaches to on demand). Mechanically this is an extraction, not a new capability: the launch already lives inside the WS consumer; we lift its launch half into a single shared _launch, add a thin backend-facing spawn_run wrapper, and refactor the consumer to call the same path — one launch path, zero divergence.

The three open decisions this LLD closes

Refinement (2026-06-29) deferred exactly three calls to the LLD: the launch.py module shape, the _build_prompt/_worktree_root relocate-vs-import question, and the LaunchUnavailable exception. Each is resolved below; the rest of the document is the decision-complete harness that follows from them.
Open questionDecisionWhy
1 · launch.py module shape — what lives in the new module and what stays on the consumer? Module-level _launch + spawn_run + _delete_agent_run + LaunchUnavailable _launch touches no self state, so it is a free function. The viewer half (PTY spawn, PtySession, cols/rows, client-size refresh, pump) stays a consumer method — it is inherently socket-bound. New file server/apps/terminals/launch.py holds the launch half + wrapper; the consumer imports from it.
2 · _build_prompt / _worktree_root — relocate into launch.py, or import one-way from the consumer? Neither — relocate to a neutral prompt_builder.py Importing them from consumers would make launch depend on consumers while consumers imports launch — a cycle. Putting them in their own leaf module terminals/prompt_builder.py lets both the consumer and launch import them with arrows pointing one way. (The #724 domain-service refactor performs this same extraction; this LLD adopts it as the resolution.)
3 · LaunchUnavailable exception — where defined, what it means, who catches it? New exception in launch.py; means "the persisted launch failed" Raised by _launch after deleting the half-inserted AgentRun row, so no orphan leaks. The consumer catches it to keep today's direct-PTY fallback; spawn_run lets it propagate (a detached backend launch has nothing to fall back to). It means infra failure only — input/context errors raise other types (see spawn_run contract).

Architecture: one launch half, two callers

The launch half is lifted out of the consumer into a shared _launch. The human WS path keeps its full prompt/argv build and attaches the viewer on top of _launch; the backend spawn_run wrapper composes the same prep helpers and calls the same _launch with no viewer. _launch contract — the shared launch half (slice #714)

Module-level, keyword-only, takes already-built launch facts and no self. It is the single launch path; the consumer's old inline body (hook injection → save → create_session → start_watch) moves here verbatim, plus the failure-branch row cleanup.
SIGNATURE
async def _launch(*, agent, project_id, module_id, task_id, argv, cwd, design_dir, scope, doc_rel_path, workspace_slug, agent_run_id) -> str
HOOKS
Inject per-agent lifecycle settings into argv for claude / codex / gemini / agy (each a no-op for other agents), using WORKTRACKER_MCP_URL (default DEFAULT_MCP_URL). Then command = shlex.join(argv). So a launched run reports to the lifecycle bus from the moment it starts — before any viewer.
PERSIST + CREATE
In one asyncio.to_thread worker: AgentRun.save(force_insert=True) (id, project/module/task ids, status="running", started_at, workspace_slug, cwd, design_dir) then tmux.create_session(agent_run_id, task_id, module_id, project_id, agent, command, cwd, scope, doc_rel_path) — which runs the agent inside a detached tmux session and writes the AgentTerminalSession row. close_old_connections() in finally.
WATCH
After success, documents_watch.start_watch(agent_run_id, design_dir, module_id, task_id, scope, publish=publish_lifecycle) — generated-HTML document watcher (#521), identical to a human run.
RETURNS
agent_run_id — the persisted, live, detached run.
RAISES
LaunchUnavailable on persist/tmux failure. Before raising, _delete_agent_run(agent_run_id) removes the half-inserted row (in its own to_thread worker, best-effort) so no orphan run leaks.
EXCLUDES
No self, no init dict, no profile, no cols/rows, no viewer. Those belong to the consumer's viewer half (PTY spawn, PtySession, client-size refresh, pump), which is unchanged and attaches on top.

spawn_run contract — the backend wrapper (slice #715)

Pure composition over the shared prep helpers + _launch, mirroring consumers._orchestrate minus the socket. Async callers await it; sync callers (the #704 on_commit receiver) wrap with async_to_sync(spawn_run)(...). Returns the id on success; raises on every failure (no socket to send an error code to).
SIGNATURE
async def spawn_run(*, agent: str, project_id: str, module_id: str, task_id: str, initial_prompt: Optional[str] = None, scope: str = "task") -> str
STEP 1 — PROFILE
_resolve_profile_index(); on None raise NoProfileSelected. Else read the profile, compute module_folder = profile.module_folders.get(module_id) or None (dropped if not a dir), cwd = module_folder or expanduser("~"). Mirrors the consumer verbatim.
STEP 2 — MINT
agent_run_id = uuid.uuid4().hex, minted before the prompt build (the task design dir embeds run_id[:8]) — exactly the WS ordering.
STEP 3 — PROMPT
await _build_prompt(...) with all mode flags false (task branch): fetch task, apply #587 worktree rooting (returns worktree_cwd), prep the #521 design dir, thread initial_prompt. Returns (prompt, design_dir, worktree_cwd, err). persist_task_id = task_id (task scope always persists under the real id).
STEP 4–5 — CWD + ARGV
if worktree_cwd: cwd = worktree_cwd (#587). argv = get_agent_command(agent, prompt); if the result is the ["echo", "Unknown agent: …"] sentinel, raise ValueError("unknown_agent") — the consumer's guard, so no unrunnable command reaches _launch.
STEP 6 — LAUNCH
return await _launch(..., doc_rel_path=None, workspace_slug=getattr(profile, "workspace_slug", None), agent_run_id=agent_run_id).
ERROR MAPPING
err == "no_profile_selected" → NoProfileSelected; any other _build_prompt code (task_id_required, task_fetch_failed, …) → ValueError(code). These are input/context failures — distinct from LaunchUnavailable, which means only that the persisted launch failed. So the #700 orchestrator can tell a bad request from an infra outage.
EXCLUDES
No viewer, no PtySession, no cols/rows, no self.send, no direct-PTY fallback (a detached backend run has nothing to fall back to). Scope is "task" only; no dedup (the "already running?" check is #700's ready-set, out of scope). agent is an explicit param with no default.
