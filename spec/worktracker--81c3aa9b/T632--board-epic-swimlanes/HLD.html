Board Epic Swimlanes — High-Level Design

Group the Kanban Board into horizontal bands, one per epic. Each lane spans the existing workflow-state columns; a card sits in its state column within its epic's lane. The same item set, re-laid-out — no new data, no backend change. Resolving a card's epic is already solved: owningEpic() walks parent_id to the first module ancestor.

The slice, in three pillars

Click a pillar to expand its boundary. Almost everything is reuse — the new surface is one selector, one lane component, one toggle.
PILLAR 1 · the lane model

A pure swimlane selector

A new boardSwimlanes() beside boardColumns() in backlogStore — same inputs, grouped by epic first.

  • Reuses owningEpic() (already in boardColumns) to resolve each card's lane — walks parent_id to the first module ancestor
  • One lane per module in module order; a trailing No-epic lane (parent null / dangling)
  • Within each lane, the existing per-state column buckets, each rank-sorted (#626)
  • All epics get a lane — even empty ones — so they're valid drop targets
  • Honors the shared epic / sprint filters exactly as boardColumns does today
PILLAR 2 · the layout

Lanes wrapping reused columns

A new BoardSwimlane renders a collapsible lane header over a row of the existing BoardColumn components, scoped to that lane's items.

  • Sticky column-header strip once at the top; lanes share one column-width grid so columns line up
  • Lane header reuses the Backlog group-header vocabulary: KEY · name, done/total, collapse chevron
  • Per-lane collapse persists via the same collapsedEpics localStorage key pattern
  • A Group by epic toggle (default ON) in the board header; OFF falls back to today's flat board
  • Toggle state persisted in uiStore
PILLAR 3 · drag = state + epic

Cross-lane drop reparents

Dropping a card into another lane's column sets both the state (the column) and the epic (the lane) in one optimistic patch.

  • Within-lane drag is unchanged: state change + #626 within-column reorder
  • Cross-lane drop computes target epic from the lane → one combined PATCH { state, parent_id, rank }
  • Optimistic update + rollback already exists in dropOnBoard / patchWorkItem — extended, not rebuilt
  • Sub-task cards across lanes: reparent-to-module would detach from their story — guarded (LLD Q1)
  • No edge routes — parent_id, state, rank are already in WorkItemPatch

Decision board

Green = resolved with the user this session. Red = genuinely open, settled in LLD — neither gates the shape.
RESOLVED · default

Toggle, and what default?

A "Group by epic" toggle, default ON. Swimlanes are the board you remember from Jira; flip off to get today's flat columns.

RESOLVED · cross-lane drag

What does dragging across lanes do?

Sets state AND reparents. Dropping into another lane's column changes the state (column) and the epic (lane) in one patch — true Jira behavior.

RESOLVED · empty lanes

Show epics with no cards?

Show all epics. Every epic gets a lane even when empty, so it's a valid reparent drop target. Plus a No-epic lane for loose cards.

OPEN · LLD Q1

Sub-task cards dragged across lanes?

A sub-task's epic is inherited from its story. Reparenting it straight to a module would detach it from its story. Recommendation: block cross-lane drop for sub-task cards (state-only, snap back). Settle in LLD.

OPEN · LLD Q2

Lane ordering & sticky behavior

Lane order = module sequence, No-epic last (low pressure). Whether the column-header strip and lane headers stick on vertical scroll is a layout detail for LLD.

Acceptance signal

The slice is done when the Board, by default, renders as horizontal epic swimlanes — one lane per epic (empty ones included) plus a No-epic lane — each lane showing the workflow-state columns aligned across the board; a card sits in its state column within its epic's lane; dragging a card across columns in the same lane changes state and reorders (#626) as today, while dragging it into another lane's column sets both its state and its epic in one optimistic patch; lanes collapse and show done/total; a Group by epic toggle flips the whole board back to today's flat columns and the choice persists — all with zero backend change, and with the sub-task cross-lane guard (Q1) and lane sticky behavior (Q2) settled in LLD.
