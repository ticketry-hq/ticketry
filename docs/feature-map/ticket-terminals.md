# Ticket terminals

A selected ticket presents its durable run through a retained terminal viewer, with native desktop rendering and an xterm compatibility path.

Surfaces: browser, desktop
Editions: pocock, core

## Sub-features

- ticket-terminal-selection: open the selected run's terminal from its workspace tab or live-terminal cycle.
- ticket-terminal-renderers: browser xterm over `browserTerminalClient`, deferred attachment and the xterm compatibility fallback.
- ticket-terminal-native-view: embedded native libghostty rendering, native input encoding and native view composition on supported macOS desktop.
- ticket-terminal-retention: keep recently opened viewers while tickets, tabs or covered workspaces change.
- ticket-terminal-ownership: present one foreground viewer, report presentation elsewhere and reclaim it with View here.
- ticket-terminal-ended: distinguish completed runs, lost sessions, dismissed terminals and resumable history.
- ticket-terminal-durability: keep run and tmux identities across viewer loss, renderer fallback and restoration.

## How to get to it

Select a Story in Stories and choose its provider/run terminal tab in **Workspace tabs** (`workspace-tabs`). **Run item**, the Agent launcher or **Open in Terminal** supplies a run; see [Agent launch](agent-launch.md). The selected terminal is rendered by `studio/src/features/task-workspace/terminals/SelectedTicketTerminal.tsx`; tab selection and dormant history are mapped in [Ticket workspace tabs](ticket-workspace-tabs.md).

Default capture actions `cycle-terminal-forward` (Cmd+Backslash) and `cycle-terminal-backward` (Cmd+Shift+Backslash, also the resulting Cmd+Shift+Pipe chord) cycle eligible live agent terminals, including a ticket inside a collapsed branch. The cycle presents the target ticket's agent terminal tab even when that ticket last remembered Details, because it publishes the terminal as the ticket's remembered workspace target before selecting it. In the WebView the chords route ahead of body engagement, so they also leave an xterm agent terminal that owns typing; an engaged native libghostty terminal does not forward them (they are not native terminal chords), so press Cmd+Escape first there. `workspace-tab-next` / `workspace-tab-previous` (Cmd+Right / Cmd+Left) select neighboring workspace tabs. Enter engages the highlighted terminal body; Cmd+Escape disengages input. `close-tab` uses fixed Cmd+W. `toggle-terminal-panel` uses Control+Backtick to reach the separate [Module terminal panel](module-terminal-panel.md); shell tabs are not agent-cycle destinations. Source: `studio/src/app/navigation/keymapBindings.ts`, `studio/src/app/navigation/workspaceNavigation.ts`, `studio/src/test/overhaulTerminalNavigationAcceptance.test.tsx` and `studio/src/test/overhaulTerminalPanelExitAcceptance.test.tsx`.

## Prerequisites

- A selected work item and a discovered or newly launched terminal session. Use disposable runs: closing a persisted terminal can terminate its underlying run.
- Desktop native proof requires supported macOS, the pinned libghostty library/resources, tmux and the desktop runtime. Use the isolated baseline profile in [the index](README.md); browser mode does not provide native views. Browser launch authority and its unverified provider-execution coverage are described in [Agent launch](agent-launch.md).
- Reclaim requires the same session to have foreground ownership on another surface. Resume requires server-reported resumability; terminated history is not automatically resumable.
- Architectural ownership is described by [Workspace Runtime](../../studio/src-tauri/crates/execution/ticketry-workspace-runtime/src/worktree/CONTEXT.md) and [Desktop Runtime](../../studio/src-tauri/crates/app/ticketry-desktop/src/desktop/CONTEXT.md). The [terminal renderer strategy](../plans/terminal-renderer-strategy.md) is historical; its status banner, `CLAUDE.md` and `AGENTS.md` identify the current renderer policy.

## Expected behavior

- **Selection and pending:** `SelectedTicketTerminal` delegates bucket/active-session presentation to retained viewers. A connecting temporary session survives durable run-ID acknowledgement. Deferred viewer attachment renders `terminal-viewer-pending`; desktop native availability or a missing durable run ID renders `terminal-renderer-pending`. These are blank pending hosts, not evidence of failure. Source: `studio/src/features/agents/terminal/RetainedTerminalViewers.tsx` and `studio/src/features/agents/terminal/Terminal.tsx`.
- **Renderers and failure:** supported desktop defaults to embedded native libghostty, which runs the validated tmux attach command in its own PTY. Browser defaults to xterm over `browserTerminalClient`'s attach-only WebSocket. Desktop xterm uses `tauriTerminalClient`; do not infer a desktop WebSocket from the browser path. Native unavailability chooses xterm. A reported native render failure falls back on the same run/session and temporarily shows **Native terminal unavailable: … Using compatibility renderer.** The notice disappears once compatibility transport is ready. Ended session statuses are not eligible for native attachment. Source: `studio/src/features/agents/terminal/Terminal.tsx`, `studio/src/features/agents/terminal/internal/rendererSelection.ts`, `studio/src/features/agents/terminal/internal/terminalClientRuntime.ts` and `studio/src/features/agents/terminal/internal/nativeViewerSessionLiveness.ts`.
- **Retention and persistence:** recently opened run viewers remain mounted while another ticket, Details or a document is selected, including a ticket with no terminals. Native viewers hide rather than reattach when their workspace is inactive or Changes is open. Module Manager hides the retained native view; ordinary dialogs preserve it beneath the WebView and surrender input. Retention is bounded to 20 mounted run viewers, including the selected viewer; least-recently-viewed eviction affects viewers, not durable session identity. A reload rebuilds presentation from authoritative run/session records and remembered run identity; it does not preserve native view objects through WebView destruction. Source: `studio/src/features/agents/terminal/RetainedTerminalViewers.tsx`, `studio/src/features/agents/terminal/NativeGhosttyTerminal.tsx`, `studio/src/test/overhaulNativeViewerRetentionAcceptance.test.tsx` and `studio/src/test/overhaulTerminalRestorationAcceptance.test.tsx`.
- **Ownership/reclaim:** the same session is presented through a foreground owner rather than duplicated for workspace/drawer/panel hosts. Another owner produces **This terminal is open in …** and **View here**. Reclaim changes presentation ownership; native ownership transfer reuses one viewer and does not itself grant input focus. Native and xterm ownership notices have different selector instrumentation. Source: `studio/src/features/agents/terminal/NativeGhosttyTerminal.tsx`, `studio/src/features/agents/terminal/XtermTerminal.tsx` and `studio/src/test/overhaulNativeViewerOwnershipAcceptance.test.tsx`.
- **Ended, close and recovery:** a `session_lost` terminal whose authoritative run is `exited` displays **Terminal ended** (or **Conversation ended**) with **The run finished and its terminal session is closed.** Other dead-session tab presentation and resumable/dismissed history are separate lifecycle projections. Externally killed terminals can remain as dead tabs; gracefully exited runs move into resumable history. Closing waits for termination; rejection keeps the terminal, and dismissal survives refetch. Source: `studio/src/features/agents/terminal/Terminal.tsx`, `studio/src/features/agents/terminal/TerminalEndedState.tsx`, `studio/src/test/overhaulTerminalLifecycleAcceptance.test.tsx` and `studio/src/test/overhaulTerminalCloseAcceptance.test.tsx`.
- **Durability:** tmux owns process continuity. Hiding or replacing a renderer does not create a different Agent Run, tmux session or persisted Terminal Session. Explicit terminal termination is a separate effect from viewer detach. Source: `CLAUDE.md`, `AGENTS.md`, `studio/src/features/agents/terminal/internal/rendererSelection.ts` and the linked Workspace Runtime context.

## Verifying it

Use `terminal-host-wrapper` and, where edit-view chrome is present, `terminal-mode-ring` with `data-terminal-mode` for the workspace surface. `retained-terminal-viewer` exposes `data-terminal-run-id` or temporary `data-terminal-session-id`; hidden retained wrappers are not current visible terminals. Native presentation uses `native-terminal-host`, `data-terminal-renderer="libghostty"` and `data-native-terminal-presented`. xterm uses `terminal-host`. Only xterm's ownership notice supplies `terminal-presented-elsewhere` and `terminal-reclaim`; native reclaim is the accessible **View here** button. Also observe `terminal-viewer-pending`, `terminal-renderer-pending`, `terminal-ended-state` and `native-terminal-fallback-notice`. `selected-ticket-terminal` in several tests is a mock selector, not a production host. Observed browser behavior these cases pin down: a ticket shell's tab (**shell terminal**) is not auto-selected; a clean shell exit or an agent run's completion removes its tab rather than leaving an ended viewer; completed runs become enabled **Resume** history; explicit close leaves a disabled **Terminated** chip; an externally killed session leaves a blank, unselected tab until backend reconciliation retires the run (about ten seconds), then the tab is removed. `terminal-ended-state` (**Terminal ended**) was not reachable in any browser flow exercised here, because the tab leaves the strip once the run is exited; ended-row cells therefore cite the history, close and lost-session outcomes. Assertions compare run IDs by membership, not row order (CODING-2870). The browser has no second foreground owner for a ticket run, so ownership is proven as one visible viewer per run; native **View here** and fallback-notice paths remain desktop evidence listed under Verifying it.

## Gotchas

- The desktop agent harness still clicks the retired **+ Add Module** control before launching a Story; current setup uses footer Module Manager → **New module**. Browser cases likewise inherit removed Modules-pane selectors in their shared onboarding/module setup. See [Onboarding gotchas](onboarding.md#gotchas). These scenarios describe authored assertions, with current passing execution unverified until setup succeeds.
- Terminal lifecycle, native viewer state and tmux liveness are separate axes. A mounted or hidden native host is not proof of a live process; `session_lost` alone does not establish a completed run. A viewer lease ending is not agent termination.
- Native libghostty terminal output never enters the WebView on desktop's native path: it stays in the renderer's PTY/native view. Lifecycle, layout, visibility and focus still use IPC. The explicit desktop xterm compatibility path consumes streamed output; do not apply the native-path claim to fallback.
- Browser xterm evidence makes no native-rendering claim. Browser module-shell tmux input/output is useful transport evidence, but does not prove native attachment retention, pixels, AppKit focus or paid-provider execution.
- Renderer overrides are development diagnostics only; packaged builds use their product default. The removed `ghostty-wasm` setting is not a selectable third renderer. The linked renderer-strategy body is historical and its title is superseded.
- The [Desktop Runtime catalog](../eventcatalog/domains/desktop-runtime/index.mdx) still mentions a Python sidecar. That runtime description is stale: the linked crate context and current `CLAUDE.md` describe in-process Rust services.
- Saved keymap overrides, typing engagement, modal ownership and pending visibility can change which route accepts a chord. Retained DOM presence alone is not visibility or keyboard ownership.
- Full installed-native reclaim/failure/retention walkthroughs are unverified here; mocked native messages and source assertions must stay labeled as such.
