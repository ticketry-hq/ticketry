Refined Scope

Today BacklogView and BoardView are two shell destinations, each building its own ViewHeader and duplicating the load / planning-reconcile / selection lifecycle; the LayoutSwitcher is a pair of router Links that navigate between them. It looks like one page but is two. This ticket makes it one — the filter unification lands separately in CODIN-833.

One route

/projects/:id/issues

The single canonical Issues URL. Legacy /backlog and /board become redirect entry points that set the layout intent, then replace to /issues.

One container

IssuesView

Owns the single ViewHeader (title Issues + count), the LayoutSwitcher, the per-layout header controls + filter slot, and the shared load / reconcile / selection / Escape lifecycle.

Local sub-state

studio.issues.layout

List/Board is persisted UI state, default list. The switcher writes it; toggling never changes the route and never refetches — the shared store keeps its data.

Toggle vs Redirect Flow

The two ways a layout is chosen: an in-place toggle (no navigation, no refetch) and a legacy deep-link redirect that lands on the same container.

In-place toggle

List ↔ Board

Clicking the switcher calls setIssuesLayout. Route identity is unchanged, loadBacklog is not re-called (project unchanged), the shared backlogStore keeps its items. Only the rendered body and the contextual header controls change.

Legacy deep link

/backlog & /board

A dedicated static route renders a redirect element that sets the layout intent (list or board) synchronously, then <Navigate replace> to /issues. The nav drawer, root redirect, create-project completion, and issue-detail back links all target /issues directly.

Routing & View Identity

A single issues active view replaces the independent backlog/board destinations. React-router ranks the static legacy segments above the dynamic :view route, so they intercept the redirect before normalizeView ever sees them.
