Rules settled in refinement

These are the load-bearing rules. The implementation should make the happy path easy and the forbidden path awkward.

Shared run identity

  • Doc-chat run identity stays in terminalStore.chatByDoc.
  • Key remains docChatKey(taskId, docRelPath).
  • Drawer and /coding dedupe to the same run.

Surface presenter

  • Overlay visibility becomes a single presenter value: coding or drawer.
  • Opening in one surface transfers presentation away from the other.
  • Closing clears only if the closing surface owns presentation.

No selection coupling

  • Drawer launch must not read tasksStore.selectedTaskId.
  • Drawer launch must not repoint /coding selected task/module.
  • Scope comes from DrawerLaunchContext.

Decisions

The LLD keeps the implementation narrow and avoids new ownership surfaces.

DecisionChosen pathWhy
Presenter storageExisting workspaceStore, not a new store.The current overlay state already lives there; a presenter value is the smallest change that encodes mutual exclusion.
Terminal presentationReuse DrawerTerminalHost from CODIN-751.Creating a second host path would bypass the single-entry-pool invariant and reintroduce duplicate xterm/WS risk.
Drawer launch scopeUse DrawerLaunchContext.The drawer knows the issue; /coding globals may be on another task/module and must not be repointed.
Run identityKeep terminalStore.openDocChat and chatByDoc.Existing #625 semantics already provide one live doc-chat run per issue/doc.
Unavailable profile UXDisable edit affordance with scoped reason.Details and iframe remain useful; launch failure should be local and explainable.

Acceptance signal

CODIN-752 is complete when a user can click edit-with-agent on a drawer Doc tab, launch or reveal the same per-doc doc-chat run using the drawer issue context, see it in a drawer overlay backed by DrawerTerminalHost, transfer presentation cleanly with /coding, and close the overlay without killing the run or disturbing Details, Doc tabs, Terminal tabs, dormant chips, or /coding doc-chat behavior.
