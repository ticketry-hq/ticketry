4 · Investigation harness — exact, non-mutating

All commands run from worktracker-stack/. Ordering guarantees "no production code changed"; steps 2–3 outputs and both git-status snapshots are pasted verbatim into the report.
1
Clean-tree guard. Record git status --porcelain for openapi.json and worktracker-typescript-sdk/src/generated before anything, so any churn is attributable.
2
Drift check (primary evidence). Run npm run contract:check. The script exports OpenAPI to a temp file and regenerates the SDK into a temp dir (sets WORKTRACKER_GENERATED_DIR internally), then diffs both against the committed copies — it never writes into the repo. Capture stdout/stderr + exit. Expected: "Contract artifacts are current." (exit 0), which makes the committed openapi.json authoritative.
3
Coverage inspection (no churn). Read the committed openapi.json (justified by step 2), and generate the SDK to a scratch path with WORKTRACKER_GENERATED_DIR=<scratch>/generated npm run sdk:generate so generation lands entirely outside the repo. Record the invocation and the generated apis/*.ts classes/methods.
4
Path extraction. Enumerate paths from the schema and method names from the scratch SDK. These two lists are ground truth for the "In OpenAPI?" and "SDK method?" columns.
5
Post-run guard. Re-run step-1 git status --porcelain; confirm unchanged and record it. Scratch dirs are outside the repo — no cleanup needed.

5 · Classification & verdict rules

How each row resolves and how the rows roll up to the binary verdict.
  • Present + SDK method → covered; T687-5 can migrate that call directly.
  • Present, no SDK method → contract present but generator gap (note generator/config implication). Not expected given the pipeline shape.
  • Missing from OpenAPI → gated; needs a contract addition before the SDK can serve it.
  • Verdict logic — if any in-scope endpoint a ported call depends on is Missing, the overall verdict is GATED, naming the gating families. T687-5 proceeds directly only if every non-WebSocket endpoint is covered.
  • The report names the root cause (two OpenAPI surfaces — standalone worktracker contract vs. unified Muxed host API) so the follow-up is scoped as which surface to expand and how, and ties the gate to CODIN-668.

Working verdict to confirm: GATED

Inspection of openapi.json (only /work-tracker paths) and server/studio_server/api.py (host routers on a separate NinjaAPI the generator never reads) indicates families B–F are entirely outside the generated contract. The report must prove this by running §4, not assert it.

6 · Gap enumeration for the follow-up (if GATED)

Descriptive scoping for CODIN-668 / a T687-5 predecessor — the spike does not design or implement these.

For each Missing family the report records: path + verb set, query/path params, request body schema, response schema (named from the host router signatures), and the architectural decision the follow-up must make:

  • Fold host routers into the SDK-exported schema (one unified OpenAPI), or stand up a second generated client for the host surface.
  • Which endpoints are unsuitable for a typed REST SDK at all — e.g. /api/docs/{doc_id}/{asset_path} serves opaque assets; /ws/terminal is already excluded.
  • runs/lifecycle-states overlaps the Studio coding-bridge seam (Studio's one current raw fetch) → highest-value first migration target.
