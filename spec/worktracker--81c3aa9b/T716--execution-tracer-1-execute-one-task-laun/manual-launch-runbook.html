Manual tracer launch

How the internal #716 execution tracer was invoked to launch one implement run for CODIN-716 and make it attachable from the terminal UI.

What this proves

TriggerThe internal callable apps.execution.driver.execute(...) can launch a task-bound implement run.
Launch seamThe driver calls apps.terminals.launch.spawn_run, not _launch directly.
UI attachAgentRun and AgentTerminalSession rows are written for the existing terminal attach path.

Preflight

Confirm the task exists in the local WorkTracker DB and inspect its parent chain.

cd /path/to/repository/server
uv run python manage.py shell -c "from worktracker.models import Issue; tid='TASK_UUID'; issue=Issue.objects.filter(id=tid).select_related('project','parent').first(); print(issue.key, issue.name, issue.type, issue.project_id, issue.parent_id)"

Expected the selected task exists beneath the expected module.

Launch

Invoke the internal tracer. The caller supplies the agent explicitly; the driver owns no default.

cd /path/to/repository/server
uv run python manage.py shell -c "from apps.execution.driver import execute; tid='TASK_UUID'; state=execute(tid, agent='codex'); print('status', state.status); print('task_id', state.task_id); print('module_id', state.module_id); print('agent_run_id', state.agent_run_id); print('error', state.error)"

Observed status=running with the expected module and agent-run identifiers.

Verify attachability

Check that the launch wrote the rows consumed by the terminal UI.

cd /path/to/repository/server
uv run python manage.py shell -c "from apps.runs.models import AgentRun; from apps.terminals.models import AgentTerminalSession; rid='RUN_ID'; run=AgentRun.objects.get(id=rid); print('run', run.id, run.status, run.agent, run.task_id, run.module_id, run.cwd); print(list(AgentTerminalSession.objects.filter(agent_run_id=rid).values('agent_run_id','tmux_session_name','task_id','module_id','agent')))"

Observed a tmux session, task, module, agent, and repository-relative working directory.

Notes

No UI trigger This is still not a product surface. It only proves the backend tracer can launch a task-bound run that the existing terminal UI can attach to.

Process-local state The execution registry lives only in the server process that ran execute(...). The terminal run itself is persisted through AgentRun and tmux.

Acceptance signal: a manual call to execute(CODIN-716, agent="codex") produced a running AgentRun and terminal session for CODIN-716, proving the #716 tracer launch path can feed the existing UI attach path without adding a trigger UI.
