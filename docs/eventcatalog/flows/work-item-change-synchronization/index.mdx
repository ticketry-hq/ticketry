## What the domain model says

There is one authoritative Work Item. Any client projection of that item should
be refreshable when its authoritative revision changes.

## What the implementation does today

Studio has multiple projections. The status feed updates backlog/task
collections for state moves, but the issue-detail store is neither reconciled
nor invalidated. The feed also has no general changed-fields event and no
deletion tombstone.

## The useful connection

This is not simply a frontend bug or backend bug. It is a translation gap
between:

1. the domain identity (**one Work Item**);
2. the backend persistence model (a complete Issue row plus a state-only
   revision cursor); and
3. the frontend read model (several independently refreshed projections).

The catalog intentionally renders that mismatch instead of inventing a cleaner
architecture than the code currently provides.
