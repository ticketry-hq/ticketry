# Conversations

Conversations launch taskless Instant agents in a module, collect optional first messages, retain user titles and select each conversation's terminal.

Surfaces: browser, desktop

## Sub-features

- conversations-instant: start immediately with the default launch policy and select the new run.
- conversations-composer: collect a first message and optional activated provider, with draft-preserving cancellation.
- conversations-rename: edit the selected conversation's manual title without changing its run or terminal identity.
- conversations-provider-title: refresh eligible Codex titles while preserving safe and manually saved names.
- conversations-terminal: select and engage the terminal belonging to a concrete conversation run.

## How to get to it

In a selected module's Stories pane, expand **Conversations** and click the **New conversation** treeitem. The `instant-change` action defaults to Cmd+I, with bare I as a default alias; it starts directly without the composer. Click **Start a conversation with a prompt** on that row, or use `instant-change-with-prompt` (Cmd+Shift+I), to expand the section and open its inline composer. These are conversation entry points, not the Story **Run item** action. Sources: `studio/src/app/shell/ticket-workspace/tasks/components/ConversationRows.tsx`, `studio/src/features/conversations/composer/conversationComposerStore.ts` and `studio/src/app/navigation/keymapBindings.ts`.

The composer has textbox **First message for the new conversation**, combobox **Agent for the new conversation**, **Default agent** option and **Start** button. Start submits the trimmed message; Cmd+Enter or Ctrl+Enter submits locally, plain Enter inserts text, and Escape closes. Activated terminal providers populate the combobox. Source: `studio/src/features/conversations/composer/ConversationComposer.tsx`.

Click a conversation row to select its exact run and focus the terminal. Clicking the selected title activates **Rename conversation: <title>**; an unselected title first selects the row. The resulting textbox is **Conversation title**. Enter or blur saves, Escape cancels, and a focused rename button accepts Enter/Space. Up/Down row navigation selects without engaging terminal input; `edit-view.right` (Right) engages the selected conversation terminal, and Cmd+Escape disengages it. Sources: `studio/src/features/conversations/rename/ConversationTitle.tsx`, `studio/src/app/shell/ticket-workspace/tasks/internal/instantRunTicketNavigation.ts`, `studio/src/test/overhaulConversationRenameKeyboardAcceptance.test.tsx` and `studio/src/test/overhaulEditViewNavigationAcceptance.test.tsx`. See [Keyboard navigation and shortcuts](keyboard-navigation-and-shortcuts.md) and [Ticket workspace tabs](ticket-workspace-tabs.md) for workspace navigation and dormant resume.

## Prerequisites

- Select a project and module. A launch requires its linked local folder; a missing folder opens the module-folder gate, whose successful save resumes the captured launch. See [Module folders and trust](module-folders-and-trust.md) and `studio/src/features/studio/modals/PlanFeature.tsx`.
- Actual agent execution requires a configured real or disposable provider and working runtime services. The feature browser suite uses the real Rust launch authority with a disposable local provider; DOM tests provide supplementary presentation coverage. No paid provider is required by the cited automated coverage.
- Rename requires an existing selected Instant conversation with a concrete agent-run ID. Automatic provider-title refresh additionally requires a Codex Instant run with a nonempty provider-session ID and hydrated conversation cache row (`studio/src/features/agents/terminal/instantRunTicketTitle.ts`).

## Expected behavior

- **Immediate launch:** the default path sends an Instant create request without forcing a provider, model, reasoning or prompt override; the server's configured default policy resolves it. The created run is attached as taskless Instant, selected in the module's scratch bucket and focused. Launch failure reports **Conversation did not start**; a zero-provider refusal leaves no new terminal. Sources: `studio/src/features/agents/terminal/instantConversationLaunch.ts`, `studio/src/features/studio/modals/PlanFeature.tsx`, `studio/e2e/documents-and-scratch.spec.ts` (`web-scratch-01`) and `studio/src/test/overhaulInstantTicketsAcceptance.test.tsx` (`overhaul-367`).
- **Composer success/cancel/empty:** opening expands a collapsed Conversations section and focuses the textbox. Blank/whitespace-only input disables **Start** and performs no launch. Submission closes the composer, clears its draft and forwards the trimmed message plus the optional explicit provider. Escape retains the typed draft for reopening; arrows and plain Enter stay with the editor. Changing module closes the composer. Draft retention is Apollo client state, not a claimed restart-persistence contract. Sources: `studio/src/features/conversations/composer/ConversationComposer.tsx`, `studio/src/features/conversations/composer/conversationComposerStore.ts` and `studio/src/app/shell/ticket-workspace/tasks/components/ConversationsHeaderRow.tsx`.
- **Rename success/cancel/error:** save trims the name; unchanged input exits without a mutation. Empty input reports **A conversation title is required.** and remains editable. A failed write keeps the draft for retry, pending writes are deduplicated/read-only, and switching rows does not redirect the original run's write. Escape performs no write. Keyboard completion restores rename-button focus only when that editor still owns focus; unrelated navigation is preserved. Sources: `studio/src/features/conversations/rename/ConversationTitle.tsx`, `studio/src/test/overhaulInstantConversationRenameAcceptance.test.tsx` and `studio/src/test/overhaulConversationRenameKeyboardAcceptance.test.tsx`.
- **Titles and persistence:** manual rename uses restricted `update_agent_run(id, input: {conversationTitle})`, then publishes its authoritative returned title to Apollo; it changes presentation without recreating the conversation session. Manual titles outrank accepted provider names. Older list/provider responses must not erase a committed rename, including a rename back to its original value. Eligible selected Codex conversations refresh on lifecycle changes, reselection and resident title-reader restart; failed or unavailable reads retain the safe existing name. Sources: `studio/src/features/conversations/rename/renameInstantConversation.ts`, `studio/src/features/agents/terminal/operations/updateInstantConversationTitle.graphql`, `studio/src/features/agents/terminal/instantRunTicketTitle.ts`, `studio/src/shared/apollo/conversationTitleGuardLink.ts` and the rename acceptance tests. The existing mock refetch/reopen coverage is not a real server-restart proof; verify authoritative readback and reload separately.
- **Terminal and empty list:** selecting a conversation routes by its run identity, rather than a remembered peer's terminal; conversation presentation is terminal-only. **New conversation** is an action row and hides the selected workspace while awaiting a launch. The heading can configure Conversations even with no chats. A recent ended-run count offers **N ended today**: it counts distinct Instant runs that ended in the last 24 hours across the module WorkItem's reattachable ended runs and the authoritative resumable-session read, so a completed conversation whose terminal session was terminated on exit still counts after reload; resumable history uses the workspace's dormant tabs. Sources: `studio/src/features/conversations/history/endedConversationsToday.ts`, `studio/src/app/shell/ticket-workspace/selected-ticket/SelectedTicket.tsx`, `studio/src/app/shell/ticket-workspace/tasks/internal/instantRunTicketNavigation.ts`, `studio/src/app/shell/ticket-workspace/tasks/components/ConversationsHeaderRow.tsx` and `studio/src/test/overhaulInstantTicketsAcceptance.test.tsx` (`overhaul-202`, `overhaul-312`) and `studio/src/test/overhaulConversationsEndedCountAcceptance.test.tsx` (`overhaul-823`). See [Ticket workspace tabs](ticket-workspace-tabs.md) for close, resume, error and retention behavior.

## Gotchas

- `studio/src/features/conversations/prototype` is excluded from the normal product inventory: `ConversationDesignPrototype.tsx` returns no variant when `import.meta.env.PROD` is true. In development only, `?conversation-design=list`, `inbox` or `timeline` opts into alternate layouts via `TasksPane.tsx`; an ordinary development launch without that query uses production rows. `studio/src/test/overhaulConversationDesignPrototypeAcceptance.test.tsx` covers those opt-in designs (`overhaul-242` and named variant cases), not normal-build reachability. Narrow command: `bun run --cwd studio test -- src/test/overhaulConversationDesignPrototypeAcceptance.test.tsx`.
- The feature suite uses a disposable provider for execution; legacy successful request mocks establish launch intent only. native terminal operation and desktop focus/trust proof need the desktop build. The current Rust browser adapter also configures terminal launch authority (`studio/src-tauri/crates/app/ticketry-dev-tools/src/bin/ticketry_graphql_adapter.rs`); its historical launch-unavailable description does not establish a universal refusal, and its real Instant launch is exercised by this browser suite. Native libghostty rendering, focus delivery, geometry and tmux retention require desktop evidence; browser xterm and mocked native messages cannot prove them. The cited desktop harness uses a disposable executable and makes no paid-provider claim.
- UI manual rename writes Ticketry's `conversation_title`; the `rename_codex_thread` MCP capability changes the provider thread name instead. The resident Codex ADR explains that distinction; these operations do not replace one another.
- Composer closes before launch success; source does not promise restoration of a submitted prompt after provider refusal. Only Escape/reopen draft preservation is covered. Draft survival through application restart, cross-module draft isolation and real native rename/focus are unverified.
- Configurable keymap overrides and modal/typing focus ownership can change effective shortcuts. Conversation **Down** selection alone does not establish engaged terminal input. Source-only timing and mock refetch behavior are not server-restart evidence.
