Collapse loopback HTTP — route owned backend through worktracker services directly

The ASGI server calls itself over httpx at 127.0.0.1:8787/api/work-tracker even though worktracker.api.router is mounted in-process. This slice replaces that self-targeted loopback with direct in-process Python calls into the worktracker package, and collapses the two duplicate adapters into one. Grounded in the live code of core/core/worktracker_client.py, worktracker/api/*, worktracker/services/*, and the four server consumers.

The mounted /api/work-tracker router stays — external and SDK callers still use it. Only the owned-backend adapter stops dialing it over TCP and instead calls the same logic in-process through the new query surface.

New read surface — worktracker/services/queries.py

The read peer of #724's mutation services. Seven sync functions, one per adapter read method. Each returns plain dicts shaped like the current *Out subset the adapter reads — so the adapter's existing _to_task_summary / _to_state mappers consume them verbatim. No Ninja Schema import; services stay framework-neutral (#735).

Per-item dict = a strict subset of WorkItemOut: id, name, project_id, sequence_id, priority, state{id,name,group,color}|null, assignees[{display_name,email}], labels[{name}], description_html, description_stripped, description, parent_id, sub_issues_count. sub_issues_count comes from the task_qs() child_count annotation (archived children excluded, #633), matching WorkItemOut.resolve_sub_issues_count. Adapter transform — core/core/worktracker_client.py

The adapter stays server-side and keeps its async 9-method contract verbatim — so every call site and every monkeypatch.setattr(pc.WorktrackerRepository, …) in the test suite keeps working. Only the transport changes.
REMOVEDimport httpx; module constants OWNED_API_PATH / LOCAL_OWNED_API_URL; the _normalize_owned_api_url function; the repo's _open(), _base_url / _headers state, the x-api-key header, and the now-unused workspace_slug binding in _set_profile.
KEPTClass name WorktrackerRepository + all 9 async method signatures; the dict→DTO mappers _to_task_summary / _to_state (reused verbatim — they already consume the dict shape the query surface returns); WorkTrackerRepository (SDK) entirely; NoProfileSelected, resolve_profile, resolve_profile_index, repository_for, get_repo (profile/backend resolution → #741).
METHOD BODIESEach method becomes await sync_to_async(queries.fn)(…) then maps the returned plain data with the existing mappers. get_tasks_and_states keeps the direct-children filter (parent_id == module_id) in the adapter; get_module_task_summaries keeps the full subtree (no filter). The old asyncio.gather of two asyncio.to_thread calls disappears — one sync_to_async hop per method.
ASYNC BOUNDARYWrap with asgiref.sync.sync_to_async (not asyncio.to_thread) — the wrapped code touches the Django ORM and needs thread-sensitive context. Query functions are fully sync and return materialized primitives, so no ORM object or lazy relation crosses the async boundary (avoids SynchronousOnlyOperation).

Parity invariants — must hold after the change

These are the behaviors the ticket calls out to preserve. They are testable assertions, not aspirations.
  • State fallback — an absent/null state serializes to TaskState(name="Unknown") via the adapter's _to_state.
  • sub_issues_count — sourced from the child_count annotation (archived children excluded, #633), not recomputed differently.
  • Module membership split — get_tasks_and_states returns only the module's direct children (parent_id == module_id); get_module_task_summaries returns the full task-descendant subtree (#516 roll-ups).
  • Ordering — work-item lists keep order_by("rank", "sequence_id"); states keep order_by("sort_order", "created_at").
  • Archived hidden — list reads exclude is_archived=True (no include_archived exposed to the adapter; default matches today's API).
  • identifier from slug — ProjectSummary.identifier is populated from the project slug.
  • DTO shapes unchanged — ProjectSummary / ModuleSummary / TaskState / TaskSummary / TaskDetails / AssigneeSummary / LabelSummary returned with identical fields and types.
  • External API untouched — /api/work-tracker routes, schemas, status codes, OpenAPI, and the SDK path are not modified; only the owned-backend adapter stops calling them over the wire.
