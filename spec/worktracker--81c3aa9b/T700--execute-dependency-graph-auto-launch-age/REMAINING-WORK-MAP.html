The shape of it

#700 is an autonomous two-phase engine — Plan (refine → split → register → leaf-LLD) then Execute (topo-launch implement runs). It is delivered as one linear chain of tracer slices over two shared foundations (the issue_state_changed seam and the spawn_run() launch primitive). The pure engine lives in ../server/apps/execution/ (reducer.py · driver.py · recipes.py · signals.py · state.py).

Done — closed in WorkTracker & in code Built — code landed, ticket still In Progress (unmerged) Remaining — designed or planned, not built Future / Backlog — not yet refined

The single-task engine works today: an implement / refine / split run can be launched, and completion is observed off the seam. What is not built is everything that turns one task into a graph: multi-task ready-set release, failure/idempotency, split registration into real tasks+edges, per-leaf LLDs, and the user-facing trigger.

What actually remains

Six tickets carry net-new behavior, plus the housekeeping of merging/closing the six already-built ones. Ordered by the critical chain.

#717 · REMAINING exec tracer 2

Ready-set release across a blocked_by chain. Today reducer.decide() tracks exactly one task. This slice adds the multi-task core: a topo walk of the subtree, compute the ready-set (blockers all in completed), launch parallel-on-ready, and release newly-unblocked tasks as seam completions arrive.

Blocks: #718. First unbuilt link in the chain.

#718 · REMAINING exec tracer 3

Failure propagation + idempotency. A failed run halts its dependents while independent branches keep draining; re-invoking an execution must not double-launch. Needs per-task run-state beyond the single Status enum.

Blocked by #717 · Blocks #719 (chain ordering only).

#745 · REMAINING LLD ready register split

Add a 4th phase register. On root → LLD, launch an agent that parses the approved HLD and creates the real leaf tasks + blocked_by edges (slug-idempotent, Todo landing, surface-and-halt on first failure). Design is complete (see ticket); state.py Phase still only has implement/refine/split.

Blocked by #720 · Closest to shovel-ready.

#743 · REMAINING leaf LLDs

Generate one LLD per registered leaf. After #745 has created the leaves, launch a leaf-level LLD-generation phase for each. Does not run implementation agents. Still Backlog; no dependency edge wired (should follow #745).

#721 · REMAINING capstone

Trigger surface + full plan→execute pipeline. The user-facing entrypoints: MCP execute_dependency_graph(root_task_id) and a Dependency-view action, wiring the whole cascade end-to-end.

Blocked by #720. (UI-launch bridging carved into #746.)

#744 · REMAINING state model

Internal / hidden lifecycle states. Replaces the interim reuse of WorkTracker states (Todo=start-HLD, LLD=approved-split) with a durable planning-pipeline state model. Explicitly deferred; the whole chain works on interim signals until then.

Contracts the next agent must honor

Exact signatures, literals, gates, and payload shapes — verbatim from the code on 2026-07-02.

Reducer state machine (state.py + reducer.py)
Phase"implement" | "refine" | "split"  (no register yet)
Status"idle" | "running" | "done" | "failed"
EventKindexecute_requested · run_started · run_failed · issue_state_changed
ActionKind"launch" (only)

Completion gate _is_complete(): implement → to_group=="completed" · refine → from_group=="backlog" and to_group=="unstarted" · split → to_state=="LLD" (by name, since LLD's group is unstarted — a Todo→LLD move doesn't change group).

decide() ignores any event whose task_id ≠ state.task_id; execute_requested is a no-op unless status=="idle".

Driver gates & run-state (driver.py)

execute(task_id, *, agent, phase="implement", spawn=None) requires Issue.type=="task"; derives module via _module_id_for (walks parent chain to a type=="module" ancestor). Raises ValueError: task_not_found · module_id_required · task_not_in_backlog (refine needs backlog group) · task_not_in_todo (split needs unstarted group).

Run-state is a module-level _registry: dict[task_id → EngineState] — process-local, non-durable, single-task. observe_issue_state_changed only acts if the task is already in _registry. This is the #716 deferral point.

Seam contract (worktracker/signals.py) — #706

Payload on issue_state_changed.send: sender=Issue, issue_id, project_id, from_state_id, to_state_id, from_group, to_group. Groups ∈ backlog/unstarted/started/completed/cancelled or None.

Fires on post_save only when state_id identity changes, deferred to transaction.on_commit (rolled-back moves emit nothing). Create-into-state emits with from_state_id=None.

Receiver rule: handlers MUST NOT synchronously mutate Issue.state / call save() with a state change (re-entrancy).

Gotcha: queryset .update(state=…) writes fire no post_save → no seam event. Confirmed live at worktracker/services/workflow_config.py:193. Any bulk state change bypasses the executor.
Launch primitive (terminals/launch.py) — #715

async spawn_run(*, agent, project_id, module_id, task_id, initial_prompt=None, scope="task") → str (returns agent_run_id). Persists AgentRun + AgentTerminalSession keyed by task_id; attachable via existing mode:"attach". No dedup ("already running?" is #700's ready-set, explicitly out of scope).

Raises: NoProfileSelected · ValueError (build-prompt/context codes) · LaunchUnavailable (tmux/persist). Driver calls it via async_to_sync(spawn)(...); on any exception it feeds a run_failed event.

HTTP entrypoint (execution/api.py)

POST /work-items/{issue_id}/planning-run · auth ApiKeyAuth. Body {phase: "refine"|"split", agent: "claude"|"agy"|"codex"|"gemini"}. Returns 201 PlanningRunOut. Codes: 409 already-running · 404 task_not_found · 422 other ValueError. This is what #746's drawer buttons call.

Recipe prompts (recipes.py)

refine: grill interview → distilled visual HLD in spec dir → update description → move Backlog→Todo; no code. split: HLD/splitter → visual HLD + proposed leaf tree + intended blocked_by; creates no tasks/edges/leaf-LLDs; approval = human moves Todo→LLD. Both interpolate issue.id/key/name/project_id/project.slug + description.

Gaps & flags

Things worth deciding before picking up the remaining chain.

Missing dependency edges

#743, #744 and #746 carry no blocked_by edges. Logically #743 (leaf LLDs) should follow #745 (register), and #721 (capstone) depends on the whole chain, not just #720. Wire these before the engine executes its own graph, or execution will mis-order them.

The chain is built out of order vs. the demo order

Plan-phase slices #719/#720 are already built, but execute-phase #717/#718 (earlier in the chain) are not. The single-task engine (#716) is done; the graph engine (#717) is the true next build.

Run-state model is thin

EngineState.status is a single enum for one task. #718 needs per-task run-state across a subtree and a durable, idempotent store — currently process-local only (the #716 orchestrator-home decision explicitly deferred durability).

#745 is the cheapest next win

Its LLD is complete and it plugs straight into the existing phase machinery (add register to Phase, a recipe, a launch-on-→LLD trigger + relaunch guard). It does not require the #717/#718 graph work.

Parent #700 state: this map is a status/roadmap deliverable, not the engine LLD. #700 stays in Todo — its next design deliverable remains the engine HLD (phase model, reaction table, run-state model) that #717/#718 build against.

Bottom line

Foundations + single-task engine + planning phases are built. A refine / split / implement run launches, and completion is observed off the tracker-state seam.

To finish #700, build (in order): #717 ready-set graph engine → #718 failure/idempotency → #745 register phase → #743 leaf LLDs → #721 trigger surface, with #744 (state model) deferred. Then merge & close the six In-Progress tickets and wire the missing dependency edges.
