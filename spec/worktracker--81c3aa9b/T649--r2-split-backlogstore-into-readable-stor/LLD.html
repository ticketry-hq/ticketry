Refactoring Specifications

Grounded details on the split file contents and type boundaries.
Module Name Purpose & Contents Signature Examples
backlogSelectors.ts Houses all pure selectors, rank comparison logic, filter matching, and output structures. Contains no Zustand dependency. compareRank(a, b)
owningEpic(item, moduleIds, itemById)
groupBacklog(items, modules, filters)
backlogSprintActions.ts Sprint operations slice. Direct mutation handlers invoking Sprint endpoints and local optimistic updates. createSprint(set, get, projectId, name, dates)
moveItemToSprint(set, get, id, sprintId)
setSprintStatus(set, get, id, status)
backlogIssueActions.ts Issue operations slice. Optimistic state transitions, reparenting, local/remote reordering, board dropping (with epic swimlane reparenting), and bulk updates. createIssue(set, get, projectId, body)
reorderItem(set, get, itemId, beforeId, afterId)
dropOnBoard(set, get, itemId, stateId, beforeId, afterId, targetEpicId)
backlogBlockerActions.ts Blocker mirroring edge update when a work item's blocker list changes. mirrorBlockerChange(set, get, blockedId, added, removed)
backlogStore.ts The orchestrating store entrypoint. Defines state interfaces, creates the Zustand hook, delegates action invocations, and re-exports selectors for backward compatibility. useBacklogStore = create<BacklogState>((set, get) => ({ ... }))

Build order

Our five-step build process to complete the refactor smoothly.
1 Selectors Extract pure functions to backlogSelectors.ts. Re-export them from backlogStore.ts and check tests.
2 Sprint Actions Extract sprint operations to backlogSprintActions.ts, update store delegation.
3 Blocker Actions Extract blocker edge mirroring to backlogBlockerActions.ts, update store delegation.
4 Issue Actions Extract issue CRUD & reorders to backlogIssueActions.ts, update store delegation.
5 Typecheck & Verify Validate all frontend builds, TypeScript types, and test suites are 100% green.
