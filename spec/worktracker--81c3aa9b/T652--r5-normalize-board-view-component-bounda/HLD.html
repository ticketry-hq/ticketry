Evolution of Board Boundaries

How component coupling changes in this refactoring to ensure clean presentational boundaries.
PRE-REFACTOR · HIGH COUPLING
BoardCard and BoardColumn directly import stores (useBacklogStore, useSelectionStore) and router hooks (useNavigate), creating implicit side effects and wide, untracked props.
⟶
THIS DESIGN · CLEAN BOUNDARIES
Only BoardView acts as coordinator for store reads and navigation. Layout components receive data and callbacks; column headers are consolidated into BoardColumnHeader.

Proposed Component Boundaries

Redistributing responsibilities across components to establish narrow props and clean abstraction boundaries.
BoardCard · Presenter

Focused Presentational Card

Only renders card content, priority chips, and local drag-start states. All database/store writes, selections, and navigations are delegated to callbacks.

Props: item, selected, onClick, onKeyDown, onDropOnCard
BoardColumn · Layout

Drop Target Layout

Binds the Pragmatic drop target to the DOM element and renders the column body. Does not import selection or issue detail stores. Passes callbacks to cards.

Props: column, laneEpicId, showHeader, onAdd, onDropOnColumn, onCardClick, onCardKeyDown, onDropOnCard, selectedIds
BoardColumnHeader · Shareable

Extracted UI Component

Combines column status indicators, names, counts, and quick-add button. Renders uniformly on flat board columns and swimlane sticky strips.

Props: state, count, onAdd

Refactoring Pillars

Click a pillar to expand its details.
PILLAR 1 · STORE DECOUPLING

Decouple Layout from Stores

Eliminate store hook invocations in Card and Column components. Move logic to callbacks.

  • Remove useBacklogStore and useSelectionStore from BoardCard
  • Remove useBacklogStore from BoardColumn
  • Inject selection states (selectedIds) as a prop or lookup set
PILLAR 2 · HEADER CONSOLIDATION

Extract BoardColumnHeader

Resolve duplicated column header rendering logic between swimlane mode and flat mode.

  • Create a new BoardColumnHeader component
  • Implement color dots, label formatting, items count, and quick-add action
  • Replace inline headers in both BoardView and BoardColumn
PILLAR 3 · DND & ROUTING PRESERVATION

Preserve DnD & Routing Interactions

Keep Pragmatic drag-and-drop auto-scroll and DOM targets functional while passing callbacks.

  • Keep DOM-bound element hooks (auto-scroll strip, drag sources, drop zones) inside layout components
  • Delegate drop coordinates and navigation actions up to BoardView
  • Ensure 100% compatibility with existing test suites
