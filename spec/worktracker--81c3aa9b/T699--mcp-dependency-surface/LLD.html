Why this exists

The capability is built end-to-end — except the one surface an agent actually uses.

  • #670 — read-only GET /work-items/{id}/scope-context → depends_on / depended_by / owned_elsewhere / advisory.

The gap (this ticket)

  • WRITE Three tool methods drafted in tools.py/service.py but uncommitted, untested, not deployed — the running MCP is stale, so no register surface is visible.

Tool contracts

Five tools total: three write (drafted), two read (one new field, one new tool). All accept UUID or KEY-N.

ToolKindSignature → returnsSemantics
set_task_blockerswrite(task_id, blocked_by_ids[]) → {task_id, blocked_by_ids, blocks_ids}Replace-set. [] clears all.
add_task_blockerwrite(task_id, blocker_task_id) → edgesAdditive. task_id becomes blocked by blocker. Idempotent.
add_task_dependentwrite(task_id, dependent_task_id) → edgesReverse sugar: dependent depends on task_id (= add_task_blocker swapped).
get_task_detailsread(id_or_key) → +blocked_by_ids +blocks_idsNew fields on the schema; reveals existing edges.
get_task_scope_contextread(id_or_key) → {depends_on, depended_by, owned_elsewhere, advisory}Thin wrapper over #670 endpoint. Read-only.

Error contract: self-block and cycle attempts surface the backend 4xx as a structured, agent-readable error result — never a raw stack trace; no partial write.

Test intentions

New test_dependency_tools.py against a mocked service / live backend.

Write

  • add_task_blocker is additive & idempotent (re-adding a blocker is a no-op).
  • set_task_blockers([]) clears; non-empty replaces.
  • add_task_dependent equals add_task_blocker with args swapped.
  • KEY-N resolves to UUID on both ends.
  • Shape asymmetry: GET reads ["task"], PATCH reads the bare body — a regression here is the most likely break.
  • Self-block + cycle → clean error result, zero writes.

Read

  • get_task_details surfaces blocked_by_ids/blocks_ids.
  • get_task_scope_context returns all four keys; matches #670 payload.
  • Read tools never mutate; no migration introduced.

Acceptance signal

  1. Through the live MCP, an agent registers a dependency three ways (UUID or KEY-N); the edge shows in Studio.
  2. Self-block / cycle → clean agent-readable error, no edge written.
  3. get_task_details returns the edge id arrays; scope-context tool returns depends_on / depended_by / owned_elsewhere / advisory.
  4. Full test suite green; draft folded in, committed, deployed.
