The two closes

Click a card to expand its design decisions.

B1 · G07 · READ-ONLY

Expose timestamps

Add created_at + updated_at to the out-schema chain; render an absolute Created / Updated row in the drawer.

  • WorkItemOut: created_at: datetime, updated_at: datetime — no defaults (always present)
  • Co-ship SDK WorkItem (extra="forbid" forces it) + FE WorkItem (string)
  • Drawer metadata row: absolute date format; relative ("2d ago") is optional polish only
  • No column change, no migration — auto_now/auto_now_add already populate them
  • No timestamps on SprintOut (out of charter) — only the work item
B2 · G06 · NAME-BASED

Editable labels

A typeable tag editor backed by a name replace-set with get_or_create — Jira free-tag semantics, self-contained.

  • WorkItemPatch.labels: Optional[List[str]] — absent = no-op (exclude_unset), [] = clear all
  • Per name: Label.objects.get_or_create(project=issue.project, name=name) → issue.labels.set([...]) post-save
  • Normalize: trim, drop empty + duplicates; case-sensitive exact match ("Backend" ≠ "backend"); cap 255
  • LabelOut.color exposed read-only; new name-created labels start blank → neutral chip
  • Orphaned labels left in table (cheap, fuel autocomplete); no cleanup, no label-CRUD endpoint, no id in the contract

Label write — one round-trip

The editable-label path mirrors the proven blocker replace-set: optimistic chip, single PATCH, server normalizes + get-or-creates, rollback on error. Click a step.

  1. 1
    User types a name + Enter (or × removes a chip) in LabelPicker
  2. 2
    patchLabels(nextNames) — optimistic chip update via patchField({ labels })
  3. 3
    PATCH /work-items/{id} with { labels: [...] }; handler normalizes (trim / dedupe / drop-empty)
  4. 4
    Per name → get_or_create(project, name); then issue.labels.set([...]) post-save
  5. 5
    Re-resolved WorkItemOut.labels (now with color) returns; FE reconciles, or rolls back on error

Decisions (resolved)

All three were settled during refinement; restated here so the LLD inherits them.

1 · Write model → name-based get-or-create

A replace-set of label names, not ids — no separate label list/create endpoint. Smallest usable path; matches Jira free-tag semantics; fully self-contained in patch_work_item. Mirrors blocked_by_ids exactly (api.py:634–640).

2 · Chip color → expose Label.color read-only

The model already has color (models.py:188). LabelOut projects it; FE renders it with a neutral fallback when blank. Name-created labels start blank → neutral. No color-picker UI this slice.

3 · LabelOut shape = { name, color }, NO id

The write path is fully name-based, and optimistic chips have no server id until the patch returns — so the FE keys chips by name in both optimistic and server state. Names are unique per project (enforced by get_or_create), making name the single consistent key. Adding id would be a field the FE never keys on. Co-ship: SDK Label + FE Label = { name, color }.

Acceptance signal

  • The drawer shows a Created and Updated date for every issue; updated_at advances after any edit.
  • Typing a label name + Enter adds a chip and persists it; the same name reused on another issue resolves to the same Label row (get-or-create), not a duplicate.
  • PATCH { labels: [] } clears all labels; an absent labels field leaves them untouched.
  • Label names are trimmed, de-duplicated, empty-dropped, and matched case-sensitively; "Backend" and "backend" are distinct.
  • Chips render their color; blank-color (name-created) labels show a neutral chip.
  • BE + SDK + FE suites + tsc + build all green. No migration. extra="forbid" SDK round-trip passes.

Attachment upload (B3/C9) and comments/activity (B4/G08) stay as separate follow-ups per the #630 charter. No label-CRUD UI, no label id in any contract.
