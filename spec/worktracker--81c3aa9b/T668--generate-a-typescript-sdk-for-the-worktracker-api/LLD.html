OpenAPI Generator · typescript-fetch

  • Pin CLI wrapper 2.39.0 and generator 7.23.0.
  • Generates Fetch endpoint classes and TypeScript models for browser and modern Node.
  • Matches the accepted committed-code, replace-only package boundary.
  • Does not own API keys, product errors, environment lookup, or Studio compatibility.

Contract decisions

Field names and behavior are fixed here; implementation syntax is intentionally omitted.

OpenAPI normalization

Operation identityExplicit unique operation ids; stable resource tags for Projects, Modules, Sprints, WorkItems, Attachments, IssueTypes, and States.
Path rootGenerated operation paths stay API-root-relative, such as /projects. The configured base URL owns /api/work-tracker, preventing duplicated path segments.
SecurityRouter-level x-api-key scheme referenced by every supported operation.
ResponsesActual success model plus applicable 401/404/409/422 shapes. Deletes stay bodyless 204 responses.
PATCH nullabilityOptional property means “leave unchanged”; explicit null remains available for relation clears.
MultipartAttachment upload remains one required binary file part under multipart/form-data.

SDK runtime

ConfigurationBase URL, optional API key, optional Fetch implementation, default headers, and per-call AbortSignal.
ErrorsWorkTrackerApiError retains status, message, full body, headers, and Ninja validation details.
BoundariesNo retry, cache, hooks, state management, telemetry, registry release, or Node Fetch polyfill.
Generated filesCommitted, replace-only, generated notice on every file; no manual edits.

Studio compatibility

api.tsExisting named functions and parameters stay stable; each delegates to the generated operation.
types.tsAPI-owned interfaces become generated aliases/re-exports; only UI-only types remain local.
ApiErrorCompatibility class remains available with today’s status/message/body behavior.
Call sitesNo broad store or component rewrite.

Validation layers

Each layer proves one boundary; no single snapshot test substitutes for behavior.
BackendSchema metadata, deterministic bytes, security, operation ids, errors, nullable PATCH, multipart, and 204.
TypeScript SDKExact URL/header/method/body, query encoding, FormData, AbortSignal, 204, and stable error mapping with stub Fetch.
Studio adapterExisting exported functions, defaults, ApiError compatibility, and unchanged caller behavior.
Full gateBackend + Python SDK + TypeScript SDK + Studio tests/typecheck/build; drift check runs first.

Build order

Six independently verifiable steps; implementation begins only after this LLD is accepted and the WorkTracker item moves to LLD.
1ExportBuilder, command, deterministic tests.
2NormalizeIDs, tags, security, responses, nullable and multipart shapes.
3GenerateWorkspace, pinned CLI/config, committed Fetch output.
4WrapBase URL, API key, abort, stable errors, README.
5AdaptStudio api/types behind unchanged facade.
6GateDrift CI and all four validation surfaces.
Acceptance signal: one deterministic export recreates openapi.json; one pinned command recreates the committed Fetch SDK; Studio consumes it behind the unchanged facade; drift fails CI; all backend, Python SDK, TypeScript SDK, and Studio checks remain green.
