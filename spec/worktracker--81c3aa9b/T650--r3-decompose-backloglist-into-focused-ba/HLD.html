Decomposition, in three pillars

Click a pillar to expand its details.
PILLAR 1 · COMPONENT EXTRACTION

Extract View Subcomponents

Move InlineCreateRow and Row components out of the monolithic file into domain-named presenters.

  • Create BacklogInlineCreate.tsx for name-only quick add
  • Create BacklogRow.tsx to handle recursive issue row rendering, selection clicks, and Pragmatic DnD hooks
  • Create BacklogGroupSection.tsx to handle rendering individual epic groups, bars, and action links
PILLAR 2 · SCOPED STATE LOCATION

Minimize State Distribution

Keep state at the lowest possible level. Leave list-global values (like collapse maps and selection maps) inside the orchestrator.

  • Keep `collapsed` and `collapsedRows` sets in the container as they drive `flattenVisible`
  • Keep `name` in `BacklogInlineCreate`
  • Keep DnD dragging indicators inside `BacklogRow`
PILLAR 3 · DIRECTORY STRUCTURE

Subfolder Scoping

Group all backlog list components together under a dedicated `views/backlog/` folder, matching the style of Sprints and StoryMap.

  • Create folder studio/src/views/backlog/
  • Move and update imports of BacklogList.tsx
  • Ensure external test suites still import `BacklogList` and `flattenVisible` cleanly

Question board

Open architectural/refactor details for the user.
OPEN · Q1

Should we move `flattenVisible` to `backlogStore.ts`?

Currently `flattenVisible` lives in `BacklogList.tsx`. The drawer navigation (#639) also imports it. Moving it to `backlogStore.ts` or keeping it exported from `views/backlog/BacklogList.tsx` is an open choice. Keep it in the view file to avoid unnecessary churn unless requested.

OPEN · Q2

Are prop-drilling collapse-toggle handlers acceptable?

We are drilling `collapsed` sets and toggle callbacks to group headers and row items. An alternative is lifting these to a shared store or React Context. To preserve the original implementation closely and prevent regressions, simple prop-drilling is recommended.
