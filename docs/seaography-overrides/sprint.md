## Sprint writes

- Generated capability attempted: Seaography create-one, create-batch, update, and delete for `worktracker_sprint`, with generated input skips for protected fields.
- Exact missing behavior: create must lock the Project, repair duplicate sequence ranks, and append a fractional rank in one transaction. Update must bind one Sprint, serialize lifecycle changes under the same Project lock, move an out-of-order start directly after history, and carry unfinished work atomically on completion.
- Why caller documents, column codecs, skips, guards, or filters are insufficient: they restrict submitted fields and row scope but cannot lock the Project, rebalance sibling ranks, allocate a sequence gap, or perform transactional carryover.
- Why constraints/defaults and entity hooks are insufficient: the rank depends on the locked project sequence. The foundation entity cannot depend on work-management's fractional-rank commands. A default cannot allocate from sibling rows or rebalance duplicate ranks.
- Pinned framework evidence: Seaography 2.0.0-rc.9 generated create has no surrounding transaction. The pinned seaolim `29f2417` generated create does open a transaction, but its `Serializer::validate_list` contract permits reads and amendments only, not persistence. Its `DefaultCreate` handle does not expose that transaction. Project locking and duplicate repair therefore require the restricted prepare hook, which runs before framework persistence inside the open transaction.
- Create-one safety: restricted `worktrackerSprintCreateOne` preserves the existing generated `data` input. The input contains only `projectId` and `name`; `EntityInputBuilder` generates it with protected-column skips. The domain prepare hook supplies the rank under the Project lock. The framework returns the authoritative full `WorktrackerSprint` entity, retaining the former Basic output's scalar fields and adding generated relations.
- Create-batch safety: private; no public batch caller or batch sequence allocation contract exists.
- Update safety: unrestricted generated update is private because optional filters permit many-row lifecycle changes and cannot enforce a single active sprint, ordered starts, or carryover. Restricted `update_sprint` requires one ID and permits only name, status, carryover destination, and suggestion-run changes.
- Delete safety: private; deleting sprint history has no approved public contract.
- Smallest custom seams: model-shaped create-one and update views implemented with seaolim's `register_restricted_model_mutation`, plus the approved `reorder_sprint(sprint_id, before_id?, after_id?)` domain operation returning the authoritative Sprint model. There is no general rank write or mirrored DTO.
- Transaction/domain modules: `sprint_create` prepares insertion; `sprint_sequence` owns rank allocation and duplicate repair; existing Sprint lifecycle commands own status validation and carryover. Seaolim owns insertion/update, commit, rollback, and observation.
- Protected fields excluded: `id`, `rank`, create status, suggestion-run identity, goals revision, and timestamps. Update cannot modify project ownership or rank.
- Drift/regression tests: `sprint_sequence_graphql` checks create append, readable/orderable protected rank, start position, completion with carryover, duplicate repair, and rollback through in-process GraphQL operations.
- Reorder safety: planned sprints move only into a concrete adjacent sequence gap after completed and active history, under the Project lock. Generated model CRUD cannot validate that ordered gap. Same-slot requests return unchanged without allocating a revision or publishing a fact, rolling back any tentative duplicate-rank repairs; successful moves allocate a fractional rank, bump the project revision, and append a durable `sprint.changed` fact in the transaction.
- Reorder regression tests: `sprint_reorder_graphql` exercises moves, invalid neighbors and history positions, same-slot no-ops, revisions, durable facts, and rollback through the public GraphQL operation. Studio acceptance covers controls, mutation failures, and cache convergence.
- Registry entry: `reorder_sprint`, with its ordered-gap reason; create and update remain model CRUD.
