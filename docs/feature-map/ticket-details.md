# Ticket details

The selected work item's Details surface connects its identity, editable fields, hierarchy, dependencies, attachments and destructive actions to the authoritative WorkItem record.

Surfaces: browser, desktop
Editions: pocock, core

## Sub-features

- `details-identifier-name`: Breadcrumb identifier and inline name editing.
- `details-type-state`: Task-level issue type and configured workflow destinations.
- `details-parent-breadcrumb`: Parent selection, project/module scope links and ancestry.
- `details-child-issues`: Child navigation and inline typed child creation.
- `details-blockers`: Navigable Blocked by/Blocks chips, add and remove.
- `details-attachments`: Existing attachment links, filenames, sizes and counts.
- `details-delete`: Confirmed leaf deletion and cancellation.
- `details-status-parent-modals`: Reachable Set Status command and retained Set Parent/Set Module dialogs with no current production opener.

- `details-archive-contract`: Public identity-bound archive patch cascades through descendants, rejects restoration and accepts repeat archive requests.

## How to get to it

- Open a module through its tab or [Module Manager](module-manager.md), select a Stories treeitem, then select the workspace tab by role **tab**, accessible name **Details** (the shared tab strip is `workspace-tabs`). The content region is named **Details**. Selection renders cached records before the post-paint refresh; no linked folder or agent launch is needed to edit fields.
- Click `issue-name` to edit the **Name** textbox; Enter or blur commits, Escape abandons the draft. Use the current type button inside `issue-type-picker`, the current state button inside `state-picker`, and the parent-name button inside `parent-picker`. The latter is in the **Breadcrumb** navigation, alongside project/module buttons and `issue-identifier`.
- Use **Add blocker** in `blocker-picker`; search by number, key or name. Navigate through a blocker identifier or a child button in `child-issues`. Choose **Child issue type** (`add-subtask-type`), fill **Add sub-task…** (`add-subtask`) and press Enter. Existing attachments are filename links; there is no upload control in this Details component.
- Open **Issue actions** (`issue-actions-trigger`) → **Delete issue…** (`delete-issue`); the **Delete issue** dialog has **Delete** and **Cancel** buttons. It is disabled while the item has children.
- With a real item selected and focus outside text editing, keymap action `status` defaults to **s** and opens **Set Status**. Modal actions `modal.previous`/`modal.next` default to Up/Down, `modal.confirm` to Enter and `modal.close` to Escape. The retained parent-update modal renders **Set Parent** or **Set Module**, with **Filter tasks…**/**Filter modules…** inputs and these same modal chords, but no current production caller or default opening chord was found. Reachable reparenting uses the breadcrumb picker. Keymap defaults and routing: `studio/src/app/navigation/keymapBindings.ts`, `studio/src/app/navigation/sharedNavigation.ts`.

## Prerequisites

Use the index's disposable browser/desktop profile, a selected project/module and a persisted work item. Issue types, states and workflow transitions come from that project's catalogue. Child creation needs a task-level type; blocker and parent choices depend on loaded project items. Attachment rendering needs existing server attachment records. Use a leaf for delete success and a parent with children for the disabled path. Review findings and descriptions have their own Work items entries in the index.

## Expected behavior

- Identity is formatted as `T-<sequence_id>`; absent sequence IDs omit the identifier rather than inventing one. Inline name editing trims nonblank changes; unchanged/blank drafts request no rename, and Escape restores the name. Successful type changes use task-level types only and repaint the normalized record. An empty type catalogue says **No task issue types.** Sources: `studio/src/features/work-items/displayIdentifier.ts`, `studio/src/app/shell/ticket-workspace/selected-ticket/details/NameEditor.tsx` and the Details field components.
- The state picker marks the current step, shows workflow order, enables only outgoing configured destinations, and displays other track states as context. Permitted off-track destinations appear after a divider; no track/options says **No permitted transitions**. Set Status instead lists all nonsynthetic catalogue states and relies on the server to accept/refuse the transition. It closes after success, shows **Saving…** while pending and retains the dialog on refusal. No states says **No states available**. Escape cancels without a write. Source: `studio/src/app/shell/ticket-workspace/selected-ticket/details/WorkflowStatePicker.tsx` and `studio/src/features/studio/modals/StatusUpdate.tsx`.
- The breadcrumb parent's picker excludes self and descendants, offers modules/tasks and a **No parent** clear choice. Search has **No eligible issues.**/**No matches.** empty paths. Project breadcrumb clicks clear the epic filter; the module segment, shown for nested task parents, scopes it to that module. Reparent writes refresh source/destination membership. Retained parent dialogs filter candidates, close without a write for the already-current parent, stay open with a toast on failure and show **No candidate parents**/**No modules available** when empty. Their task mode excludes self but does not implement the breadcrumb's descendant filter; server validation remains necessary.
- Child buttons select the canonical child identity. No children says **No sub-tasks yet.** Enter requests creation only with a nonblank name and chosen type, under the displayed parent, then clears the input; a refused create shows a toast rather than retaining that name. Source: `studio/src/app/shell/ticket-workspace/selected-ticket/details/ChildIssues.tsx` and `studio/src/app/shell/ticket-workspace/selected-ticket/details/IssueDetail.tsx`.
- Add blocker excludes self, existing blockers and cycle-closing candidates; **Remove blocker** replaces the blocker set without that edge. Chips navigate by identity, loaded tasks outside resolved state groups show `data-warn="true"`, and inverse **Blocks** is hidden when empty. Writes travel through restricted `update_work_item`; rename/details cannot be combined with state, parent or blocker domain patches. Backend cycle/workflow guards still apply to externally authored writes. Source: `studio/src/app/shell/ticket-workspace/selected-ticket/details/fields/BlockerPicker.tsx`, `studio/src/app/shell/ticket-workspace/selected-ticket/details/BlockerChipView.tsx` and the contract specs below.
- Attachments appear only when nonempty: `attachments` contains a count and `attachment-row` filename links with formatted sizes, opening their URLs in a new browsing context. They come from the attachment subcollection, not inline WorkItem fields. Source: `studio/src/app/shell/ticket-workspace/selected-ticket/details/Attachments.tsx` and `studio/src/features/work-items/queries/useWorkItemAttachments.ts`.
- Delete asks for confirmation naming the item; Cancel requests no deletion. With children, the menu is disabled and titled **Remove sub-tasks first**. Success evicts the known Apollo identity and refreshes module membership. Delete failure feedback is not established by the Details handler (see Gotchas). Source: `studio/src/app/shell/ticket-workspace/selected-ticket/details/IssueActionsMenu.tsx`, `studio/src/app/shell/ticket-workspace/selected-ticket/details/IssueDetail.tsx` and `studio/src/features/work-items/mutationTransport.ts`.
- Subtree run actions depend on the edition (CODING-2865). For a branch item (one with children), Pocock's Details toolbar shows only **Run subtree serially**, which carries the `normal-run-command` (Cmd+Enter) chord and starts the serial campaign. Every Pocock Graph Run press sends `serial`. Core shows both **Run subtree** and **Run subtree serially**; in core Cmd+Enter keeps starting the parallel **Run subtree**. While a subtree run is active, both editions replace the buttons with the lifecycle badge and **Open subtree run**. The server enforces the same rule: a Pocock request for `parallel` is refused with `edition_capability_unavailable`. See [Dependency-graph runs](dependency-graph-runs.md).
- Persistence means a server round trip: read the same identity's name/type/state/parent/blocker fields and attachment subcollection after the mutation, reload, reselect and verify them again. Reparent also checks both modules' membership and the child's parent; blocker changes check both edge directions; confirmed deletion checks the identity is absent, while cancelled deletion still resolves. Optimistic repaint alone is insufficient. Existing tests below establish parts of this through fixture reads or historical real-server reloads; this map did not execute a live walkthrough.

## Gotchas

- CODING-2759 fixed a browser Name-editor focus defect: a single click opened the Name input, then Details surface engagement blurred it and the editor closed. Surface engagement now leaves focus with a text editor already focused inside Details (`studio/src/features/task-workspace/internal/useTaskWorkspace.ts`); `overhaul-822` in `studio/src/test/overhaulTaskWorkspaceSurfaceFocusAcceptance.test.tsx` covers it. Settled-page DOM focus/mutation evidence for the original defect is retained under runner run `2026-10-10T16-46-48-495Z-76f12733`; the migrated cases retain their original assertions.
- `overhaul-web-14` passes (CODING-2760): a canonical WorkItem read that fails while the browser is offline stays owed by the status feed's WorkItem invalidator and is retried at the reconnect's caught-up boundary, so the visible row converges to the renamed record without a reload. Focused run on 2026-10-11 passed; run `2026-10-10T16-51-27-179Z-240ab9d2` records the original failure. Vitest guard: `studio/src/test/overhaulOfflineEditGapAcceptance.test.tsx`.
- Playwright `studio/e2e/support.ts` `openModule` waits only for the selected module tab and module workspace region (CODING-2847); onboarding setup also uses removed module-entry controls. The current Module Manager replaced that pane. The cited browser tests are existing coverage descriptions, not successful runs during this docs campaign. A setup timeout is a blocker before behavioral assertions, not evidence the details behavior failed.
- The status picker and Set Status modal have different candidate policies; the modal's catalogue listing is not permission to bypass server workflow gates. Custom keymap overrides replace defaults, and text editing/modal focus changes routing. Set Status refuses a commit if project/task selection changed after opening.
- No production `parent-update` opener was found in the current source; internal modal registration and a test-pushed dialog do not create a user entry point. Do not invent a parent shortcut. Parent dialog success/cancel/empty behavior is source-grounded but production reachability remains unverified.
- `IssueDetail.tsx` currently synthesizes `taskQuery.error` as undefined; its `issue-not-found`/`issue-load-error` branches are not established reachable error UI. Attachment data defaults to an empty array without rendering the hook's error. Visible missing/read-error recovery remains unverified. No task selected explicitly renders **No task selected**; a missing record after loading may render no Details content.
- The delete promise is not caught in `IssueActionsMenu.tsx`/`IssueDetail.tsx`; no reliable user-visible delete refusal feedback is claimed. Do not infer it from the generic field-mutation toast path. Child creation clears its draft before the server answers; do not claim failed-entry retention.
- A source path proves how a behavior is implemented, not that it ran. Full real-server reload/restart coverage and native-desktop proof remain separate from fixture acceptance and schema introspection.
