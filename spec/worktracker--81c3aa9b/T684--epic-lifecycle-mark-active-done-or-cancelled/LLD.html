Epic Lifecycle — reuse the epic's workflow state; hide closed epics, backend-owned

Epics are Issue rows with type="module" that already carry a state FK. This slice gives an epic the same full state picker as any issue, hides closed epics (completed/cancelled group) from active surfaces by default in list_modules, and exposes one per-project "show closed" toggle. Cancel reuses the #633 cascade behind a confirmation. No new field, no migration.

Implementation harness

Three seams, in dependency order. Each later seam depends only on the one before it; the five active surfaces need almost no per-surface code because hiding is centralized.

SEAM ABackend owns visibility & exposes epic stateworktracker/
  • ModuleOut gains a nested state so every consumer can read the epic's group.
  • list_modules hides closed epics by default and accepts one include_closed switch.
  • Marking is the existing PATCH /work-items/{id} with state_id — no new endpoint. The cancel cascade already lives there (#633) and fires for module-type issues unchanged.
SEAM BRegenerate the typed SDK from OpenAPIworktracker-typescript-sdk/
  • Picks up ModuleOut.state and the renamed includeClosed query param so the Studio types flow through automatically (Module = ModuleOut).
SEAM CStudio: one toggle, one mark action, surfaces inheritstudio/src/
  • studioStore holds a persisted per-project includeClosedEpics flag and passes it on every modules fetch; all five surfaces read modules and inherit hiding for free.
  • EpicRail renders a state pill, mounts the existing StatePicker as a mark action, gates cancel behind a confirm, dims closed rows, and hosts the toggle.
  • ParentPicker always filters closed epics out regardless of the toggle.
Why no migration. Epic lifecycle is the module issue's existing workflow-state group. "Closed" = completed or cancelled. The HLD's "1 migration" chip and the dedicated-lifecycle-enum alternative are dropped.

Backend steps

All in worktracker/worktracker/. Click a step to expand its decisions.

B1Expose epic state on ModuleOutschemas.py
  • Add state: Optional[StateOut] = None to ModuleOut (the StateOut schema already exists and carries id/name/group/color/sort_order).
  • Nullable: new epics start with NULL state, so the field is optional and serializes null.
  • No change to ModuleIn/ModulePatch — marking goes through the work-item patch, not the module patch.
B2Default-hide closed epics in list_modulesapi.py
  • Rename the query param include_archived → include_closed (default False); update the docstring.
  • Default (include_closed=False): exclude rows where is_archived=True (cancelled, via #633) and exclude rows where state.group == "completed" (done — the genuinely new behavior; done epics are not archived).
  • include_closed=True: apply no exclusion — return active, done, and cancelled epics alike.
  • Add "state" to the existing select_related(...) so the nested StateOut serializes without an N+1.
  • Leave create_module untouched (NULL state default); a NULL group is not closed, so new epics are visible.
  • Scope guard: only the modules-list endpoint changes. list_module_work_items and list_tasks keep their own include_archived params.
B3Confirm marking reuses the existing patch pathapi.py (read-only)
  • PATCH /work-items/{id} already accepts state_id for any issue by id, including type="module" — no new route, no branching on type.
  • The active→cancelled transition already sets is_archived=True and calls _cascade_archive; marking an epic done (completed group) does not flip is_archived, so done epics are hidden by group, not by archive.
  • Do not add module-specific cancel logic — the generic transition is the single source of truth.

Studio steps

All in studio/src/. The store change carries the toggle; surfaces mostly inherit.

C1Persisted per-project "show closed" flagstores/studio/studioStore.ts
  • Add includeClosedEpics: boolean to state and a setIncludeClosedEpics(value) action.
  • Persist per project in localStorage under a dedicated key prefix (mirrors planningFilterStore's per-project key idiom); a missing/invalid value reads as false.
  • selectProject loads the persisted flag for the project before fetching, and passes it to listModules.
  • setIncludeClosedEpics persists, then re-fetches modules for the current project with the new flag and replaces the list.
C2Thread the flag through the API bindinglib/api.ts
  • listModules(projectId, includeClosed = false) forwards includeClosed to sdk().modules.listModules(...).
C3Mark-epic action + refreshstores/studio/studioStore.ts
  • Add setEpicState(epicId, stateId): calls api.patchWorkItem(epicId, { state_id }).
  • On success, re-fetch modules with the current includeClosedEpics flag (the epic may now be hidden) and trigger the backlog reload (a cancel cascade may have archived child tasks).
  • Failure surfaces via the existing toast.error path; the list is left as-is.
  • Do not optimistically mutate the module's group client-side — the backend decides visibility.
C4Closed-epic helperlib/display.ts
  • Add isClosedEpic(module) → true when module.state.group is completed or cancelled (NULL/active → false). Reuse the existing resolved-group set already defined for blockers.
  • Used by the rail (subdued styling) and the parent picker (hard exclusion).
C5EpicRail: state pill, mark action, cancel confirm, dim, toggleviews/EpicRail.tsx
  • Each entry shows a state pill (color/label via stateColor/stateLabel from epic.state); a NULL state renders a neutral "no state" pill.
  • Mount the existing StatePicker as a per-epic mark control, wired to setEpicState. It is a distinct control inside the entry so it never triggers the row's filter-toggle click.
  • Cancel gate: when the picked state's group is cancelled and the epic is not already cancelled, first await dialog.confirm({ danger: true, ... }) whose message states how many child stories/sub-tasks will be archived (descendant count walked from the backlog items); proceed only on confirm.
  • When the toggle is on, closed epics render with subdued styling (reduced opacity); when off they are absent from modules entirely.
  • Host the per-project "Show closed epics" toggle in the rail header, bound to includeClosedEpics/setIncludeClosedEpics (global state — flipping it updates board, map, and filter together).
C6ParentPicker: always exclude closed epicsfields/ParentPicker.tsx
  • Filter the epic candidate list with !isClosedEpic(m) regardless of the toggle — you cannot file new work under a closed initiative.
  • If the issue being edited already points at a now-closed epic, keep showing that current value's label, but never offer closed epics as new options.
C7Inheriting surfaces — verify, light styling onlyEpicsFilterDropdown · BoardSwimlane · StoryMap
  • EpicsFilterDropdown, BoardSwimlane (lanes), and StoryMap (columns) all read useStudioStore(s => s.modules) and inherit hiding with zero logic change.
  • Optional: subdued styling on closed rows in the dropdown when the toggle is on, for parity with the rail.
  • Reconcile is already wired: StoryMap/BoardView call planningFilterStore.reconcile({ moduleIds: modules.map(...) }), so a now-hidden epic auto-prunes from epicIds (decision #8).

Acceptance signal

  • An epic can be marked to any project state via the same picker as any issue; lifecycle is the chosen state's group.
  • Done (completed) and cancelled epics disappear from the rail, swimlanes, story-map columns, and the epics filter by default.
  • One per-project "show closed epics" toggle reveals them together, subdued, persisted in localStorage.
  • Cancelling an epic archives it and cascade-archives its task descendants, gated by a confirmation that states the child count; marking done does not cascade.
  • The parent picker never offers a closed epic, regardless of the toggle.
  • No new lifecycle column or migration; ModuleOut.state + include_closed are the only contract changes; backend & Studio tests cover visibility and cascade.
