# Ticketry app-server schema explorer

## Product

A local developer explorer for the TypeScript contract generated by `codex app-server generate-ts`. It helps someone understand hundreds of request, response, notification, event, and supporting types without reading files one by one.

The core job is orientation. The explorer must answer: what messages exist, who sends them, how the domains group together, which parameter and response types belong to a method, and where one type references another.

## Information architecture

- A compact header names the artifact, generation status, and schema count.
- A left navigation rail groups the protocol into Overview, Requests, Server requests, Notifications, and Types. Domain filters such as threads, turns, apps, plugins, MCP, filesystem, accounts, config, commands, permissions, and models sit below.
- The central pane is the working list or protocol map. Search and small filters stay fixed at its top.
- The right inspector shows the selected method or type, its direction, fields, referenced types, source path, and readable TypeScript.
- Overview uses an understandable message-flow diagram: Client → Request → Codex app-server → Response, with server requests and notifications returning to the client.
- Keyboard interaction is visible, not hidden. `/` focuses search, arrow keys move selection, and Enter opens a type.

## Visual system

Use Ticketry's existing dark workbench language.

- Background `#0a0a0a`, panels `#111317`, borders `#2a2f3a`, title strips `#1f2530`.
- Primary text `#d6deeb`, secondary `#9aa5b8`, muted `#7a8599`.
- Blue focus `#7aa2f7`, cyan active `#7dcfff`, green response/success `#9ece6a`, amber server request `#e0af68`, pink notification `#f7768e`.
- Hanken Grotesk for explanation and labels. JetBrains Mono for method names, paths, field names, counts, and code.
- All corners are square. No gradients, glass effects, floating cards, oversized hero text, decorative illustration, or marketing copy.
- Dense but readable. Prefer aligned rows, thin rules, subtle selected fills, and a clear two-font hierarchy.
- Use tiny directional markers and restrained color coding. Never rely on color alone, include a label or icon.
- Animate selection and pane changes in 150–220ms. No ambient animation.

## Responsive behavior

The primary target is a 1440×900 desktop window. At narrower widths, collapse the left rail to icons and let the right inspector open as an overlay. Preserve search and the method list.

## Content rules

Use real generated names and methods. Helpful examples include `thread/start`, `turn/start`, `app/list`, `plugin/install`, `mcpServer/tool/call`, `command/exec`, `ClientRequest`, `ServerRequest`, `ServerNotification`, and `ThreadStartParams`. Do not invent capabilities. Keep explanations short and factual.
