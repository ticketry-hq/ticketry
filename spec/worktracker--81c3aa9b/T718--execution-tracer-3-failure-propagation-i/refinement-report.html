Hard question answered

What exactly counts as failure before durable lifecycle states exist?

Two signals only: run_failed from launch failure, and a running node's task moving into the cancelled state group. The stall case is any run ending without the task reaching the phase completion gate; it does not release dependents and must be logged/observable.

Clarified Decisions

These decisions are stable enough for LLD without reopening Backlog refinement.

DecisionRequirement
Status vocabularyGraph node status becomes idle | running | done | failed | halted. halted is terminal for this invocation and never enters the ready-set.
Failure propagationWhen a node becomes failed, decide_graph marks every still-idle transitive dependent halted. Running/done/failed nodes are not rewritten.
Independent branchesBranches not descending from the failed node continue to launch and complete using CODIN-717 ready-set rules.
Failure signalsSupport run_failed and running task move to cancelled group. Durable lifecycle-state failure semantics remain deferred to CODIN-744.
Stall semanticsIf a run ends without the issue reaching the phase completion gate, keep the node not-done, do not release dependents, and log/surface it. Do not silently mark done.
Durable idempotencyNo new model. Seed done from tracker completed group; adopt the newest live AgentRun with status="running" for the task as running; launch only idle ready nodes with no live run.
Restart recoveryAfter clear_registry() or process restart, execute_graph rebuilds graph state from DB facts and resumes without duplicate launches.
