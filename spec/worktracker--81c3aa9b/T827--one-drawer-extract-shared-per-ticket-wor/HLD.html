The host ⇄ workspace interface

Three parts. Hosts stay distinct surfaces (foreground arbitration per CODIN-749 is untouched); the workspace is one implementation behind one prop contract.
COMPONENT · what hosts mount

<TicketWorkspace> in issue/

Props: bucket (ticket id; /coding may pass the scratch sentinel), owner ("drawer" | "coding") for terminal foreground identity, and the slot set. Tab strip, Details, Doc tabs, Terminal tabs — Studio's implementation, one copy.

Takes a ticket id as props — mounted by both hosts
STORE · one per-ticket state

workspaceStore promoted

coding/stores/workspaceStore (docs, active tab, overlay flags, run history — keyed by bucket) moves to issue/internal/workspaceStore. issue/internal/drawerWorkspaceStore (the mirror) is deleted. Terminal tabs remain derived from terminal/'s session store, as today.

Open a doc tab in /coding → the drawer shows it, and vice versa
OVERLAY · one wiring point

Coding slot pack

The workspace defines named slots (details-extra, doc-tab actions, terminal extras, launch panel). The concrete coding components (WorktreeBlock, doc-agent overlay, resumable rows, agent launch) stay in coding/; a single wiring module supplies the same slot set to both hosts, so both surfaces look identical.

Drawer host's import of the pack = one inventoried SHARED-FILE hunk

The refactor, in three pillars

Click a pillar to expand its boundary.
PILLAR 1 · D1 STUDIO WINS · the component

Shared workspace component

Studio's IssueDrawerTabs + drawer content host become issue/'s exported <TicketWorkspace>; coding's TicketWorkspace.tsx becomes a thin host.

  • Tab strip: pinned Details, closable Doc + Terminal tabs, lifecycle badges — from the drawer implementation
  • Details content = IssueDetail, identical on both surfaces
  • coding's tab strip, tabs/DetailsTab, tabs/DocTab deleted
  • Host chrome (drawer resize, keyboard nav, /coding pane layout) stays per-host
PILLAR 2 · D5 STORE PROMOTION

One tab-state store

workspaceStore moves under issue/internal/; the drawer's mirror store is deleted. State was already shared underneath — now it is shared by construction.

  • Keyed by bucket (ticket id, or scratch sentinel from /coding only)
  • Docs, active tab, overlay flags, closed-run history — one record per ticket
  • issue/internal/drawerWorkspaceStore deleted (hydrate/resolve logic folds into the component)
  • Both stores are in-memory today → no persisted-state migration story needed
PILLAR 3 · D2 CONVERGE + D4 SLOTS

Full parity via slot pack

Both surfaces get everything: drawer gains doc-agent overlay, resumable terminal rows, WorktreeBlock; /coding gains the agent launch panel.

  • Slot pack module in coding/ exports the one slot set; both hosts pass it
  • Scratch-bucket docs stay /coding-only (no ticket id → drawer never sees the sentinel)
  • OWNERSHIP.md: drawer-host slot import recorded as SHARED-FILE hunk; boundary grep stays clean in CORE files
  • Drawer tests pinning "read-only docs / no edit-with-agent" are rewritten to pin the converged behavior

Question board

Green = answered during refinement. Red = deliberately deferred to LLD/implementation — none gates the design.
ANSWERED · scope

Whole workspace or Details only?

Whole workspace. The shared module is the tab strip + store + all tab content; sharing only Details would leave the duplication the ticket exists to remove.

D1
ANSWERED · parity direction

Converge features or slot-gate per surface?

Converge. "Both look the same" is the requirement. Drawer doc tabs stop being read-only; the drawer tests pinning that (IssueDrawerDocTabs) get rewritten, not preserved.

D2
ANSWERED · store migration

What is the persisted-state migration story?

There isn't one — by inspection. Neither store touches browser storage; the drawer store already delegates to coding's. Promotion + delete, no data migration.

D5 · codex divergence map
ANSWERED · overlay boundary

How do coding features enter a CORE module?

They don't — their render slots do. Slot contract in issue/, implementations in coding/, one wiring module, one inventoried SHARED hunk in the drawer host. Boundary grep stays clean.

D4 · OWNERSHIP.md
DEFERRED · LLD

Exact slot names + prop types

LLD scope. Candidate set: detailsExtra, docTabActions, terminalListExtras, launchPanel. Sized against the four coding features plus the drawer launch panel.

DEFERRED · LLD

Test rewrite inventory

LLD scope. Known casualties of convergence: IssueDrawerDocTabs (read-only pins), IssueDrawerWorkspace, TicketWorkspace; arbitration suites (terminalForegroundArbitration, drawerTerminalPresentedElsewhere) must pass unmodified.

Acceptance signal

The refactor is done when one workspace implementation exists (issue/'s <TicketWorkspace>, mounted by both the Studio drawer and /coding), the duplicated tab strip / DetailsTab / DocTab and the drawerWorkspaceStore mirror are deleted, and opening a doc or terminal tab on either surface shows the same tabs on the other. Both surfaces render the full converged feature set (doc-agent overlay, resumable rows, WorktreeBlock, launch panel) with identical Details display. The arbitration suites pass unmodified (terminalForegroundArbitration, drawerTerminalPresentedElsewhere), rewritten workspace suites are green, and the overlay boundary grep stays clean with OWNERSHIP.md updated for the single drawer-host slot hunk.
