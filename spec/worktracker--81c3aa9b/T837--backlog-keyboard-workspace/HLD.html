The keymap

One glance = the whole interaction contract. No pane-focus model: the list owns every key below except while browser focus sits in an input/textarea/contentEditable.
↑↓jk

Cursor = selection

Moves across stories and group headers. The right pane tracks the cursored story live — no confirm step.

→l

Expand

On a group header or parent with children: expand. Already expanded: step into the first child.

←h

Collapse, else epic picker

Expanded header/parent: collapse. Otherwise ← falls through and summons the epic-picker modal.

SpaceEnter

Picker: toggle · commit

Inside the picker only. Enter applies the epic set to the shared filter and clears any story selection. Enter never selects a story, anywhere.

Esc

Deselect

Clears the selection; the right pane falls back to its empty/create state. In the picker: cancel without applying.

NI

Quick-create

The Board's #686 chord, extended to the Backlog: deselects, then hands the right pane to the create surface.

s

Status (the one mutation)

Opens status change for the cursored story — the single coding-inherited mutation key in v1.

⌘ctrlalt

Never hijacked

Modifier-held keys and typing targets always pass through — #642's guard, kept verbatim.

The three-way contract: list ⇄ workspace pane ⇄ epic picker

Each surface has one owner and one write path. The picker writes only filter state; the pane writes only issue fields; the list writes only the cursor.
LIST · owns the cursor

Grouped rows, headers included

The visible-row order (epic tree or status sections, #828) is the single traversal sequence. Group headers are first-class cursor rows: expand/collapse with →/←, never draggable. DnD reorder stays exactly as shipped in #778.

Cursor state is the only selection — no second highlight concept
WORKSPACE PANE · owns mutations

IssueDetail, or create

Selected: the self-loading <IssueDetail issueId> from #827 — same component the drawer renders, zero forked detail code. Nothing selected: an empty-state panel hosting the quick-create surface. Mouse-first inside the pane by design (v1).

The pane never handles list keys; the list never edits fields
EPIC PICKER · owns nothing

A keyboard face on #833

Summoned by ←, rendered as a modal/dropdown. Space toggles epics, Enter commits, Esc cancels. It reads and writes the existing shared planning-axes epic selection — the same state the FilterBar, Board, and Story Map already share. No new filter semantics.

Commit = apply filter + clear story selection · no standing rail

Question board

Green = answered in the requirements interview. Red = genuinely open — all four are LLD scope, none reopens a decision above.
ANSWERED · selection model

Highlight-then-Enter, or cursor = selection?

Cursor is the selection. The detail pane tracks ↑/↓ live, exactly like the coding app's tasks pane. The full-width no-selection state stopped mattering once the empty pane became a create surface.

KB-001 · KB-002
ANSWERED · picker semantics

What does the committed epic set do?

Nothing new — it's the existing filter. The picker is a keyboard home for the #833 epic selection; Space toggles, Enter commits + clears selection, Esc cancels.

KB-004 · KB-005
ANSWERED · layout

Persistent epic rail or summoned picker?

Two permanent panes; the picker is a modal. The three-column rail (V2) was explicitly rejected — no standing space cost for a rarely-touched filter.

KB-004
ANSWERED · focus model

Who owns arrows when the pane has inputs?

No pane-focus concept. The list owns the keys except while a typing target has browser focus. The pane is mouse-first in v1 — stated, not accidental.

KB-007 · KB-009
OPEN · Q1 collisions

Keymap collisions with existing shortcuts

Needs an audit: useGlobalKeyboardShortcuts and the drawer's keyboard nav already claim keys in Studio. The Backlog keymap must compose (single router, like coding's routeFocusedPane) rather than stack listeners.

OPEN · Q2 cursor landing

Where does the cursor land after a filter commit?

Selection clears by rule (KB-005), but the cursor's landing row (top of list? nearest surviving row?) is undecided. Also: what, if anything, Enter does on a cursored header.

OPEN · Q3 chord semantics

N/I chord: Board-only → shared

#686 built the chord Board-only with planning-axis seeding. Extending to the Backlog means deciding what the seed is here (cursored group? active epic filter?) and where the chord hook lives so the two views share it.

OPEN · Q4 overlay boundary

Generic-core purity

This is generic-relevant tracker core in the lead repo: no coding-overlay symbol may leak into the keymap/pane/picker (OWNERSHIP.md). The coding app is a design reference, never an import.

Acceptance signal

The slice is done when, on the Backlog with hands never leaving the keyboard, you can ↑/↓ across stories and group headers with the right pane tracking the cursored story live as a full IssueDetail; →/← expand and collapse groups; ← from a leaf summons the epic picker, where Space toggles and Enter applies the shared epic filter, re-renders the list, and clears the selection; Esc returns the pane to its quick-create empty state, from which N/I starts a create; s changes the cursored story's status — while the Board's floating drawer behaves exactly as before, and not one coding-overlay symbol appears in the new files.
