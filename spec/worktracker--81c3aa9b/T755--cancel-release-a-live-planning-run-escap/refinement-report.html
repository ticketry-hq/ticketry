Release A Stuck Planning-Run Lock

Manual recovery hatch for planning_run_already_running; it clears the execution guard and does not claim to kill or diagnose the underlying agent.
requirements clearno implementation in this phaseready for LLD
DecisionContractBoundariesAcceptance

Decision

Use “release” as the product and implementation language; “cancel” is only an API affordance alias if needed.
Operator
  • Does: explicitly declares the run abandoned and asks to clear the lock.
  • Does not: rely on server death inference or timeout.

Contract

The first slice targets the process-local implementation; CODIN-757 later retargets the same contract to the durable row.
SurfaceRequirement
driver.release(task_id)Atomically transitions a registered running planning run to released state by removing/resetting the guard entry. The reducer owns legality; the driver owns mutation.
DELETE /work-items/{id}/planning-runReturns 200 with the released previous state and current idle/unregistered state. Returns 404 with planning_run_not_found when no running planning run is registered.
release_planning_run(task_id)MCP tool mirrors launch tooling for agent/operator recovery. It is not exposed as agent death reporting.
StudioAdd a “Release run lock” affordance beside tracked planning-run launch controls in the drawer. Dependency view release is optional unless LLD shows it is the only place graph status is visible.

Boundaries

In Scope

Manual release for stuck planning-run guard, backend/API/MCP/Studio client wiring, and tests proving release then relaunch starts a fresh run.

Out Of Scope

Automatic death detection, timeout, boot sweep, durable run-state, terminal termination, and graph-run release unless LLD finds shared primitives make it free.

Risk Control

Copy must say “release lock,” not “kill run.” A still-live orphan is possible; that is accepted operator responsibility in this hatch.
