Drawer Planning-Tracer Bridge — explicit Refine / Split launch

The tabbed issue drawer gets two dedicated, state-gated controls — Refine (Backlog task) and Split (Todo task) — that launch a tracked planning-tracer phase through the already-shipped internal primitive apps.execution.driver.execute(task_id, agent, phase). A new authenticated endpoint POST /work-items/{id}/planning-run creates the process-local tracer state and launches; the run then surfaces as a normal drawer Terminal-tab run by attaching to its spawned tmux session. The generic untracked terminal launch path is untouched.

Rules settled in refinement

Load-bearing rules. The implementation should make the explicit, completion-only, single-live-run path easy and every other path awkward.

Explicit, never inferred

  • A tracked run is created only by the Refine / Split buttons.
  • Never inferred from prompt text or the generic launch path.
  • phase in the request body selects the recipe.

State-gated + re-validated

  • Refine visible/enabled only for the backlog group.
  • Split only for unstarted (Todo).
  • Server re-validates the group; wrong group → 422.

Completion-only transitions

  • Backlog→Todo only completes an in-flight refine.
  • Todo→LLD only completes an in-flight split.
  • No transition auto-launches the next phase.

One live run per task

  • Re-click while a run is live → 409, guarded server-side.
  • Guard reads driver.get_state(task_id) before launching.
  • No GET/status endpoint; the button shows no live status.

Agent from the drawer

  • Body carries the drawer's currently-selected agent.
  • Endpoint owns no agent-defaulting policy; agent is required.
  • Same agent set as the terminal-tab picker (#751).

Process-local only

  • Registry stays the in-process _registry dict.
  • Restart drops in-flight tracer state; documented limitation.
  • Durable lifecycle tracking deferred to #744.

Endpoint contract

One authenticated route, owned by CODIN-746, thin over the shipped driver. Registered on the host API (no /work-tracker prefix) since it drives the Coding-side apps.execution tracer, which the generic worktracker package must not import.

RoutePOST /api/work-items/{issue_id}/planning-run
AuthRouter-level ApiKeyAuth (x-api-key), matching every other host/worktracker route.
Pathissue_id — task UUID (the drawer's launchContext.taskId).
Body{ "phase": "refine" | "split", "agent": "claude" | "agy" | "codex" | "gemini" }. Both required; no defaulting.
Success201 → { task_id, phase, status, agent_run_id } reflecting the freshly-launched engine state (status = "running" on a successful spawn).
409 ConflictA live tracer run already exists for the task — driver.get_state(issue_id) is present with status == "running".
422 UnprocessableTask not in the phase's required group (task_not_in_backlog / task_not_in_todo) or its module cannot be resolved (module_id_required).
404 Not FoundNo task with that id (task_not_found).
500Only for a genuinely unexpected fault; the spawn failure itself is folded to a failed engine state by the driver, not raised here.

The endpoint adds exactly two responsibilities on top of the shipped execute(): the duplicate-live-run 409 pre-check (needed because execute() otherwise overwrites the registry entry and would relaunch), and the ValueError → HTTP status mapping. Group re-validation is already enforced inside execute() and is surfaced, not re-implemented.

Decisions

The LLD keeps the surface minimal and refuses to reshape the shipped driver or the untracked path.

DecisionChosen pathWhy
Endpoint ownershipNew apps/execution/api.py router on the host API.The generic worktracker package cannot import the Coding-side tracer; the tracer's own app owns its HTTP seam.
Duplicate-run guard placementIn the endpoint, before execute(), via get_state.execute() overwrites the registry unconditionally; the 409 must be decided before that overwrite. Keeps the driver primitive untouched.
Wrong-group status422 for group mismatch; 409 reserved for a live run.Group mismatch is an unprocessable request against task state; a live run is a genuine conflict. Both are permitted by the AC ("409/422").
Agent sourceDrawer's selected terminal-tab agent, sent explicitly in the body.Decision #5: no server defaulting; the drawer already owns agent selection via #751.
Run surfacingAttach to the spawned tmux run by agent_run_id.The WS transport already supports mode:"attach"; this makes the tracked run appear as a normal drawer terminal tab with no second launch mechanism.
No auto-chainingCompletion only marks the phase done.Decision #3; auto-launch/chaining is #721's deferred pipeline, kept out of the interactive path.
No durable trackingProcess-local registry; restart limitation documented.Decision #7; durable lifecycle-state tracking is #744.

Test plan

Backend: endpoint contract tests injecting a fake spawn through the driver seam. Frontend: rendered drawer integration for gating + launch. The completion-only reducer behavior is already covered by the shipped test_reducer / test_driver suites and is re-asserted, not rebuilt.

api · refine happy path
POST {phase:refine,agent} on a Backlog task → 201, status=running, agent_run_id present; spawn called once with the refine recipe and the given agent.
api · split happy path
POST {phase:split,agent} on a Todo task → 201, split recipe prompt, correct agent.
api · duplicate 409
Second POST while get_state is running → 409; spawn not called a second time; registry entry unchanged.
api · wrong group 422
Refine on Todo and Split on Backlog each → 422 with the matching gate message; nothing spawned.
api · not found / auth
Unknown id → 404; missing/invalid x-api-key → 401.
reducer · completion-only (existing)
Re-assert: Backlog→Todo completes a running refine; Todo→LLD completes a running split; neither launches anything.
drawer · gating
Refine renders only for backlog, Split only for unstarted; neither for started/completed/cancelled; both disabled when profile not ready.
drawer · launch + attach
Click Refine → posts correct phase + selected agent; on 201 an attach-mode session for the returned run appears in the Terminal tab and is focused; no relaunch.
drawer · no tracked run from generic path

Acceptance signal

CODIN-746 is complete when a Refine button on a Backlog task and a Split button on a Todo task each POST /work-items/{id}/planning-run with the drawer's selected agent, creating process-local tracer state and launching a tracked run that appears as a normal drawer Terminal-tab run; a duplicate click while the run is live returns 409 and a wrong-group request returns 422; Backlog→Todo completes an in-flight refine and Todo→LLD completes an in-flight split, each launching nothing; no tracked run is ever created from prompt text or the generic launch path; and the #719/#720 "immediate Todo→LLD" wording is corrected to attribute automatic chaining to the deferred pipeline. All paths are tested and the process-local restart limitation is documented.
