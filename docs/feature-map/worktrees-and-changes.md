# Worktrees and changes

Worktrees isolate a ticket's checkout, while the independent Changes workspace reviews module or task changes through a checkout switcher, file list, diff and branch inspector.

Surfaces: browser, desktop
Editions: pocock, core

## Sub-features

- worktree-ticket-control: opt into an isolated checkout from selected-ticket Details.
- worktree-details: inspect branch, path, cleanliness, divergence, conflict and parent sharing.
- worktree-discard-and-trust: confirm explicit discard and recover declined or failed directory trust.
- changes-independent-workspace: enter review without changing the planning selection and return to its origin.
- changes-checkout-switcher: select the module checkout or a current task worktree with pointer or local keys.
- changes-branch-inspector: reveal branch status, publishing, pull-request, local-merge and cleanup controls.
- changes-file-navigation: traverse directories and changed files without selecting a file merely by focusing it.
- changes-diff-and-patch: read rendered or raw patches, error and non-text states, and resize the review panes.

## How to get to it

Select a ticket and open **Details**. Its action toolbar contains `worktree-block`: **+ Worktree** creates an opt-in checkout; an existing branch button (**View changes on <branch>**) opens its Changes view. **Show worktree details** opens `worktree-details`, with **Discard**, **Yes, discard** and **Cancel** for an owned checkout. Shared children have no discard control. Sources: `studio/src/features/agents/worktrees/WorktreeBlock.tsx` and `studio/src/app/shell/ticket-workspace/selected-ticket/details/IssueDetail.tsx`.

Click the workspace tab **Changes · <module>** (`workspace-tab-changes`) to review the module checkout independently of ticket Details. With keyboard focus on that tab, Enter or Space enters and focuses **Choose checkout**. Open that trigger to select **Open Module checkout Changes** or **Open <ticket> Changes**. Click **Branch** to reveal the inspector; **Close branch inspector** or Escape inside it closes it. Return through the originating module tab; Escape outside a Changes popup also leaves review. Sources: `studio/src/app/shell/ticket-workspace/WorkspaceTabs.tsx`, `studio/src/app/shell/ticket-workspace/ModuleTabStrip.tsx`, `studio/src/app/navigation/useGlobalKeymap.ts` and the worktree Changes components below.

The following fixed local bindings are defined in `studio/src/app/navigation/keymapBindings.ts`. They apply to the focused checkout options or file rows, rather than the application globally. See [Keyboard navigation and shortcuts](keyboard-navigation-and-shortcuts.md) for focus ownership.

## Prerequisites

- Select a module to enable its Changes tab. A linked local Git repository is required for meaningful checkout/diff operations; a non-Git module offers no false **+ Worktree** control. A task worktree must exist before reviewing its isolated checkout. See [Module folders and trust](module-folders-and-trust.md).
- Use disposable local repositories for creation, discard, commits, merges and cleanup. Publishing requires a configured remote and credentials; pull-request operations additionally need the runtime's GitHub facilities. Mocked acceptance tests do not establish those external integrations.
- Worktree directory trust is distinct from creation: the checkout may already exist when trust is declined. Retry trust on that checkout rather than creating another (`WorktreeBlock.tsx`). Browser and desktop share the Changes UI; desktop terminal evidence uses the [terminal renderer strategy](../plans/terminal-renderer-strategy.md), not this diff viewer.

## Expected behavior

- **Worktree status and creation:** no checkout shows **+ Worktree**; pending creation disables it and shows **Creating…**. Success renders the mutation's authoritative branch/status. Before status loads, or for `no_repo`, the ordinary control is absent. Status, creation and discard errors are visible. Trust failure retains the checkout, reports the reason and offers **Retry trust**. Selection changes clear local confirmation and mutation errors. Sources: `studio/src/features/agents/worktrees/WorktreeBlock.tsx` and the selected-task/creation/status acceptance tests below.
- **Details, sharing and completion:** owned checkouts show Clean/Dirty, ahead/behind against the base, path and **Completion keeps the worktree**. Shared children identify their top-level owner and cannot discard its checkout. Conflict details ask the user to resolve and commit in that worktree; completion does not automatically merge or discard it. **Discard** first asks for confirmation; **Cancel** sends no removal, and only **Yes, discard** submits the identity-bound request. Success publishes authoritative returned status or refetches it. Sources: `WorktreeBlock.tsx` and `studio/e2e/web-app.spec.ts` worktree journeys.
- **Independent review and return:** entry captures the prior module, ticket, workspace and layout/focus state; checkout switching changes the review target without replacing that origin. Returning restores it. The checkout last chosen in module review applies only to the module's own Changes surface; a ticket's **View changes on** chip always opens that ticket's worktree, including right after module review without a reload (CODING-2872, `@case-changes-origin-return`). Source: `studio/src/features/task-workspace/internal/WorkspaceTabBody.tsx`. If the original ticket was removed, recovery selects the same module's scratch Details rather than a different surviving ticket. The return path stays usable through loading and read failure. Saved legacy ticket Changes targets migrate to Details; the retired per-ticket Changes tab is removed from saved order. Sources: `studio/src/features/agents/worktrees/changes/changesWorkspaceState.ts` and workspace navigation/recovery/compatibility acceptance tests.
- **Switcher and inspector:** the switcher lists module checkout first, then active task worktrees, with branch and status summaries. It reports loading, failure, no task worktrees and truncation. Arrow navigation clamps at the ends; Enter/Space selects, Escape cancels, and close restores trigger focus. A failed task-list fetch still leaves the module checkout reachable. The collapsible branch inspector exposes status and eligible actions; explicit open focuses Close, while close returns to the visible Branch trigger when the inspector still owns focus. Commit and Push remain distinct; Push publishes committed work only. Stacked publishing asks for confirmation, starts on Cancel, permits Escape before submission, and locks controls while pending. Sources: `WorktreeSwitcher.tsx`, `BranchInspector.tsx`, `ChangesToolbar.tsx` and their acceptance tests.
- **Files and diff:** module review names its selected comparison baseline; task review includes committed work from the recorded base. The file list groups paths with directory disclosure, status badges and keyboard focus navigation. Navigation moves focus without selection; Enter/Space selects a file or toggles a directory, Right expands or moves from a file into the diff, and Left collapses a directory. File selection is kept per checkout in Apollo client state; a removed selected path clears after loading. Previous/Next changed-file buttons wrap without moving focus. Empty module/task lists explain the baseline-specific absence. Sources: `ModuleVersionControl.tsx`, `TaskWorktreeChanges.tsx`, `ChangedFilesList.tsx` and `ChangesFileReview.tsx`.
- **Patch, failure and resizing:** the named diff region remains mounted across loading, failure, binary, empty, truncated and patch states. A rendered patch falls back to raw patch while its renderer loads or fails. The region supports arrows, PageUp/PageDown and Home/End scrolling; Left at the horizontal start returns to files, and Up at the vertical start returns to commands. The visible separator resizes file/diff panes by keyboard or pointer within panel bounds. Late file responses must not present another selection's diff. Sources: `DiffReadingRegion.tsx`, `FileDiffSurface.tsx`, `ChangesFileReview.tsx` and the diff/stale-data acceptance tests.

## Gotchas

- The current checkout picker is a toolbar listbox, not a permanent checkout column. `studio/e2e/web-app.spec.ts` still has historical column/narrow-window cases expecting `changes-checkouts-column`, `changes-checkouts-resize-handle`, `changes-files-scroll` and region **Current worktrees**; these are absent from the current components. Record failures honestly and do not use those historical expectations as proof of today's layout. `overhaul-web-15` and the current DOM acceptance cases use the real switcher.
- The label **Changes** does not imply a saved per-ticket workspace tab. The independent workspace captures an in-memory Apollo origin; compatibility tests explicitly remove the retired tab. Per-checkout file-selection memory is not a claimed reload/restart persistence contract.
- Terminal lifecycle, native viewer state and tmux liveness are separate axes. Worktree existence/cleanliness is another observation and must not be inferred from a run reaching Done or its terminal ending. On the primary native desktop path terminal output never enters the WebView; patch/diff content does. Browser xterm/WebSocket or Changes evidence makes no native-rendering claim. See [terminal renderer strategy](../plans/terminal-renderer-strategy.md), [AGENTS.md](../../AGENTS.md) and [CLAUDE.md](../../CLAUDE.md) for renderer/fallback and tmux durability facts.
- Right/Left have different owners in a directory, file row, toolbar, separator and diff region. Apply the listed keymap chords to the intended focused control; file focus alone does not open a diff. Popup Escape cancels the popup before the outer workspace exit.
- No live walkthrough is part of this map change. Stale browser selector scenarios, real GitHub publishing, installed-desktop review focus, current narrow layout and review-state restart persistence remain unverified here; cited mocks and source do not close those gaps.
