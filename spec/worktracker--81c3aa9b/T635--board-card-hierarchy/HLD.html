Board Card Hierarchy — High-Level Design

On the Kanban Board today, a top-level Story and a Sub-task render as identical cards — same key, priority and title, no cue to tell them apart. When sub-tasks are shown, a state column becomes a flat mix and you can't see what is a child of what. This slice gives sub-task cards a left accent bar + indent and a small parent reference, and gives parent stories a sub-task count badge — borrowing the vocabulary the Backlog list already uses. Pure frontend, zero backend.

The slice, in three pillars

Click a pillar to expand its boundary. The whole change is one annotation in the board selector and a presentational branch in one card component.
PILLAR 1 · the signal

Annotate cards with hierarchy

The flat-board and swimlane selectors tag each card with isSubtask and, when it is one, its immediate parent's key.

  • A card is a sub-task when its parent_id resolves to another work item (a Story), not to a Module (Epic)
  • Same parent-walk machinery as owningEpic() already used by boardColumns and boardSwimlanes — a Module parent = top-level Story; a work-item parent = Sub-task
  • Resolve the parent key from the already-loaded item set for the ↳ chip
  • All data is already on WorkItem: parent_id, sub_issues_count, key — no fetch
PILLAR 2 · the look

Inset, barred, referenced

BoardCard grows a presentational branch: sub-tasks get a left accent bar + indent + parent chip; stories get a count badge.

  • Sub-task: left accent bar (border-l) + small left margin/indent, using one shared design token for now
  • Sub-task: a muted ↳ KEY parent chip above the row (reuses IconCornerDownRight, the Backlog sub-task glyph)
  • Any card with children: a sub-task count badge from sub_issues_count — including a sub-task that is also a parent
  • Keep the accent source isolated so a later connected-accent scheme can derive colour from the parent without changing card classification or layout
  • Same tokens as the Backlog: text-text-muted, accent for the bar; honours the dark Studio theme
PILLAR 3 · the blast radius

Presentation only, board-wide

No backend, no store action, no drag change. Works whether the board is flat (today) or in epic swimlanes (#632).

  • Drag, drop, #626 reorder, click-to-open — all untouched
  • Lives in BoardCard, so it applies in every board layout including future swimlanes automatically
  • No migration, no route, no SDK change — read-only use of existing fields
  • Count badge when sub-tasks are hidden, bar colour, deeper nesting — LLD details

RESOLVED · treatment

How do sub-task cards look different?

Left accent bar + indent. A colored left border and a small left margin inset the sub-task, plus a ↳ parent-key chip. Chosen over a type-icon-only or glyph-only treatment for the clearest at-a-glance grouping.

RESOLVED · ticket scope

Where does this live?

A standalone, whole-board ticket. The flat board already mixes stories and sub-tasks today, so this ships independently of #632 swimlanes and benefits both.

RESOLVED · which levels

Does Epic get a card treatment too?

Story vs Sub-task only. Epics are lanes/columns, not draggable board cards, so no epic card styling is needed.

RESOLVED · accent source

Accent bar — one colour or per-story?

One shared token colour for now. Keep the accent value behind a small isolated presentation seam so a later connected-accent treatment can derive sibling colour from the parent without redesigning classification, selector data, or card layout.

RESOLVED · count visibility

Count badge when sub-tasks are hidden

The badge always shows when sub_issues_count > 0, regardless of the Show sub-tasks toggle.

RESOLVED · deeper nesting

What if a sub-task also has children?

Keep one bar + one indent because hierarchy treatment is binary. Show both the immediate-parent key chip and the card's own child-count badge.

Acceptance signal

The slice is done when, on every Board layout, a sub-task card is immediately distinguishable from a top-level story — inset with one token-coloured left accent bar and carrying a ↳ immediate-parent-key reference — while every card with children shows a sub-task count badge, visible even when sub-tasks are hidden. A nested sub-task shows both its parent chip and child count. The distinction stays binary (one bar + one indent, not depth-scaled); the accent source is isolated for a later connected-accent treatment; drag, #626 reorder, and click-to-open are unchanged; flat board and epic swimlanes behave consistently; and all of it ships with zero backend change.
