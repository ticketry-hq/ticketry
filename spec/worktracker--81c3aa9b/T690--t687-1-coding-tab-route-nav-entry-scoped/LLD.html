The routing subtlety (decision-complete)

A static coding segment outranks the dynamic :view route — which changes how the view is derived.

In React-router v6, once the splat route /projects/:projectId/coding/* exists, even the bare /projects/:projectId/coding URL matches it — there params.view is undefined and params["*"] is a defined (possibly empty) string. So the view cannot be read from params.view for this surface.

Decision: treat the presence of params["*"] as the coding signal. In useRouteSync, the effective view becomes "coding" when params["*"] is defined, else normalizeView(params.view). Only the coding splat route populates params["*"], so this is unambiguous. The key-present (drawer) early-return stays first.

coding is still added to the View union / VIEWS array so setView, activeView comparisons, and nav active-highlighting are type-safe.

Nav placement & placeholder spec

A distinct group keeps the execution surface legible against TRACK and PLAN.

NavDrawer — dedicated CODE section
  • Single item { view: "coding", label: "Coding", Icon: <new icon> }, placed between PLAN and the pinned Settings block. Rationale: Coding is an execution surface (the eventual per-ticket terminal / coding-agent pane), distinct from TRACK ("where work is now") and PLAN ("how it's organized").
  • Reuses NavSection + NavDrawerItem unchanged — project gating, data-testid="nav-coding", and active styling via activeView === "coding" all come for free.
  • Link resolves to /projects/${selectedProjectId}/coding → matches the splat route → activeView === "coding".
CodingView placeholder
  • Mirrors sibling views: root flex h-full flex-col, a ViewHeader titled Coding, and a body region.
  • Project guard: when selectedProjectId is null, render the same centered "Select a project…" empty-state idiom (covers direct-URL hits; nav is already gated).
  • Body copy: a brief centered placeholder stating the per-ticket coding pane is not mounted yet and lands in #691. No interactivity.
  • Uses Studio's existing token classes (bg-pane-bg, text-text-muted, …) exactly like siblings — no theme wrapper, no scoped styles.

Test plan — codingRoute.test.tsx

Additive only; existing route/nav/view suites must stay green.

  • Nav entry renders & gates. With a project, nav-coding is a link to /projects/<id>/coding; with none, it is disabled (aria-disabled, not a link).
  • Base route. At /projects/<id>/coding, activeView is coding, the nav item shows aria-current="page", and content-coding renders the placeholder.
  • Nested splat. At /projects/<id>/coding/anything, activeView === "coding" still resolves and renders the placeholder (proves the params["*"] rule).
  • No regression. A non-coding view (e.g. /projects/<id>/board) resolves normally and does not render content-coding.

Validation: npm run -w studio test (new green, existing unchanged); npm run -w studio build/typecheck (View-union change compiles across all activeView consumers); manual gating + base/nested URL checks.
