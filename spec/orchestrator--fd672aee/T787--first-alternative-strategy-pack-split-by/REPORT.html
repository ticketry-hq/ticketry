Swappability — the actual proof

The design goal was: a new strategy is a new directory, not a code change.

The by-interface pack was authored with zero edits to loader.py, reducer.py, services.py, or policy.py. It declares the same required phase set and uses only the existing interpolation whitelist (key, name, description, children, project_id, project_slug). load_pack("by-interface") validates and renders through the identical path as default. Only the prompt prose differs: the split axis is the system's interfaces, and blocked_by edges encode interface-consumption order (a consumer leaf is blocked by the leaf that owns the interface it consumes).

Deterministic child slugs — convention, per the brief

Amendment: the pack spec must require deterministic slugs. The brief (§2.6 / §8) fixes the enforcement model.

Deterministic slugs are a prompt-level convention, not a loader mechanism (brief §8: "a convention, not a mechanism"). Every decompose.md instructs the agent to derive a stable, reproducible slug per child and to SKIP any slug already present in the rendered {{children}} block. The safety nets are the driver's structural postcondition (union-validated) and the partial-failure test below — not a brittle prose check in the loader. test_strategies.py::test_pack_decompose_requires_deterministic_slugs pins the requirement across all packs.

Reconcile retry is duplicate-proof

The deliberate partial-failure test — driven end-to-end through the real fold, reducer, and driver.

  1. Attempt 1 exits clean but incomplete — 1 child, below the 2..budget band → postcondition fails → quadrant 2 → stopped_incomplete → one reconcile retry armed.
  2. The retry's decompose prompt re-renders with the created child in {{children}} (reconcile input wired — asserted).
  3. A well-behaved agent recreates only the missing children; the already-made slug is skipped.
  4. The union postcondition passes → root lands done with exactly the intended set.
  5. Assertions: no duplicate tracker children, no duplicate RunNode rows.

Note: a hard kill (exit≠0 / timeout) lands in quadrant 4 (failed, no retry) under the current reducer — the reconcile path that makes dedup matter is the clean-but-incomplete exit modelled here. A fake agent stands in for the subprocess so the mechanism is deterministic without an LLM.

Live-E2E runbook (human-gated)

A true both-packs run needs pnpm orchestrate, real agent CLIs + keys, and MCP — it is not automatable in CI. Run once per pack against the same parent:

pnpm orchestrate            # boots ASGI + worktracker + orchestrator, signal seam live

# default pack
POST /api/orchestrator/runs { parent_task_id, strategy: "default",      model, check_command, autonomy }
# by-interface pack (same parent, after the first lands / is released)
POST /api/orchestrator/runs { parent_task_id, strategy: "by-interface", model, check_command, autonomy }

GET  /api/orchestrator/runs/{id}   # each run header records strategy + created_ticket_ids

Both run headers already persist strategy and created_ticket_ids (see CoordinatorRun / serialize_run), so the two child-ticket trees are attributable to their pack — the comparison that feeds Benchmarking & Evals (#762).
