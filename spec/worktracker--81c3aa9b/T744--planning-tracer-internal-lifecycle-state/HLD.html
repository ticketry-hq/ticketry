A durable, engine-owned planning lifecycle that advances independently of the coarse user-facing board state. Nineteen internal states form one guarded state machine on Issue.lifecycle_state; the five frozen visible groups and their board columns are left untouched.

Scope lock

Own the state semantics of the planning pipeline: define, store, validate, expose, and wire a durable internal lifecycle. Do not generate artifacts, create leaves, or launch agents — those stay with the phase tickets.

Build

  • Add Issue.lifecycle_state (nullable enum, 19 values) to WorkTracker core — migration 0009.
  • One unified, role-gated transition table + a strict guarded write path (only writer of the field).
  • Validate both the lifecycle→lifecycle transition and the (lifecycle, visible state) pairing; illegal → raise InvalidTransition.
  • Define the lifecycle→visible-state map and the three sanctioned sync points (define + validate only).
  • Retrofit apps/execution to persist lifecycle and delete the phantom to_state=="LLD" magic string.
  • Read/write surface: read on WorkItemOut, POST /work-items/{id}/lifecycle, MCP set_lifecycle.
  • Drawer lifecycle chicklet — view + change, offering only legal next transitions plus failed/cancelled.
  • Tests: transition validity, pairing validity, and UI-visibility regression guards.

Do not build

  • No engine auto-mutation of Issue.state — sync points are defined & validated, not performed here (phase tickets keep moving visible state).
  • No PRD / HLD / LLD artifact generation; no leaf-task or edge creation; no agent launches.
  • No sixth visible group and no new visible State row — the five groups stay frozen.
  • No blocked lifecycle value — reuse the existing Blocked visible state + blocked_by edges.
  • No subtree/aggregate rollup of a root from its leaves' lifecycles.
  • No board column, swimlane, filter, or workflow-config surface for internal states — the drawer chicklet is the only opt-in surface.

Two orthogonal axes

The disease this ticket cures: today the pipeline overloads the visible-state axis (e.g. gating on a phantom LLD state that is never even seeded). CODIN-744 gives the pipeline its own axis.

Visible workflow axis — unchanged

  • State rows, five frozen groups (backlog / unstarted / started / completed / cancelled).
  • Issue.state — single FK; the clean user-facing column axis.
  • Board columns, swimlanes, pickers, filters, workflow config all derive 1:1 from State rows.
  • Coarse milestones: Backlog Todo In Progress Done.

Internal lifecycle axis — new

  • Issue.lifecycle_state — a separate nullable enum field, per work item.
  • 19 fine-grained states; engine, agents, reducers read/write via the guarded path.
  • Structurally invisible: it is not a State row, so the board that reads only State rows can never render it as a column.
  • Explicit opt-in display: the drawer chicklet — nothing else.

Because visibility is achieved by where the data lives (a field the board never queries) rather than by a runtime "hide this row" flag, the visibility requirement is satisfied by construction. The UI-visibility tests are therefore regression guards, not new hiding logic.

The lifecycle state machine

Click any state to see its meaning, legal next states, mapped visible state, and owning ticket. Green outline = an *_approved gate (human acceptance). Red = terminal error/abandon, reachable from any active state.

Role-gated entry, one table: a root work item traverses backlog → … → split_created and stops. Each leaf created by the split enters at split_created and runs lld_generating → … → done. A leaf later re-split simply re-enters the split lane. Same enum, same guard, different entry point.

The pairing guard (why the chip can 422)

  • Setting lifecycle=implementing while Issue.state=Backlog is rejected — the pair is illegal.
  • The visible state must first be moved (by a human or a phase ticket) to In Progress; then the lifecycle write succeeds.
  • This keeps 744 contract-only: nothing here auto-moves the visible state.

Three sanctioned sync points

  • prd_approved ⇄ Todo — owned by CODIN-719.
  • implementing ⇄ In Progress — owned by execution launch.
  • done ⇄ Done — owned by execution completion.
  • All other lifecycle steps advance with the visible state held coarse.

Read / write surface

One guarded service is the sole writer. Three callers reach it; all pass through the same transition + pairing validation.

Guarded service (core)

  • set_lifecycle(issue, target) — validates transition + pairing, else raises InvalidTransition.
  • The only code path that writes the field; model save is not a bypass (enforced via the service / a checked setter).
  • Exposes allowed_transitions(issue) for the picker.

HTTP + serialization

  • WorkItemOut.lifecycle_state — read-only; board ignores it.
  • WorkItemOut.lifecycle_transitions — legal next set (feeds the picker).
  • POST /work-items/{id}/lifecycle {target} — guarded write; 422 on illegal.

MCP + engine

  • MCP tool set_lifecycle — agents drive lifecycle over MCP.
  • apps/execution reducer/driver persist lifecycle at phase boundaries via the service.
  • Phantom to_state=="LLD" gate replaced by lifecycle==hld_approved.

Drawer lifecycle chicklet

  • Sits beside the existing visible-state chip in the Issue drawer (the one explicit opt-in surface).
  • Picker shows only legal next transitions (from lifecycle_transitions) plus failed / cancelled, which are always offered.
  • Illegal targets are unreachable from the UI; the server still guards. A rejected pairing surfaces as an error toast.
  • Board, swimlane, StatePicker, BoardFilterBar, and workflow-config panel are untouched.

Test plan

Transition & pairing validity

  • Every listed transition is accepted; a representative set of unlisted ones raises InvalidTransition.
  • → failed / → cancelled accepted from each active state; rejected from terminals.
  • Back-edges (*_review → *_generating) accepted.
  • Illegal pairing (e.g. implementing while visible Backlog) rejected; legal pairing accepted.
  • allowed_transitions(issue) returns exactly the table's next set for a given state.

UI-visibility regression guards

  • boardColumns() / boardSwimlanes() derive only from State rows — a set lifecycle_state adds no column.
  • StatePicker / BoardFilterBar options contain no lifecycle values.
  • Workflow-config panel lists no internal states.
  • Drawer chicklet renders only legal next transitions + failed/cancelled.
  • Engine retrofit: split completion now keys off hld_approved, and no test depends on a seeded LLD state.

Acceptance signal
