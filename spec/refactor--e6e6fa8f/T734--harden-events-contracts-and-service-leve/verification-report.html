Findings

Two genuine behaviour regressions (confirmed red, then fixed green), one documentation drift restored, one additive change accepted.

F1 · regression fixed

Module work-item create dropped its 422 on a wrong-level issue type

The moved service converts the helper's HttpError into a domain ValidationError, but api/work_items.create_module_work_item shipped without the try/except ServiceError its siblings all have — so the domain error escaped uncaught.

before: invalid type → 500
after: invalid type → 422 (matches HEAD)
F2 · regression fixed

Module create raised 500 on a missing project

services/modules.create_module used a bare Project.objects.get (raising DoesNotExist) where HEAD used get_object_or_404. Hardened the service to raise NotFoundError and to wrap the issue-type HttpError as ValidationError, and the route now maps ServiceError → HttpError.

before: absent project → 500
after: absent project → 404 (matches HEAD)
F3 · doc drift restored

14 route descriptions had been truncated to their first line

Moving handlers into api/*.py kept only the summary line of each multi-paragraph docstring — and ninja publishes those as the OpenAPI description, so the generated SDK lost them. Restored verbatim from HEAD across work_items, projects, sprints and configuration. Contract descriptions now match exactly.

F4 · accepted addition

Two new attachment endpoints (PATCH + DELETE)

updateAttachment and deleteAttachment are absent from the pre-refactor baseline but arrived in this batch with 53 lines of passing tests, are purely additive, and change no existing operation. Reviewed and accepted as intentional under AC5.
