Merge Muxed + Studio into one frontend — High-Level Design

Two React apps already run over one backend. Fold Muxed's coding surface into WorkTracker Studio as a single left-nav tab, collapse the duplicated terminal WebSocket transport into one shared wire-contract both consumers import, route all REST through the generated SDK, then delete web/frontend. One app, one port, one deployable — the missing-mode drift caught in #685 can no longer recur.

How we got here

The backend is already unified (one Django server on :8787 exposes the worktracker ninja API and the terminal /ws). Only the frontend is split. Three ways to converge it.
TODAY · THE PROBLEM
Two React apps: web/frontend (:5173, raw fetch, no router) and studio (:5174, react-router + SDK). Each owns a copy of the terminal transport — #685's copy-slimmed ws.ts already drifted from the original (missing mode frame).
⟶
CONSIDERED · SUPERSEDED
Shared-package monorepo: extract packages/transport, packages/tokens both apps import; keep two shells/routers/deployables. Real option — but the genuinely-shared surface is small, and it preserves the very divergence we want gone.
⟶
THIS DESIGN
Fold into ONE app. Studio is the base; Muxed ports in wholesale as a single left-nav tab "for now"; one shared WS transport + wire-contract; REST on the SDK; web/frontend deleted, :5173 dropped.
The repo is already a pnpm monorepo — "monorepo vs fold" was a false choice; the workspace exists, the question is only what survives inside it. The two apps' Tailwind color palettes are byte-identical today, so the visual seam is narrow.

User stories

Actors: the developer using the app, and the frontend maintainer who keeps client and server from drifting.

One app, one surface

  1. As a developer, I want the tracker and the coding/terminal surface in one app behind one URL, so I stop juggling two windows on :5173 and :5174.
  2. As a developer, I want the coding surface as a left-nav tab inside Studio, so I switch to it the same way I switch between Backlog, Board and Story Map.
  3. As a developer, I want the coding tab to keep its familiar dark/mono terminal look, so the port doesn't change muscle memory while the rest of Studio stays light.
  4. As a developer, I want everything Muxed did — terminals, scratch terminals, running-agent counts, doc-chat, live lifecycle badges — present in the tab, so nothing I rely on disappears in the merge.

No more client/server drift

  1. As a maintainer, I want one terminal WS client and one wire-contract types module, so a frame the server expects can't silently go missing on the client (the #685 mode bug).
  2. As a maintainer, I want both the ported coding tab and #685's per-work-item terminal pane to import the same transport, so there is exactly one place a frame is defined.
  3. As a maintainer, I want all REST to go through the generated SDK, so a backend contract change surfaces as a TypeScript error, not a runtime 404.
  4. As a maintainer, I want the LifecycleEvent TypeScript mirror to live in one surviving frontend, so the agent-hook docstrings still point at a real file.

Clean cutover

  1. As a maintainer, I want web/frontend deleted and dropped from scripts/dev.mjs, so there is no second app to keep limping along.
  2. As a developer, I want the Django SPA catch-all to serve Studio's build after cutover, so the production single-origin URL keeps working.
  3. As a maintainer, I want pnpm dev to start exactly one frontend, so onboarding and CI stop referencing a dead service.

Sequenced, reversible-ish

  1. As a maintainer, I want this to land after #685, so I extract the shared transport against two known-good consumers instead of guessing.
  2. As a maintainer, I want model reconciliation (dropping the duplicate task-tree, rekeying by work-item id) deferred, so this story stays a port + de-dup and not a rewrite.
  3. As a maintainer, I want the governance docs retired alongside (#688), so the OWNERSHIP/overlay rules don't flag this consolidation as a violation.

  • Add /ws proxy to Studio's vite.config; both already target :8787
  • Delete web/frontend, drop :5173 from dev.mjs, repoint Django SPA catch-all at Studio's build

Testing & the seam

One seam carries the risk this story exists to remove. Test there, at the highest point, and the #685-class drift is caught by the type-checker and a contract test — not in production.

The one seam: the shared wire-contract module

The single highest-value seam is the wire-contract types + frame builders in the shared transport. It is the one place every terminal frame (init spawn/attach, ready, resize, scroll) and REST DTO is defined. Both the coding tab and #685's pane construct frames through it; nothing builds a frame by hand.

Prior art: Studio already runs contract:check (SDK regenerated from the backend's ninja OpenAPI and diffed). Extend that discipline to the WS frames — assert the client's frame shapes against the backend's expected schema so a missing field like mode fails CI.

Wire-contract (unit)

Test external behavior: given spawn vs attach params, the builder emits a frame with the required fields the server consumes. Drop a field → test fails. No internals asserted.

Transport reconnect (unit)

Port Muxed's existing transport tests onto the merged module: backoff budget, binary-bytes vs JSON-control routing, reconnect callbacks. Behavior, not timers.

SDK contract (CI gate)

Reuse contract:check: if the coding endpoints aren't yet in the OpenAPI (see Q1), this gate is where the gap shows up — informs whether #668 must land first.

A good test here asserts only the frame/DTO shape that crosses the wire — never how the store or socket is wired internally, so the deferred model-reconciliation refactor won't churn these tests.

Out of scope (deferred)

Kept out deliberately to keep #687 a port + de-dup, not a rewrite.

Model reconciliation

Dropping Muxed's duplicate tasksStore/task-tree and rekeying terminals/agents onto Studio work-item ids. Both client models coexist after #687.
