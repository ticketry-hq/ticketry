Newest story on top — global rank flip

Stories currently list oldest-first. Seed newly created items at the top of the shared LexoRank instead of the bottom, and re-stamp existing items newest-first once. Manual drag-to-reorder keeps working and persists, unchanged.

Problem Approach Change map Trace Files Acceptance

The problem

Every surface — Backlog, Board columns, Story Map cells — sorts by one global rank string (fractional-index LexoRank, #626), ascending, tiebroken by sequence_id. The frontend comparator compareRank deliberately mirrors the server's ORDER BY rank, sequence_id.

TODAY

Oldest first

The 0006 backfill stamped ranks in sequence_id ascending order, and every create calls append_rank → new items land at the bottom. So the list reads oldest → newest.

WANTED

Newest first

Latest-created story appears at the top, on all rank-driven surfaces. New items prepend to the shared rank.

INVARIANT

Drag still wins

Manual reorder (reorderWorkItem → key_between) is untouched; any arrangement the user drags into place persists exactly as before.

Approach — mirror append_rank

The rank machinery already supports "before the first": key_between(None, first). We add the symmetric helper and flip the seam. Comparator, drag endpoint, schemas, and the whole frontend stay as-is — only the seed value of new ranks and a one-time re-stamp change.

1 · NEW FN

prepend_rank(project_id)

Mirror of append_rank: key_between(None, Min(rank) or None) — a key sorting before every existing rank in the project.

2 · SWAP SEAM

Both create paths

create_work_item and create_module_work_item switch rank=append_rank(...) → prepend_rank(...).

3 · MIGRATION

Re-stamp existing

Sibling of 0006: rebalance() keys applied in -sequence_id order per project → existing list flips to newest-first in one pass.

Global by design: rank is a single shared key, so Board columns and Story Map cells also become newest-first within each cell — the intended, confirmed scope.
