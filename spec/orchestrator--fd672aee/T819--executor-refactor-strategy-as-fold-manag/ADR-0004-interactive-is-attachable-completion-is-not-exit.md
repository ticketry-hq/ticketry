# Interactive is an attachable Session; completion is not exit; attachers are pluggable

An interactive run is not a second execution model: it is the same ManagedAgent atom on the same Session substrate with attach permitted and gated approvals configured. Two rules follow. (1) Completion and exit are decoupled Facts: a node completes when its contract is met (`ContractMet`, e.g. ticket transitioned), which for interactive sessions may arrive long before — or without — `Exited`; Strategies fold on `ContractMet` and treat `Exited` as cleanup information. (2) Who attaches is open: a human today, an overseer LLM later; an attacher acts only through the same channels a human would (answer questions, approve actions, transition tickets), so its actions land as ordinary Facts and the Executor never knows the difference. We rejected a separate interactive execution mode (two substrates to reconcile) and rejected building the LLM overseer into the Executor (it is a consumer of the attach surface, not part of the atom).
