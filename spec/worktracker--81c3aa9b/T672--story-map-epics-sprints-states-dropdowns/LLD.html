Decisions trace

The decision-complete choices that resolve the ticket's revised scope. Each is final for this LLD.
DecisionResolution
D1 · Where to filterPost-filter the buildStoryMap() result inline in StoryMap.tsx — no new selector helper, no change to backlogSelectors.ts. The builder stays the canonical full model; the view derives three locals (visibleColumns, visibleRows, visibleCells) from it.
D2 · Epic columnsWhen epicIds is non-empty, keep only columns whose col?.id ?? NO_EPIC is in the selection. The trailing null (No-epic) column maps to the NO_EPIC sentinel. Empty epicIds = all columns.
D3 · Sprint rowsWhen sprintIds is non-empty, keep only rows whose row?.id ?? BACKLOG_ROW is in the selection. The trailing null (Backlog) row maps to the BACKLOG_ROW sentinel. Empty sprintIds = all rows.
D4 · State = card hidingWhen stateIds is non-empty, filter the cards inside each cell to those whose item.state?.id is selected. Columns and rows still render unchanged — emptied cells stay present so the whole row remains a drag-to-sprint drop target. Empty stateIds = all cards.
D5 · Null-state cardsThe States axis has no sentinel (#674). Under an active state filter, a card whose item.state?.id is null/unknown is hidden (it can never be in the selected set). Its column and row still render.
D6 · Store lifecycleOn project change call setProject(projectId) (loads that project's persisted selection). After the backlog load for the current project completes, call reconcile({moduleIds, sprintIds, stateIds}) from the live data to prune stale ids. reconcile is idempotent, so re-running it when the live sets change is safe.
D7 · IsolationRead/write only planningFilterStore. Never touch useBacklogStore.filters — the Backlog/Board chip filters and the planning selection are independent surfaces.
D8 · Header slotMount the three dropdowns in the ViewHeader actions slot alongside the existing NewSprint — the slot the retired LensTabs vacated.

Filter semantics matrix

The exact behavior of each axis at each selection state. "All" is the cleared/empty state for every axis.
AxisEmpty (= all)Non-emptySentinel
Epics
epicIds		 All columns render (every module + No-epic). Only selected epic columns render. Removed columns disappear from the header and from every row. NO_EPIC → the trailing null column.
Sprints
sprintIds		 All rows render (every sprint + Backlog). Only selected sprint rows render. Removed rows disappear entirely. BACKLOG_ROW → the trailing null row.
States
stateIds		 All cards visible. Cards whose item.state?.id is not selected are hidden. Columns & rows still render (drop targets preserved). Null/unknown-state cards are hidden. None — every item has a state; no sentinel by #674's design.

The three axes are independent and compose: a card is shown only if its column survived the Epics filter, its row survived the Sprints filter, and its state survived the States filter. Card ordering inside a surviving cell is unchanged — buildStoryMap already sorts each cell by the shared rank (#626), and the post-filter only removes cards, never reorders.

Invariants & guards

Properties the implementation must hold, derived from the live code of the read-only inputs.
  • Drop targets survive emptying. The state filter must never remove a column or row — only cards. SprintRow registers the whole row as one drop target regardless of cell contents, so a row emptied by the state filter still reassigns a dragged card's sprint.
  • Sentinel mapping is exact. Columns key on col?.id ?? NO_EPIC and rows on row?.id ?? BACKLOG_ROW — the same null→sentinel mapping cellKey and the dropdowns already use, so a selected "No epic" / "Backlog" keeps its column/row.
  • reconcile order. setProject (keyed on projectId) loads the persisted selection synchronously before any data arrives; reconcile (gated on the loaded project + live arrays) runs afterward. Re-running reconcile on live-set changes is safe because pruning a stale-free selection is a no-op.
  • Live id sets. reconcile receives moduleIds from studioStore.modules, sprintIds from backlogStore.sprints, and stateIds from backlogStore.states filtered to truthy ids (states may carry a null id, matching StatesFilterDropdown's own option guard).
  • Backlog filters untouched. No read or write of useBacklogStore.filters anywhere in this change (D7).
  • Cell ordering preserved. Filtering a cell's MapCard[] preserves array order, so the rank-sorted ordering from buildStoryMap is retained for visible cards.
