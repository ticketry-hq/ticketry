Read first — the test-launch hazard (discovered the hard way)

Building #745 surfaced a real hazard every remaining slice must respect. It briefly spawned ~10 real tmux sessions from unit tests before being caught (all killed; no real DB touched).

The mechanism: execution tests run django_db(transaction=True), so transaction.on_commit fires for real — every Issue.save() in a test emits the real issue_state_changed signal, the real receiver calls driver.observe_issue_state_changed(), and any launch that triggers uses the real spawn_run → a real tmux session. Before #745 the receiver was harmless (completion only); now it launches. After #717 it will launch fan-outs.

The guards now in place — keep them:

  • apps/execution/tests/conftest.py — autouse fixture monkeypatches driver.spawn_run to raise. Any accidental real-launch path shows up as a failed engine state with error real spawn_run blocked in execution tests, never a tmux session.
  • test_driver.py — autouse fixture disconnects the seam receiver (dispatch_uid="execution_observe_issue_state_changed") so unit tests drive events explicitly and don't race the on-commit signal.

Rule for new tests (#717/#718/#743/#721): new test modules in apps/execution/tests/ inherit the spawn block automatically. If a test saves Issue rows while an engine state is registered and wants deterministic event ordering, copy the receiver-detach fixture. Tests outside the execution app that move issue states while the execution app is installed get the real receiver — they are safe only because the registry is empty for their tasks; don't seed it.

#717 — Exec tracer 2: ready-set release TO BUILD · first

Turn the single-task engine into a graph engine: walk a root task's subtree, launch every task whose blockers are all complete, and release newly-unblocked tasks as seam completions arrive. Ticket is unrefined in WorkTracker — this section is the spec; paste it into the ticket when starting.

Settled design decisions (don't re-litigate)

  • Planning phases stay single-task. The graph layer applies to the implement phase only. refine/split/register/lld keep the existing per-task registry untouched. Two registries, no migration of existing behavior.
  • New pure module apps/execution/graph.py mirroring the reducer pattern: frozen dataclasses + a pure decide_graph(graph, event) → GraphDecision. This is the test seam; no I/O. (FE analogue for reference: studio/src/views/Dependencies/graph.ts buildGraph/reachable.)
  • Nodes = all non-archived type="task" strict descendants of the root (BFS over parent). Edges = blocked_by pairs where both ends are nodes; edges to tasks outside the subtree are ignored in this slice (log them).
  • Containment does not gate readiness — only blocked_by edges do. (Matches #698's treatment of subtasks as containment-only.)
  • Seeding from the tracker: a node whose current state group is completed seeds as done; everything else seeds idle. Re-running a partially-complete graph therefore skips finished work by construction.
  • Determinism: ready-set is sorted (by sequence_id, fall back task_id) so launch order is stable for tests.
  • Re-invoke guard (minimal for this slice): execute_graph on a root that already has a graph in the registry returns the existing state unchanged, launching nothing. #718 refines this into real idempotency.

Shapes (pure layer)

# apps/execution/graph.py  — pure, no Django imports
TaskRunStatus = Literal["idle", "running", "done", "failed"]   # "halted" arrives in #718

@dataclass(frozen=True)
class TaskNode:
    task_id: str
    sequence_id: int
    status: TaskRunStatus = "idle"
    agent_run_id: str | None = None
    error: str | None = None

@dataclass(frozen=True)
class GraphState:
    root_id: str
    project_id: str
    module_id: str
    agent: str
    nodes: tuple[TaskNode, ...]                 # frozen; replace() to update
    edges: frozenset[tuple[str, str]]           # (blocker_id, blocked_id)

@dataclass(frozen=True)
class GraphDecision:
    next: GraphState
    actions: list[LaunchAction]                 # reuse state.LaunchAction, recipe="implement"

def ready_set(graph: GraphState) -> list[str]:
    """idle nodes whose in-graph blockers are all done, sorted."""

def decide_graph(graph: GraphState, event: SeamEvent) -> GraphDecision:
    """execute_requested(root) → launch ready_set;
    run_started/run_failed(task) → flip that node;
    issue_state_changed(task, to_group=='completed') → node done + launch newly-ready;
    everything else → unchanged."""

Driver deltas (driver.py)

  • _graph_registry: dict[str, GraphState] (root_id-keyed) + get_graph(root_id); clear_registry() clears both dicts.
  • execute_graph(root_task_id, *, agent, spawn=None) → GraphState: load root (type=="task", else task_not_found); module via existing _module_id_for (else module_id_required); BFS descendants; no descendants → graph_empty; build+seed GraphState; feed execute_requested; apply each launch action.
  • Launch application mirrors _apply_launch_action: call async_to_sync(spawn or spawn_run) with phase="implement" semantics (initial_prompt=None, scope="task"); success → feed run_started for that task; exception → feed run_failed. Refactor to share with the single-task path rather than duplicating.
  • observe_issue_state_changed: after the existing single-task handling, scan _graph_registry for graphs whose nodes contain the task; feed the event through decide_graph; apply any launch actions. (Linear scan is fine; graphs are few.)

Test plan (new tests/test_graph.py pure + driver tests)

  • Pure: chain A→B→C: execute_requested launches only A; A's completion event releases exactly B; B's releases C. Diamond A→{B,C}→D: A completes → B and C launch together; D launches only after both complete.
  • Pure: pre-completed node at seed time is skipped and counts as a satisfied blocker; non-completed transitions and unknown tasks are ignored; launch order is sorted.
  • Driver: real Issue rows + blocked_by M2M; stub spawn records fan-out; seam completion of a blocker releases the dependent; graph_empty/task_not_found raise; re-invoke returns existing graph without new spawn calls.
  • Reuse both hazard guards (block-spawn conftest is automatic; copy the receiver-detach fixture into any new driver-level test module).

Acceptance

  • A root with a registered blocked_by chain launches its ready leaves in parallel and drains the chain purely off seam completions — verified in tests with mocked spawn, no tmux.
  • Single-task behavior (all 40 existing execution tests) unchanged.

#718 — Exec tracer 3: failure propagation + idempotency TO BUILD · second

A failed run must halt its transitive dependents while independent branches keep draining, and re-invoking an execution must never double-launch — even across a server restart. Ticket unrefined; this is the spec.

Settled design decisions

  • New node status "halted". When a node becomes failed, every transitive dependent (following edges outward) that is still idle flips to halted — pure graph computation inside decide_graph. Halted nodes never enter the ready-set. Independent branches are untouched.
  • Two failure signals: (a) run_failed (launch failure — already an event); (b) interim agent-failure signal: a node's task moving into the cancelled group marks the node failed. This is the same interim-WorkTracker-state convention the whole chain runs on until #744; record it in the ticket.
  • Durable idempotency record = existing rows, not a new model. No migration. The tracker is the durable completion record (group completed → done at seed). The agent_runs table is the durable launch record: before launching a node, if a live AgentRun exists for that task_id, adopt it (node → running with that run id) instead of launching. Verify the liveness predicate against the terminals session registry first — rows are created with status="running" and deleted on failed launches (launch.py:67); confirm what marks a finished run (check apps/terminals/session_registry.py + apps/runs/dao/lifecycle.py) and encode that as a single helper, e.g. _live_run_for(task_id).
  • Re-invoke semantics: execute_graph on a root with an existing in-memory graph re-seeds from the DB (tracker groups + live AgentRuns), then launches only nodes that are idle, ready, and have no live run. This replaces #717's return-unchanged stopgap and makes restart recovery work: after a process restart the registry is empty, and a re-invoke reconstructs reality instead of double-launching.

Test plan

  • Diamond A→{B,C}→D: B fails at launch → D is halted, C still launches and completes; graph reports failed=1 halted=1 done=….
  • Cancelled-group transition on a running node → node failed → dependents halted.
  • Re-invoke with a live AgentRun row for a node → zero new spawn calls for it; node adopted as running.
  • Restart simulation: clear_registry() + execute_graph() again → completed tasks seed done, live-run tasks adopt, only genuinely-new work launches.

Acceptance

  • Failure halts exactly the transitive dependents; independent branches drain to completion.
  • Double-invoke and restart-then-invoke produce zero duplicate launches, proven by spawn-call counting in tests.

#743 — Leaf-LLD generation phase TO BUILD · third

After #745's register agent has created the leaves in Todo, generate one split-level LLD per leaf. Wire the WorkTracker edge first (Housekeeping). Ticket is Backlog/unrefined; this is the spec.

Settled design decisions

  • New phase "lld" in Phase (state.py) + _lld_prompt() in recipes.py. The prompt: this leaf is a registered slice of an approved split; read the parent's approved HLD (parent spec dir) for context; write a split-level LLD as a visual HTML page in this leaf's spec dir per repo convention — exact changes, test plan, explicit out-of-scope; do NOT implement code, do NOT create tasks or edges; the leaf stays in Todo.
  • Gate: execute(phase="lld") requires the task's group to be unstarted — reuse the existing task_not_in_todo error.
  • Fan-out helper generate_leaf_llds(root_task_id, *, agent, spawn=None) → list[EngineState] in driver.py: for each non-archived type=task child of root in the unstarted group, skip children that already have an engine state in the registry (relaunch guard), then execute(child, phase="lld"). Launch failures are recorded per-child and do not stop the loop (unlike register's surface-and-halt — LLD generation per leaf is independent).
  • No machine completion gate. A written document is not a state move; like register, an lld run stays running. Durable "LLD written" tracking is #744's problem. Do not invent a marker-file watcher in this slice.
  • No automatic trigger from register. Register completion is deliberately not machine-observed (#745 decision), so #743 does not auto-fire; the trigger is the capstone (#721) or a manual call. Optionally extend the HTTP PlanningPhase literal with "lld" so #746's drawer can launch one leaf's LLD — small, safe delta.

Test plan

  • Recipe branch: prompt contains the leaf key/id, references the parent HLD, forbids code/tasks.
  • Fan-out: root with 3 Todo children + 1 Backlog child + 1 archived → exactly 3 launches; child with an active engine state skipped; one child's launch failure doesn't stop the others.

Acceptance

  • generate_leaf_llds(root) launches one lld run per eligible leaf, idempotently, with failures isolated per leaf.

Contracts quick-reference (post-#745)

The invariants the remaining slices build against — updated from the previous map where #745 changed them.

State machine (state.py / reducer.py)
Phaseimplement | refine | split | register (+lld in #743)
Statusidle | running | done | failed
Completionimplement→group completed · refine→backlog→unstarted · split→state name LLD · register/lld→none (stay running)

Split completion is transient: observe_issue_state_changed immediately launches register, and the task's registry entry becomes the register state. That overwrite is the relaunch guard.

Driver gates (driver.py execute())

task_not_found (not a task) · module_id_required · refine: group ≠ backlog → task_not_in_backlog · split: group ≠ unstarted → task_not_in_todo · register: state name ≠ LLD → task_not_in_lld. Registry is process-local; the seam only acts on registered tasks.

Seam (worktracker/signals.py)

Emits on state identity change, on commit, with from/to state ids + groups. Receivers must never synchronously mutate Issue.state. Still true: queryset .update(state=…) emits nothing (live instance at worktracker/services/workflow_config.py:193) — bulk moves bypass the engine.

Launch (terminals/launch.py)

async spawn_run(*, agent, project_id, module_id, task_id, initial_prompt=None, scope="task") → agent_run_id. No dedup — that's #718's job. Raises NoProfileSelected · ValueError · LaunchUnavailable; the driver folds any exception into run_failed.

HTTP (execution/api.py)

POST /work-items/{id}/planning-run {phase: refine|split, agent} → 201/409/404/422. #721 adds the execute-graph routes beside it.
