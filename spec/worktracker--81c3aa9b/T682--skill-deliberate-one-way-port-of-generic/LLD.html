Agent skills — deliberate one-way port of generic-relevant changes into generic WorkTracker

A shared, human-gated port procedure exposed as agent-native skills for Claude Code, Codex, and Agy/Antigravity. Each skill lives in the generic repo, surveys tracker work in a local sibling Muxed checkout, classifies generic-relevant vs Coding-overlay, reproduces the generic-relevant gaps adapted to generic's local APIs, and hands the working tree to a human to review and commit. Plus the doc rewrites that flip the governance model in both repos.

Deliverable A — agent-accessible skills (live in the generic repo)

port-from-coding for Claude, Codex, and Agy

  • One canonical procedure, mirrored into agent-native skill locations so Claude Code, Codex, and Agy can all invoke it.
  • Each skill is invoked manually from inside the generic repo. No network, clone, fetch, or CI.
  • Reads a local sibling Muxed checkout (read-only) to survey tracker features in worktracker-stack/.
  • Classifies each feature generic-relevant vs Coding-overlay using overlay knowledge embedded in the skill text.
  • Re-assesses generic's current state semantically each run — no ledger, no commit-walking.
  • Reproduces selected generic-relevant gaps by editing the generic working tree directly, adapted to generic's local APIs.
  • Stops at a human gate: proposes the port set + shows the working-tree diff; never commits, never merges sibling history.
Deliverable B — governance doc rewrite (both repos)

Flip the river, retire the subtree recipe

  • New model in both repos: Coding leads; generic trails; generic-relevant features flow up deliberately via these skills.
  • Neither repo is a git upstream of the other; independent releases, lockfiles, history; no automated/CI sync.
  • Retire the git subtree pull recipe in Coding's MAINTENANCE.md (added by #666/#678).
  • Resolve the live contradiction between Coding's #666 docs and generic's #664 docs.
  • The worktracker-stack/ directory and git history stay as-is — only the policy text changes; no history rewrite.
Explicitly out of scope (rejected at the grill)

Not built here

  • T631 slot/registry (region/action/route/service, typed context, Radix Slot) — deferred until generic has a named downstream consumer.
  • Bidirectional / two-way sync — would make each repo track the other as an upstream.
  • CI-driven / automated sync — no clone/fetch/compare of Muxed from CI.
  • Git plumbing — no subtree push/split, patch files, ledger, or commit-walking.
  • A shared package importing the classification into both repos — overlay knowledge is generic-side only, duplicated as skill text where each agent expects it.
  • Any reverse flow (generic → Coding) or generic → eventual-consumer assistance.
Transport & guardrails (the invariants)

How features move

  • Transport = the agent edits a generic working tree directly. No artifacts between the repos.
  • Sibling repo is touched read-only — file reads only; never its git history.
  • The only git the skill runs is on the generic repo's own working tree (status/diff) to present the proposal.
  • Reproduced features must keep the generic forbidden-symbol scan green — no overlay symbol may land.
  • Per-feature granularity; human decides the subset that lands and commits it.
