Shared WS wire-contract module; coding tab consumes it

Collapse the terminal transport into one Studio-shared module: a single WS client (reconnect/backoff + binary-bytes-vs-JSON-control routing) plus a single-source wire-contract that defines every frame. The coding tab is migrated to build all frames through it — no frame is hand-constructed anymore. A contract test asserts builder output against a backend-exported JSON Schema, so the CODIN-685 missing-mode bug class fails CI instead of production.

Scope lock

One transport, one frame definition, one consumer this slice. The change is a compatible wire change — mode becomes an explicit field the client sends and the backend dispatches on — with no user-visible behavior change.

  • In: a new shared module studio/src/lib/transport/ — the WS client (moved from ws.ts) + a wireContract.ts that is the only definition of init(spawn/attach) / ready / resize / scroll and exposes typed frame builders.
  • In: the coding tab migrates to build every frame through the builders; the copied studio/src/coding/lib/ws.ts is deleted and its importers repointed.
  • In: mode becomes an explicit wire field. Backend consumers.py dispatches on it (stops inferring from agent_run_id presence) and rejects inconsistent frames.
  • In: backend declares frame models, exports a committed JSON-Schema artifact, and a TS contract test diffs builder output against it — wired into contract:check.
  • Out (decision): REST DTOs. Terminal/WS REST families (B–F) aren't in the SDK yet (per #689); deferred to #668 / #687-5. contract:check still guards the already-covered SDK DTOs unchanged.
  • Out (decision): new transport behavior unit-tests — none exist to port; reconnect/backoff + binary-routing are preserved by a manual mid-session-disconnect check.
  • Out: #685's per-ticket pane (not built). It adopts this module later; #692 is not gated by it.

Wire contract — the single source of truth

wireContract.ts is the only place a frame is shaped. Every outbound frame is produced by a builder; nothing is constructed inline. The discriminant on init is the explicit mode field (new).

FrameDirectionBuilderShape (structural, schema-guarded)
init · spawnclient → server buildSpawnInit(params) { type:"init", mode:"spawn", agent, project_id, module_id, task_id, initial_prompt, cols, rows, is_planning, is_instant, instant_prompt, is_doc_chat, doc_rel_path, doc_id } — new: mode:"spawn".
init · attachclient → server buildAttachInit(agentRunId, cols, rows) { type:"init", mode:"attach", agent_run_id, cols, rows } — new: mode:"attach".
readyserver → client parseReady(json) (typed parser) { type:"ready", session_id, agent_run_id? } — unchanged.
resizeclient → server buildResize(cols, rows) { type:"resize", cols, rows } — unchanged.
scrollclient → server buildScroll(dir, lines) { type:"scroll", dir:"up"|"down", lines } — unchanged.
errorserver → client parseError(json) { type:"error", message } — unchanged.

Binary frames (raw PTY bytes) carry no JSON envelope; the client routes by event.data instanceof ArrayBuffer → onBytes, else parse-and-dispatch. That routing rule lives in the client and is preserved verbatim.

The wire-contract module owns frame structure only. Semantic rules (clamp cols/rows to 1–1000; the three spawn modes are mutually exclusive; doc-chat path-safety; task-id required unless planning/instant/doc-chat) remain imperative in consumers.py — they are not in the schema and not in the builders.

The mode discriminant — why this is the ticket

Today the backend never reads a client mode; it infers spawn vs attach from whether agent_run_id is a non-empty string, then injects mode internally. The client never sends it. That implicit coupling is exactly what drifted in #685. #692 makes mode explicit and authoritative on both sides.

Before — backend infers (current _validate_init):

agent_run_id = payload.get("agent_run_id") if isinstance(agent_run_id, str) and agent_run_id: # inject mode the client never sent return {"mode": "attach", ...} # else fall through → spawn return {"mode": "spawn", ...}

After — backend dispatches on the explicit field:

mode = payload.get("mode") if mode == "attach": if not _nonempty_str(payload.get("agent_run_id")): return None, "bad_init" # reject ... elif mode == "spawn": if payload.get("agent_run_id") is not None: return None, "bad_init" # reject mismatch ... else: return None, "bad_init" # unknown mode
Frame the client sendsBeforeAfter
mode:"attach" + valid agent_run_idattach (inferred)attach (dispatched)
mode:"spawn" + full spawn fieldsspawn (inferred)spawn (dispatched)
mode:"attach" but no agent_run_idsilently → spawn-validate → confusing errorrejected bad_init
mode:"spawn" but carries an agent_run_idsilently → attach (wrong branch)rejected bad_init
mode missing (the #685 bug)guessed by agent_run_idrejected + contract test fails CI
Compatibility: the live coding-tab client is migrated to send mode in the same change, so the stricter backend never sees a real legacy frame. No user-visible behavior changes — the same spawns and attaches succeed.

Contract test — mirroring contract:check

Same discipline already used for the REST SDK: the backend is the source of truth, it exports a committed artifact, and CI fails on drift. Here the artifact is a JSON Schema for the WS frames instead of openapi.json.

StepMechanism
1 · DeclareBackend frame shapes become declared models in server/terminals/frames.py (Pydantic / ninja schema). _validate_init validates structure from them, then applies the existing semantic rules.
2 · ExportA management command (export_wire_frames, alongside export_openapi) dumps JSON Schema to the committed artifact wire-frames.schema.json.
3 · Assert (drift)scripts/check-contract-drift.mjs re-exports the schema and diffs it against the committed copy — CI fails if backend frame shapes changed without regenerating. Advises npm run contract:generate.
4 · Assert (builders)A vitest test studio/src/test/wireContract.test.ts validates each builder's output against wire-frames.schema.json (via a JSON-Schema validator, e.g. ajv). The TS types and the backend schema cannot silently diverge.
5 · Prove teethThe test includes a case that strips mode from a builder's output and asserts schema validation fails — the executable proof that a dropped required field is caught.

The builders are the only frame source in TS, so step 4 transitively guarantees every frame the coding tab emits matches the backend's declared schema. Step 5 is the literal acceptance criterion rendered as a test.

Migration — replace, don't wrap

The coding tab currently imports the wholesale-copied coding/lib/ws.ts. Leaving a hand-built client beside the shared one re-opens the exact drift this ticket kills, so the copy is deleted and importers repointed.

  • Move the client logic from ws.ts into transport/terminalSocket.ts, swapping its inline frame literals for builder calls (buildSpawnInit / buildAttachInit / buildResize / buildScroll). The reconnect/backoff schedule (500ms base ×2, 10s cap, 8 attempts, 25% jitter) and the retry-only-if-everReady-and-agentRunId rule are preserved byte-for-byte.
  • The reconnect path rebuilds the attach init once an agent_run_id is known — that now flows through buildAttachInit, so the explicit mode:"attach" is present on reconnect too.
  • Repoint coding/panes/TerminalHost.tsx (and any other importer of the copied ws.ts) to @/lib/transport; delete coding/lib/ws.ts.
  • web/frontend/src/lib/ws.ts (the origin) stays untouched — it's retired wholesale later (#696/#697), out of scope here.
Riskiest edit: the backoff/retry path is rewritten with no regression test (a scoped-out decision). The manual validation step must exercise a real mid-session transport drop, not just a happy-path spawn.

Validation

  • Contract test studio/src/test/wireContract.test.ts: every builder validates against wire-frames.schema.json; the strip-mode case fails validation.
  • Drift gate: npm run contract:check re-exports the WS schema and fails on any uncommitted backend frame-shape change (now in addition to the OpenAPI/SDK diff).
  • Backend: consumers.py tests extended for the new dispatch — accept mode:"attach"/"spawn", reject the two mismatch cases and unknown/missing mode.
  • npm run -w studio typecheck & build green; no remaining importer of the deleted coding/lib/ws.ts.
  • Manual tracer: open Coding tab → spawn a terminal (bytes stream) → kill the socket mid-session (e.g. drop the network / restart the proxy) → confirm reconnect/backoff re-attaches and streaming resumes; then a clean exit closes terminally (no retry storm).

Acceptance signal

  • One shared transport module exists at studio/src/lib/transport/; the coding tab's terminal builds all frames through it.
  • wireContract.ts is the only definition of init/ready/resize/scroll; the client emits explicit mode.
  • Backend declares frame models, dispatches on mode, rejects inconsistent frames, and exports a committed wire-frames.schema.json.
  • A contract test fails when a required field (e.g. mode) is removed; the drift gate fails on un-regenerated backend changes.
  • Reconnect/backoff + binary-vs-control routing preserved (manual mid-session-disconnect check passes).
  • The old coding/lib/ws.ts is deleted with no remaining importers; no behavior change visible to the user.
