# Sprint mapping generation adaptation

- Exact missing behavior: SQLite declares sprint timestamps as `datetime`, which the pinned SeaORM CLI emits as ignored custom string columns; generated relationship names also differ from the established GraphQL names. Seaography rc.9 applies compound ordering in entity column order, so database column order would put ID ahead of rank.
- Rejected facilities: changing stored timestamp encoding or public relation names would expand the change beyond sprint ordering. Input object ordering does not override rc.9's `Column::iter` ordering.
- Smallest seam: `sprint-entity-generation.mjs` adapts CLI output from the sprint migrations, maps datetime columns, keeps existing relation names, removes the CLI's unconditional uniqueness inferred from the partial active-sprint index, and places rank before ID. Existing lifecycle validation lives separately in `sprint_behavior.rs`; generated output contains no lifecycle implementation.
- Drift prevention: `verify-generated.mjs` regenerates the sprint mapping twice from the migration-backed database and compares both with the checked-in entity. GraphQL sprint-choice tests cover rank as the primary sort and ID as the tie-break.
- SQLite migration adaptation: bundled SQLite 3.51 cannot set a column's `NOT NULL` constraint after backfill. The migration backfills a nullable column, copies it into a non-null replacement column and renames that column inside the same transaction. This leaves all inbound sprint references intact and retains the empty-string default used by existing rank storage. Migration-chain acceptance checks canonical ranks, non-null metadata, NULL rejection and preservation of issue membership and goals.
