Resize mechanics

A pointer-driven left-edge handle. Click a step for its exact mechanics and edge cases. Width is right-anchored: the drawer's right edge is pinned, so widening pulls the left edge (and the handle) leftward toward the nav.
Click a numbered step.

Clamp formula. clamp(w) = max(MIN, min(w, maxAvail)) where MIN = 760 and maxAvail = window.innerWidth − navWidth − GAP, with navWidth = uiStore.navCollapsed ? 64 : 232 (the live NavDrawer widths) and a small GAP so the nav edge always stays visible. Live width during a move is computed as clamp(window.innerWidth − e.clientX). The clamp runs again on every open so a width stored on a wide monitor shrinks gracefully on a narrow one.

Width state contract — uiStore

Modeled exactly on the existing navCollapsed / groupByEpic pattern in uiStore.ts: a plain field seeded from localStorage by a read-helper, plus one setter that writes through. No persist middleware, no new dependency.
fielddrawerWidth: number — current drawer width in px. Lives in UiState next to drawerKey.
seedreadDrawerWidth() reads studio.drawerWidth from localStorage, parses an int, falls back to DEFAULT_DRAWER_WIDTH = 760 on missing / NaN / thrown (private-mode) — mirrors readNavCollapsed().
settersetDrawerWidth(px) clamps against the live viewport + nav width, sets state, and best-effort writes localStorage.setItem("studio.drawerWidth", String(px)) inside try/catch. The only mutation path.
keyDRAWER_WIDTH_KEY = "studio.drawerWidth" — a sibling of NAV_COLLAPSED_KEY / GROUP_BY_EPIC_KEY.
consumerIssueDrawerHost reads drawerWidth and renders the aside with style={{ width }}, replacing the w-[min(760px,82%)] class. The handle calls setDrawerWidth on release; live drag updates a local ref/state for smoothness, committing to the store on pointerup.
unchangeddrawerKey, openDrawer, closeDrawer and all nav/board/palette state are byte-for-byte unchanged.

Why store-level, not component-local: persistence must survive unmount (the drawer is mounted/unmounted by route), and CODIN-703's later subtasks read the same width when the drawer hosts terminals/iframes. Putting it in uiStore keeps one source of truth and matches the existing convention.
