Module shape — five symbols in one new file

Everything lives in worktracker/worktracker/signals.py. It imports Issue from models and state_group from the already-relocated state_groups (prefactor #705, DONE). It is import-side-effect-only: importing the module connects every receiver via @receiver decorators.
NEW · the signal

issue_state_changed

A bare django.dispatch.Signal() instance at module top. No providing_args (removed in modern Django). The seam every future consumer connects to.

sent with sender=Issue and the six payload kwargs
NEW · snapshot

_snapshot_old_state (pre_save)

Receiver on pre_save, sender=Issue. Reads the pre-write state_id straight from the table — Issue.objects.filter(pk=instance.pk).values_list("state_id", flat=True).first() — and stashes it on instance._old_state_id.

On create the row does not exist yet, so the query returns None → from_state_id = null, exactly as required.

NEW · decide + defer

_emit_on_state_change (post_save)

Receiver on post_save, sender=Issue. Compares instance._old_state_id to instance.state_id. If equal → return (no-op / non-state save). If different → resolve from_group/to_group via state_group() now, capture the full payload in a closure, and register it with transaction.on_commit(...).

NEW · v1 receiver

_log_state_change

Receiver on issue_state_changed. Logs issue_id + from_group → to_group at INFO via a module logging.getLogger(__name__). Docstring states the re-entry contract: receivers must not synchronously mutate Issue.state.

MODIFIED · wiring

WorktrackerConfig.ready()

No ready() exists today. Add one whose only body is from worktracker import signals # noqa: F401. INSTALLED_APPS = ["worktracker"] auto-discovers this single AppConfig, so the import (and thus all receiver connections) runs once at app load.

REUSED · no change

state_groups.state_group

Resolves a state_id → group by a fresh .only("group") read, returning None for falsy/unknown ids. Router-free import (the whole reason for prefactor #705). Used for both from_group and to_group. Unchanged.

Decision trace

The choices that make this plan decision-complete. Click a row to highlight the affected sequence step.
IDDecisionRationale
D1Snapshot old state_id via a DB read in pre_save, not via an in-memory tracking field on the model.Zero model/migration change. The pre-write row still holds the old id; on create the query naturally returns None. Avoids stale-FK-cache pitfalls (same reason state_group reads fresh).
D2Detect change on state_id identity, not on group.AC: a within-group state move (e.g. two unstarted states) is still a transition and must emit; a same-id re-save must not.
D3Resolve groups in post_save, capture payload in the on_commit closure.Group lookup happens once, inside the txn; the deferred send carries frozen values. Keeps the receiver dumb and the send-site allocation-free at commit.
D4Dispatch via transaction.on_commit.Rolled-back transitions never emit (AC). In autocommit (no open txn) Django runs the callback immediately — correct for raw .save() outside a request.
D5No type filter — tasks and modules (epics) both emit.HLD requires epics in scope; consumers self-filter on payload. One chokepoint, no per-type branching.
D6v1 ships exactly one receiver, logging only; re-entry contract in its docstring.Pure seam — orchestration (#700) hangs off it later. Docstring forbids synchronous Issue.state mutation to prevent post_save recursion.
D7Wire receivers by importing signals from AppConfig.ready().Canonical Django pattern; the single auto-discovered WorktrackerConfig guarantees one-time connection at app load.
D8.update(state=…) in delete_state is a known gap, left as-is.Queryset update bypasses model save by design (bulk SQL). It is config cleanup, not a transition. Documented in code + pinned by a 0-event test rather than fixed.

Acceptance signal

Done when —
  • State change through any patch_work_item path fires issue_state_changed exactly once with correct from_group/to_group.
  • Creating an issue into a state fires one event with from_state_id=null; a non-state or same-state save fires none.
  • A rolled-back transaction emits nothing (on_commit semantics, proven under the capture fixture).
  • The single v1 receiver is invoked with the structured payload and logs the transition.
  • .update(state=…) fires no event — locked in by the gap test.
  • Full suite green; no user-visible behavior change.
