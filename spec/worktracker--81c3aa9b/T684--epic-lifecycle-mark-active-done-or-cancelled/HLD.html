Epic Lifecycle — active epics stay visible, closed epics leave active views

Epics are module rows today. This design gives them their own lifecycle affordance without changing story states: mark an epic not started, in progress, done, or cancelled; hide done/cancelled epics from active planning surfaces by default; keep a deliberate way to review closed epics.

The feature in three pieces

Click a card to expand the boundary. The important rule: epic lifecycle never mutates child story states.

P1 · DATA CONTRACT

Lifecycle on epics

Expose lifecycle on `ModuleOut` and `ModulePatch`: not started, in progress, done, cancelled.

  • Migration adds a project-safe module lifecycle value, or reuses `Issue.state` for type=module with the same external enum.
  • `list_modules` hides closed epics by default and supports an include-closed mode.
  • Changing an epic status does not cascade to stories or sub-tasks.
P2 · ACTIVE SURFACES

Hide closed epics

Backlog rail, board lanes, story map columns, planning filters, and parent pickers use the same visible epic set.

  • Active views default to not started + in progress epics.
  • Done/cancelled epics no longer occupy rails, columns, lanes, or dropdown space by default.
  • Stories under a closed epic are not deleted; they can still be found by direct issue search/detail.
P3 · AFFORDANCE

Mark and review

Users can mark lifecycle from the epic rail/header and temporarily show closed epics when needed.

  • Epic rail entries show a compact lifecycle badge and action menu.
  • Closed-epics toggle reveals done/cancelled epics with subdued styling.
  • Creation defaults new epics to not started; first visible transition is in progress.
