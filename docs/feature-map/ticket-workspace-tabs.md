# Ticket workspace tabs

A selected ticket presents Details, document and terminal surfaces with durable ordering, remembered targets and a dormant-tab menu.

Surfaces: browser, desktop
Editions: pocock, core

## Sub-features

- ticket-tabs-surfaces: select Details, document or terminal tabs without recreating retained viewers.
- ticket-tabs-dormant: reopen closed documents, resume eligible conversations and inspect terminated history.
- ticket-tabs-order: drag mixed tab identities using near/far drop seams and persist the order per work item.
- ticket-tabs-keyboard: navigate the visible tab sequence, highlight and engage bodies, and close eligible tabs.
- ticket-tabs-restoration: restore remembered document paths or durable run identities without overriding newer navigation.

## How to get to it

Select a Story from Stories, then use the tablist **Workspace tabs** (`workspace-tabs`). **Details** is the ticket surface; documents use their labels (for example **DESIGN**) and terminals use provider/run presentation names (for example **codex terminal**). Documents are supplied by the document registry; use the entry in [Descriptions and documents](descriptions-and-documents.md). The issue-actions menu's **Open terminal**, **Run item** or the workspace Agent launcher can supply a terminal; provider execution belongs to the agents campaign. **Open terminal** launches the Work Item's own login shell (scope `shell`, bound to the Work Item); it appears as the **shell terminal** tab beside agent terminals, while a module shell (scratch task id) stays in the [Module terminal panel](module-terminal-panel.md). Source: `isWorkItemShellRun` in `studio/src/features/agents/status/runScopes.ts`, consumed by `studio/src/features/agents/terminal/runTabRestoration.ts` and the terminal session store. Source: `studio/src/features/task-workspace/internal/WorkspaceTabStrip.tsx` and `studio/src/app/shell/ticket-workspace/selected-ticket/details/IssueActionsMenu.tsx`.

Use **Dormant tabs (N)** (`dormant-tabs-trigger`) at the strip's right end. Its **Dormant tabs** menu offers **Reopen <document label>**, **Resume <terminal accessible name>** and disabled **Terminated <terminal accessible name>** entries. Escape dismisses and returns focus to the trigger; Up/Down cycle enabled menu buttons. Source: `studio/src/features/task-workspace/internal/DormantWorkspaceTabs.tsx`.

Default capture actions `workspace-tab-next` / `workspace-tab-previous` use Cmd+Right / Cmd+Left. In edit view, `edit-view.next-zone` (Shift+Tab) reaches the tab strip; `edit-view.right` / `edit-view.left` highlight tabs and `edit-view.commit` (Enter) activates the highlight. The body can then be engaged with Enter and disengaged with Cmd+Escape. `close-tab` is fixed Cmd+W, with configurable global Q as another default. See [Keyboard navigation and shortcuts](keyboard-navigation-and-shortcuts.md) and `studio/src/app/navigation/keymapBindings.ts`.

## Prerequisites

- A selected work-item bucket; the empty public workspace component renders **No task selected**, while the Studio host collapses its unselected ticket pane; an empty module visibly reports **0 of 0 stories** with no workspace tab strip. Conversations can be terminal-only and omit Details/documents, so use an ordinary Story for mixed-tab verification.
- Registered documents and an existing disposable terminal/run for the corresponding tabs. A resumable conversation requires server-reported resumability; terminated history is not a resume action.
- A hydrated WorkItem and authoritative saved order before drag reorder is enabled. Scratch buckets without a WorkItem identity cannot save this order.
- Test terminal closure with disposable runs: closing a persisted terminal invokes termination, while closing a document changes presentation.

## Expected behavior

- **Selection and empty:** default visible order is Details, available documents and terminals, projected through saved precedence. Unavailable terminal selection or an empty open-document set falls back to Details; an absent selected document ID can project the first open document. Remembered-path restoration separately repairs an authoritatively missing document to Details. Conversation-only presentation shows its terminals. The selected tab exposes `aria-selected`; the strip scrolls the active tab into view. Details and document viewers retain mounted lifetimes across tab changes, and the terminal host stays mounted with visibility control. Source: `studio/src/features/task-workspace/internal/useWorkspaceTabPresentation.ts`, `studio/src/features/task-workspace/internal/WorkspaceTabBody.tsx` and `studio/src/features/task-workspace/TaskWorkspace.tsx`.
- **Close/reopen:** closing hides a document and retains it for **Reopen**. Closing the active document remembers Details for later restoration; the current projection can select the first remaining open document, otherwise Details. Closing a persisted terminal waits for termination; refusal produces **Terminal could not be closed:** feedback. A successful close can separately report a resumable-history refresh failure. Remaining-terminal selection and remembered run identity are repaired; history remains available. Source: `studio/src/features/task-workspace/internal/useWorkspaceTabActions.ts` and `studio/src/features/task-workspace/internal/closeTerminalTab.ts`.
- **Dormant/cancel/error:** no dormant trigger appears when its count is zero. Reopening selects the document. Resume disables the pending row, deduplicates repeat requests and retains a successful successor even if newer navigation prevents its selection. Failures keep the source retryable and show specific missing-directory, still-active or unsupported-resume feedback, or **Could not resume session**. Escape/outside dismissal performs no resume or document reopen. History is noninteractive. Source: `studio/src/features/task-workspace/internal/DormantWorkspaceTabs.tsx` and `studio/src/features/task-workspace/internal/useWorkspaceTabActions.ts`.
- **Drag:** any eligible visible tab, including Details, can move before/after another. `workspace-tab-drop-seam` exposes `data-drop-intent="near"` or `"far"`. Escape cancels; self/no-op drops do not save. Pending or unhydrated orders disable drag. The drag's trailing pointer click is consumed, while a fresh gesture can select immediately. A failed save rolls the optimistic order back and reports **Workspace tabs could not be reordered:**. Known dormant identities retain their positions; new visible identities append without undoing a queued reorder. Source: `studio/src/features/workspace-tabs/internal/useWorkspaceTabReorderDrag.ts`, `studio/src/features/workspace-tabs/ordering.ts` and `studio/src/features/workspace-tabs/mutations.ts`.
- **Keyboard:** Cmd+arrows select in the actual visible order and clamp at the edges; the left-edge host may return to Stories. Typing editors retain their arrows, including Cmd+Left/Right line movement, while xterm capture and modal workspace ownership route a single accepted event to one workspace. Because engagement is global, a Cmd+arrow arrival on a document while the body is engaged (for example from a terminal) disengages and lands in navigation mode on the tab body, so the next Cmd+arrow continues; Enter engages the editor. Highlighting in edit view differs from body engagement. Source: `studio/src/features/task-workspace/internal/useTaskWorkspaceTabNavigation.ts`, `studio/src/features/task-workspace/internal/useTaskWorkspace.ts` and `studio/src/features/task-workspace/internal/useWorkspaceTabFocus.ts`.
- **Persistence:** tab order writes through the restricted WorkItem update and returns authoritative `workspace_tab_order`, using durable agent-run IDs when available; temporary viewer identities must be checked again after durable rekey. Read that WorkItem from the server, reload, reselect the Story and verify the visible order; verify a second Story's order independently. The active target is separately remembered locally by bucket as Details, document path or agent-run ID, then reconciled with authoritative documents/runs. Failed document hydration preserves intent; a successful read proving it missing repairs to Details. An old response must not replace a newer Story/Details selection. Each retained presentation reentry (for example `workspaceActive` false → true when a configuration overlay closes) issues a fresh restoration request that an already-hydrated remembered document settles from its unchanged documents, so the document stays selected and its retained frame regains authorized focus; stale async completions from the previous entry stay invalidated (CODING-2905). Closed-document flags are client presentation state; do not infer server persistence of those flags from order persistence. Source: `studio/src/features/workspace-tabs/mutations.ts`, `studio/src/features/workspace-state/studioWorkspaceTarget.ts`, `studio/src/features/workspace-state/workspaceTabs.ts` and `studio/src/features/task-workspace/internal/useStudioWorkspaceRestoration.ts`.

## Gotchas

- These are ticket tabs, distinct from project module tabs. **Changes** now opens an independent workspace in Studio; legacy Changes identities are stripped from durable order and remembered targets migrate to Details. Do not require a persistent ticket-local Changes tab.
- Ordering is server data; remembered active target and closed-document visibility are separate client preferences. A DOM remount over a mock is not a server reload round trip.
- Conversation workspaces are terminal-only. The old **Local scratch** row is not a reliable current production entry; current scratch-document reachability is unverified (see the document entry).
- Native libghostty requires desktop evidence. Browser xterm and mocked native focus/close messages do not establish installed rendering, viewport geometry or run retention.
- Saved keymap overrides can change configurable chords. Modal and typing ownership can suppress routes; tab selection alone does not mean terminal input is engaged.
- The [keyboard reference](../../studio/KEYBOARD_NAVIGATION_CURRENT.md) retains retired sidebar wording. Source and current acceptance files govern navigation here.
