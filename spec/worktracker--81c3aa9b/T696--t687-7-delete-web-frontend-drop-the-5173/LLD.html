Decisions resolved for implementation

The refinement left two genuinely open choices. Both are resolved here so the slice is decision-complete.
QuestionDecisionWhy
Deep-link replacement target: in-app /coding root, per-issue /coding/issues/:key, or remove the trigger? Navigate in-app to the project's coding surface root /projects/:projectId/coding; keep the button + w shortcut. Matches the agreed scope ("in-app /coding"). The mounted coding surface's internal per-issue routing belongs to #691 (still unmerged), so a per-issue path would couple this ticket to unfinished internals. Root nav keeps the affordance, drops the external tab, and stays decoupled. A per-issue deep-link is a clean later enhancement once #691's internal router is settled.
Fate of codingBridge.ts after openInCodingApp / codingAppUrl are removed? Slim it to a pure path builder (e.g. codingSurfacePath(projectId)); navigation moves to the call sites via react-router useNavigate. Keeps one testable seam instead of duplicating a path string across two call sites; lets codingBridge.test.ts survive as a rewritten pure-function test (no :5173). The hook/component own useNavigate because it cannot live in a plain module.
Source of projectId at the call sites? Read the active project id from useStudioStore. The issue drawer is project-scoped — the drawer's issue belongs to the active project, so the active id is the correct target. No new prop threading.
