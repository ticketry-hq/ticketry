Generate leaf LLDs for an approved split — the lld phase

Add a fifth phase lld to the process-local execution tracer (apps/execution). After #745's register agent has created the split-tree leaves in Todo, a new fan-out helper generate_leaf_llds(root) launches one leaf-LLD agent run per eligible leaf. Each run reads the parent's approved HLD and writes a split-level visual LLD into that leaf's own spec dir — no code, no tasks, no edges. Like register, an lld run has no machine completion gate: a written document is not a state move, so the engine leaves it running (durable "LLD written" tracking is #744). This is a thin, additive change: one new phase string, one new recipe, one new gate, one new driver helper — reusing the existing execute() launch path wholesale. No models, no migration, no endpoints, no frontend.

The flow: generate_leaf_llds(root) fans execute(child, phase="lld") across eligible leaves

Unlike register, #743 has no automatic trigger: register completion is deliberately not machine-observed (#745), so leaf-LLD generation is fired explicitly (the capstone #721 or a manual call). The helper enumerates the root's direct type=task children, keeps only non-archived leaves in the Todo (unstarted) group, skips any that already carry an EngineState (relaunch guard), and calls execute(child, phase="lld") for each. Each launch is independent — a per-leaf failure is recorded and the loop continues. Click a node for its mechanics and edge cases.

Driver contract — the lld gate and generate_leaf_llds

#743 does not touch the pure reducer: lld is absent from _is_complete, so it inherits register's "never auto-done, stays running" behavior for free. All new logic is in the driver — one gate line in execute() and one fan-out helper.
PHASE VOCAB
Phase = Literal["implement","refine","split","register","lld"] in state.py. Adding the string is the whole type change; EngineState.phase and LaunchAction.recipe widen for free.
EXECUTE GATE
In execute(), after the register gate: if phase == "lld" and state_group(issue.state_id) != "unstarted": raise ValueError("task_not_in_todo"). Reuses the same error string as the split gate — a leaf-LLD run is valid only for a Todo leaf.
FAN-OUT HELPER
generate_leaf_llds(root_task_id, *, agent, spawn=None) → list[EngineState]. Loads the root (type=task else task_not_found); enumerates direct non-archived type=task children ordered by (sequence_id, id); for each, skips non-unstarted children and any already in _registry; otherwise calls execute(child, phase="lld", spawn=spawn) and appends the result.
RELAUNCH GUARD
if _registry.get(str(child.id)) is not None: continue. A leaf that already has an engine state (a prior LLD run, or any other phase) is not relaunched. Idempotent per process for the common "call twice" case.
FAILURE ISOLATION
Unlike register's surface-and-halt, each leaf is independent. execute() already folds a spawn exception into a failed EngineState (it does not raise), so a launch failure is returned in the list and the loop proceeds. A gate ValueError (would be rare given pre-filtering) is caught, logged, and skipped so one bad leaf never aborts the fan-out.
NO COMPLETION GATE
lld is intentionally absent from reducer._is_complete. A written HTML document is not a state transition, so no issue_state_changed flips the run to done — the run stays running. Durable "LLD written" tracking is #744; no marker-file watcher is invented here.
UNCHANGED
The reducer, the graph engine, observe_issue_state_changed, the seam, and the HTTP API are untouched. The execute-graph/generate-leaf-llds HTTP routes and the drawer/MCP surfaces belong to #721.
