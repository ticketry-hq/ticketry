This document is that rewrite — it replaces the catch-up-merge text that was still on disk.

Steady-state — pulling generic work down

The re-point's whole payoff: with the shared base in place, syncing future generic work is one command + a mechanical overlay re-apply. This is the recipe the rewritten MAINTENANCE.md carries.
PULLgit subtree pull --prefix=worktracker-stack ../worktracker <ref> -m "chore: subtree pull generic" — run from the Muxed root with a clean tree. Only the post-base upstream delta merges in.
CONFLICTSLand only on the SHARED files above. Resolve deterministically: keep the generic (incoming) body, re-add the Coding hunk. The overlay is fixed and small — re-applying it is mechanical, not judgement.
VERIFYRun the forbidden-symbol scan in both repos (non-empty here, empty upstream), then the green gates: npm run typecheck, npm run test --workspace @worktracker/studio, (cd studio && npx vite build).
AUTHORINGGeneric features → authored upstream in ../worktracker, then pulled. Overlay behaviour → authored here, kept inside the inventory. Never the reverse — a generic feature added only here is lost on the next pull.
SPEC/Coding's spec/ design history lives inside the prefix but is downstream-only; upstream carries no spec/ there, so it never participates in a pull.
