Merge Muxed-core into the Muxed-server package

Fold the standalone core/ distribution into server/, decomposed by function into the consuming apps and the studio_server composition package. A pure packaging + import-path move: zero behavior change, loopback HTTP preserved as-is (its removal is #738). worktracker_gateway is NOT created — #739 rejected the WorkTracker/WorkTracker bridge premise: WorkTracker is the owned backend, so the former config/DTO/worktracker_client cluster lands in studio_server named for its WorkTracker-adapter responsibility, not as a swappable-backend bridge. Grounded in the 20 live import sites and the real core/core/* dependency graph.

1 · Objective

Retire the separately-installed Muxed-core distribution by relocating its modules into their real consumers and the studio_server composition package, with a clean break (no compatibility shim) since there are no external consumers.
  • By function, not wholesale. The launcher goes to terminals (its sole consumer), the design-doc path contract to documents, and the tracker-backend integration cluster (config + DTOs + adapter) into the studio_server composition package — its consumers span 4 apps, no single existing app owns it, and #739 forbids a dedicated bridge package.
  • Zero behavior change. Loopback HTTP, SDK calls, agent-launch command strings, and design-doc paths are byte-identical. The only thing that disappears is the core distribution.
  • No backend switchability (#739). WorkTracker is the owned backend. The relocated adapter/config/DTOs are named and placed for the WorkTracker-adapter responsibility, NOT to keep WorkTracker swappable. worktracker_gateway is not created — no package, no INSTALLED_APPS entry, no worktracker_gateway* discovery glob, no backend selector. A regression check fails if a worktracker_gateway package or import reappears.
  • Out of scope: removing the loopback → #738; the bridge-rejection decision itself → #739 (locked); the framework-neutral service-error contract → #735; WorkTrackerRepository / profile cleanup → #741; any DTO/route/behavior change.
