Decomposes `SettingsView.tsx` into a modular tree inside `studio/src/shell/settings/`. Simplifies a 516-line file mixing type config, state config, inline drag-and-drop, swatches, modals, forms, and route routing.

Why Decompose

The current `SettingsView.tsx` combines multiple responsibilities in a single flat file. Breaking it down ensures single responsibility and easier maintenance.
Responsibility Today Issues / Costs Decomposed Solution
Container Router Wiring Loaded settings verification and loading states are mixed with UI layouts. Keep SettingsView.tsx strictly as a container/loader.
Issue Type Panel Direct dependency on drag reorder, dialog triggers, and defaults logic. Extract to IssueTypesPanel.tsx.
Workflow State Panel Complex logic determining if a state is last-in-group or deletable. Extract to WorkflowStatesPanel.tsx.
Config Row & Add Row atlaskit pragmatic drag-and-drop bindings mixed inside the same file. Extract reusable ConfigRow.tsx and AddRow.tsx components.
Helpers & SWATCHES Large chunks of constants and arrays occupy top-level lines of code. Extract to settingsUtils.ts.

      Proposed File Tree Change-Map

      How the files will be laid out inside the directory. New files are marked green; the original SettingsView file will be significantly smaller and is marked amber.
      studio/src/shell/
        ├── SettingsView.tsx (simplified)
        └── settings/ (new subdirectory)
            ├── settingsUtils.ts
            ├── ConfigRow.tsx
            ├── AddRow.tsx
            ├── IssueTypesPanel.tsx
            └── WorkflowStatesPanel.tsx
      • SettingsView.tsx drops from 516 lines to ~50 lines, focused solely on project context check and section layout.
      • settingsUtils.ts hosts shared types, reorderAcross, SWATCHES, LEVELS, and GROUP_LABEL.
      • ConfigRow.tsx isolates Atlaskit drag-and-drop bindings.
      • AddRow.tsx houses the state and logic for typing / submitting inline additions.
