Library exploration — why these three, and the road not taken

The job splits into three roles: parse markdown → HTML, convert stored HTML → markdown, and sanitize before render. The chokepoint module — lib/markdown.ts

The only place marked, turndown, and dompurify are imported. Three pure functions; every render — read view and Preview tab — passes through one sanitize call, so there is exactly one trust boundary.
toHtml(md: string): string

marked-parses markdown → HTML, then sanitizes the result. Used on Save (the value handed to patchField) and in the Preview tab. Synchronous — async: false so the return is a string, not a Promise.

toMarkdown(html: string | null): string

turndown-converts stored description_html → markdown to seed the textarea when the editor opens. Best-effort / lossy by design; null or "" → "". Legacy hand-HTML or plain-text descriptions convert approximately on first edit.

sanitize(html: string): string

Bare DOMPurify pass against the explicit allow-list (§ Config). Exported and called directly by the read view before dangerouslySetInnerHTML — the line that fixes today's unsanitized render. toHtml reuses it internally.

// studio/src/lib/markdown.ts — the whole module (~30 lines) import { marked } from "marked"; import TurndownService from "turndown"; import DOMPurify from "isomorphic-dompurify"; const ALLOWED_TAGS = ["p","br","strong","em","b","i","s","h1","h2","h3","ul","ol","li","a","code","pre","blockquote","hr"]; const ALLOWED_ATTR = ["href","target","rel"]; // Force external-link safety on every sanitized anchor (idempotent global hook). DOMPurify.addHook("afterSanitizeAttributes", (node) => { if (node.tagName === "A") { node.setAttribute("target", "_blank"); node.setAttribute("rel", "noopener noreferrer"); } }); const turndown = new TurndownService({ headingStyle: "atx", bulletListMarker: "-", codeBlockStyle: "fenced" }); export function sanitize(html) { return DOMPurify.sanitize(html, { ALLOWED_TAGS, ALLOWED_ATTR }); } export function toHtml(md) { return sanitize(marked.parse(md, { gfm: false, breaks: true, async: false })); } export function toMarkdown(html) { return html ? turndown.turndown(html) : ""; }

Q1 resolved — marked config & the sanitizer allow-list

Basic CommonMark-ish, GFM off. The allow-list is the contract: anything outside it is stripped, so a stored <script> or onerror= never reaches the DOM.
KnobValueWhy
marked.gfmfalseScope is basic CommonMark — no tables / checkboxes / autolink / strikethrough-by-tilde surprises.
marked.breakstrueA single newline in the textarea becomes <br> — matches what a non-markdown user expects from a plain text box.
marked.asyncfalseGuarantees a synchronous string return; keeps toHtml usable inline in render.
ALLOWED_TAGSp, br, strong, em, b, i, s, h1–h3, ul, ol, li, a, code, pre, blockquote, hrExactly the tags the basic toolbar + marked can emit. Headings capped at h3 (drawer context). No img/iframe/table/style.
ALLOWED_ATTRhref, target, relOnly links carry attributes. No style, class, or on* handlers (DOMPurify drops event handlers regardless).
Link scheme safetyjavascript: / data: blockedDOMPurify's built-in URI policy rejects dangerous schemes on href by default — no extra config.
Link hardeningtarget=_blank rel=noopener noreferrerThe afterSanitizeAttributes hook forces it on every anchor — safe external nav, no reverse-tabnabbing.
turndown optionsatx headings · "-" bullets · fenced codeRound-trips cleanly with the markdown the toolbar produces, so edit → save → re-edit is stable for tool-authored content.

Q2 resolved — toolbar insertion mechanics

Two primitives over the textarea's selectionStart/selectionEnd. Every button is a thin call to one of them; an empty selection inserts a selectable placeholder so the next keystroke replaces it. No window.prompt — links use an inline (url) placeholder.

B I </>  wrap — surround(pre, suf, ph)

Bold **…** · Italic *…* · Code `…`. Selection present → wrap it, keep it selected. Empty → insert pre+ph+suf and select ph (e.g. "bold text").

H • —  line-prefix — linePrefix(token)

Heading "## " · Bullet list "- ". Prepends the token to the start of each line the selection touches. Cursor lands after the inserted token.

🔗  link — surround("[", "](url)")

Wraps the selection as [text](url) and selects the literal url so the user types the destination immediately. Empty selection → [text](url) with text selected first.

cursor restoration

Each primitive sets value via React state, then restores selectionStart/End on the textarea ref in a useLayoutEffect keyed by a pending-selection ref — so React's re-render never clobbers the caret.

Keyboard, on the textarea (mirrors NameEditor): ⌘/Ctrl+B bold · ⌘/Ctrl+I italic · ⌘/Ctrl+Enter Save · Esc Cancel. The toolbar renders only on the Edit tab; Preview has no toolbar.

Decisions resolved at LLD

The HLD left three questions to settle here. All resolved; none changes the HLD shape.
Q1 · RESOLVED — config & allow-list

marked basic CommonMark; explicit DOMPurify tag/attr allow-list

gfm:false, breaks:true, async:false. Tags limited to the basic set (h-levels capped at h3); attrs to href/target/rel; links forced to target=_blank rel="noopener noreferrer" and dangerous schemes blocked by DOMPurify defaults. Full table in § Config.

Q2 · RESOLVED — insertion mechanics

Two primitives: wrap & line-prefix; inline link placeholder

Empty selection inserts a selectable placeholder ("bold text", url) so the next keystroke replaces it; non-empty wraps and keeps selection. Caret restored via useLayoutEffect + ref. No window.prompt. Detail in § Toolbar.

Q3 · RESOLVED — bundle handling

Eager import; ~45 KB gzip added; revisit only if build warns

marked + turndown + dompurify add roughly ~45 KB gzip — small against the existing @atlaskit DnD + fontsource deps. Import eagerly in lib/markdown.ts; Vite optimizeDeps picks them up. Lazy-loading the editor chunk is deferred — adopted only if vite build flags the chunk-size budget.
