The boardSwimlanes() selector

A pure function beside boardColumns() — same item set, re-bucketed by (lane × state). The board renders only what it returns. owningEpic() is lifted to a module-level helper so both selectors share one walk-to-ancestor implementation.
SIGNATUREboardSwimlanes(items, states, modules, filters) → { columns: (State | null)[]; lanes: SwimLane[] }
UNIFORM COLUMNSComputed once across all visible items: a leading null "No State" column only when some visible item is stateless/unknown, then the real states sorted by groupRank(group). The same array drives the sticky header strip and every lane's cells, so columns align.
LANE = SwimLane{ epic: Module | null; cells: WorkItem[][]; done; total } — cells is parallel to columns (same length/order); each cell is rank-sorted via compareRank (#626).
LANE MEMBERSHIPAn item belongs to lane owningEpic(item) — walk parent_id to the first module ancestor (cycle-guarded), else the No-epic lane. Sub-tasks roll up to their story's ancestor epic for free.
LANE SETOne lane per module in module order; trailing No-epic lane. When filters.epicIds is set, only selected epics' lanes render (+ No-epic if NO_EPIC ∈ selection) — the exact same gating groupBacklog uses.
VISIBILITYReuses boardColumns' predicates: honors the epic + sprint filters, drops sub-tasks when showSubtasks === false, and ignores the state filter (state is the column axis).
PROGRESSPer lane: total = visible cards in the lane, done = those with state.group === "completed" — the Backlog group-header vocab, scoped to what the board shows.

Precedent: a single global rank ordered within a 2-D bucket is exactly how buildStoryMap already fills its (epic × sprint) cells. rank stays one global field per item (#626) — swimlanes only change which neighbors a reorder compares against.

Drop decision — three branches

A drop target (column body or card) lives in a lane and always passes that lane's epic id to the store. The store — which has the full item list — decides reparent vs state-only. Click a node.

The extended dropOnBoard contract

One added optional argument; the flat board calls it without that argument and behaves exactly as today. All branches are a single optimistic mutation with snapshot rollback.
SIGNATUREdropOnBoard(itemId, stateId, beforeId, afterId, targetEpicId?: string | null)
targetEpicIdThe destination lane's epic — a module id, null for the No-epic lane, or undefined when the flat board calls it. undefined ⇒ never reparent (flat board is byte-for-byte preserved).
A · STORY, lane ≠Item is top-level (not a sub-task) and targetEpicId !== owningEpic(item): optimistic { parent_id: targetEpicId, state, rank }; server = patchWorkItem({ parent_id, state_id }) then reorderWorkItem(before, after). Neighbors are correct because the card lands in lane B's bucket — the one the user dropped into.
C · SAME lanetargetEpicId === owningEpic(item) (or undefined): unchanged from today — optimistic state (if changed) + rank; patchWorkItem({ state_id }) if the column changed, then reorderWorkItem.
B · SUB-TASK, lane ≠Item is a sub-task and targetEpicId !== owningEpic(item) (Q1): state-only. Optimistic { state }; server = patchWorkItem({ state_id }). No parent patch, no reorder — the dropped neighbors belong to the wrong lane, so rank is left untouched and the card re-renders in its own lane's new-state column.
NO-OPIf neither state, parent, nor position changes (or rankBetween throws on inverted neighbors), the drop is dropped — same guard as today.
ROLLBACKAny thrown server call restores the pre-drop items snapshot and surfaces error — one path for all three branches.

Sub-task detection reuses the existing rule: a parent that is another work item (in itemById), not a module and not null/dangling. Component contract: BoardColumn / BoardCard gain a laneEpicId prop and a showHeader prop (false in swimlanes — headers live once in the sticky strip); they always pass laneEpicId through to dropOnBoard and are otherwise unchanged.
