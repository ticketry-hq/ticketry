Headless Agent Launch Primitive

A narrow orchestrator-owned subprocess primitive for codex exec and claude -p: build a non-interactive command, start it in the provided cwd, persist a fresh run record, supervise exit and timeout, capture stdout plus usage, and expose enough facts for the later coordinator driver.

Scope Boundary

This slice replaces the tmux-backed spawn_run substrate for orchestrator launches. It does not become the coordinator, worktree manager, or policy engine.
Owns

Agent command construction, non-interactive flags, MCP config injection, subprocess start, launch failure cleanup, run-record persistence, stdout capture, exit status, timeout kill ladder, and restart adoption hooks.

Does Not Own

Worktree creation, branch naming, integration merge-back, reducer folding, retry decisions, model policy selection, postcondition checks, HTTP/MCP run trigger surfaces, or any import from apps.execution / apps.terminals.

Resolved Ambiguity

The contract keeps cwd as an input. CODIN-788 owns worktree provisioning and passes the prepared directory to this primitive.

Validation Constraint

Do not launch a live claude -p process while validating this slice. Claude CLI inspection/smoke checks are allowed only when they do not use -p; Claude launch behavior must be covered with fakes. Codex launch tests are allowed when needed.

Launch Sequence

The primitive raises before persistence on bad input or command build failure; after a process starts, termination is recorded as facts on the run row.
StepDriver-visible factGuard
1. Validate agent, model, task_id, prompt, cwd, timeout policy.No row if validation fails.Unknown agent/model or missing cwd raises launch failure.
2. Build CLI argv with non-interactive and JSON-output flags.Command family stored for audit.Permission prompts must be impossible by construction.
3. Inject WorkTracker MCP config for the existing HTTP MCP tools.Agent can move states and write feedback through the unchanged server path.No direct DB writes by the launched process.
4. Create HeadlessRun and start subprocess in provided cwd.Record has pid/handle, started timestamp, agent, model, task id, cwd.Launch failure cleans up the half-created row and raises.
5. Supervisor drains stdout and waits for exit or timeout.Full stdout transcript and parsed token/cost usage are stored on the same record.Timeout sends SIGTERM, grace, then SIGKILL.
6. Finish record and notify the future driver hook.Exit status, timeout flag, finished timestamp, parser errors, and usage facts are durable.Postcondition checks and retry decisions stay outside this slice.

Run Record

Fresh model in apps.orchestrator. This is not AgentRun, because there is no tmux session, attach path, or terminal viewer.
Identity

id, task id, optional parent orchestration run id when later wired, phase label, attempt number, agent, model, cwd.

Process Facts

pid or OS handle, status, exit code, timeout flag, started and finished timestamps, signal used for forced termination.

Observation

Full stdout transcript, parsed JSON usage payload, token counts, cost if reported, parser error if the CLI output cannot be normalized.
